# 2026/08/14 数式は翻訳前に保護区間へ差し替え、モデルに触らせない

# Status
- superseded
- 既定値は [保護区間は既定で切る ADR](./20260815-protection-was-compensating-for-encoding.md) が置き換える（本 ADR の前提だった「モデルが書き写せない」は、実際には Ollama の `format:"json"` による符号化の破壊だった）。

# Situation
- ローカル LLM 単独（cloud を使わない）で論文 1 本を訳し切る運用を始めた。実行環境は MacBook Air M4 / 24GB、`gemma4:12b-it-qat` で **11.8 tok/s**。翻訳 1 呼び出しが 100〜400 秒かかり、**改稿 1 往復のコストが cloud とは桁違いに高い**。
- この条件で arXiv 2203.06060（36 セグメント）を訳し、形式検査の通過は 33/36 だった。

# Context
- **落ちた 3 本のうち 2 本が `math`**（残り 1 本は改稿上限到達）。構造保持（`\citep` / `\includegraphics` / 見出し）はほぼ完全で、Opus 版とのコマンド出現数の差分は 36 本中 30 本でゼロだったのに、数式だけが繰り返し壊れた。
- 現在の構造は「訳させる → `formalCheck` が数式の不一致を検出 → 差し戻して再訳」。差し戻しの情報量を増やす改善（欠けた式・増えた式を名指しする）で失敗は 8 → 4 → 3 本まで減ったが、**消し切れていない**。改稿は上限 4 回まで回っており、回数ではなく「モデルが数式を書き写せない」ことが原因。
- 数式は**訳す対象ではない**。原文のまま持ち越すのが正しいと分かっているものを、モデルに書き写させて事後照合している状態だった。書き写しの機会そのものを与えなければ、この失敗は原理的に起こらない。
- 区間走査（`src/tools/tex-spans.ts`）は既に TeX のエスケープ規則・verbatim・未閉じ区切りへの対応を持っており、保護に必要な部品は揃っている。

# Material for decision
- [品質ゲート ADR](./20260708-quality-gate-machine-vs-llm-and-explicit-failure.md): 「機械で確定できる欠陥に LLM コストを払わない」。数式の一致は機械で確定できる。
- [プロンプト注入対策 ADR](./20260811-untrusted-text-never-becomes-instructions.md): 印は system で意味を教え、per-segment の情報は user 側に置く。
- [プロンプトキャッシュ再利用 ADR](./20260722-prompt-cache-reuse-stable-system-prompt.md): 印の規約は固定文なので system の前置きを崩さない。
- 実測（本 repo の run）: 36 セグメント中 `math` 起因の失敗 2 本、再訳 1 回あたり 320〜408 秒。
- 実測（印の形式）: `gemma4:12b-it-qat` に 3 文 × 3 個の印を訳させ、`〔n〕` / `[[n]]` / `@@n@@` / `⟦n⟧` の 4 形式を比べた。**保持率はいずれも 9/9 で差が出なかった**ため、選択は保持率ではなく原文との衝突しにくさで決めた。訳文は「すべての実験において〔1〕を設定し、〔2〕を〔3〕とともに報告します」で、**助詞も自然に付いた**。なお `@@n@@` は訳文で前後に空白が入り（「@@1@@ を設定し」）、復元後に数式の前後へ余分な空白が残る。全角括弧はそれが起きなかった。
- 既存実装 `normalizeMath`: 照合時に数式内の `\text{...}` の中身を潰している＝**現在のゲートは数式内の地の文を検査していない**。

# Decision
- **数式区間を翻訳前に `〔n〕` へ差し替え、訳文で復元する**（正本は `src/segment/protect.ts`）。対象は `$..$` / `\[..\]` / `equation`・`align` 等の数式環境で、判定は `tex-spans.ts` の `mathSpans` に委ねる。
- **数式環境の一覧は `tex-spans.ts` を単一の正本にする**。保護と検査が別の一覧を持つと「保護したのに検査されない」「検査されるのに保護されない」区間が生まれる。
- **節ループは印のまま回す**。差し戻す前回訳（`priorJa`）も印のまま渡し、`formalCheck` と成果物の直前でだけ復元する。復元後の照合は原文と突き合わせるので、印を保った訳なら数式は 1 文字も違わない。
- **印が落ちたら番号で名指しして差し戻す**（`〔2〕が消えています`）。`formalCheck` の「数式個数不一致」より具体的で、モデルが直せる形にする。
- **印の形は `〔n〕`**。4 形式とも保持率は同じだったので、**原文との衝突しにくさ**で決める。`[` は LaTeX のオプション引数で頻出し、`@` は `\makeatletter` 系で現れる。`〔` は英語論文の原文にまず現れず、日本語の文中で前後に空白を要求しない。**原文が印そのものを含む場合は保護しない**（復元で原文を上書きしないための fail-safe）。
- **verbatim・lstlisting は保護対象に含めない**。対象論文に 0 件で壊れた実績が無く、中身が一様でない（コード本体は訳すと壊れるが、コメント行は訳す価値がある）。言語ごとのコメント記法の解析が要るわりに、現状は誰も困っていない。`algorithm` / `algorithmic` は verbatim ではないので、擬似コードは従来どおり翻訳対象のまま。
- **数式内の `\text{...}` も当面は数式ごと保護する**。現在の照合規則が既にその中身を無視しているため、保護しても意味論は変わらない。必要になったら「数式は保護、内側の `\text{...}` だけ翻訳スロットとして露出」へ拡張する。

# Consequences
- 良い面
  - 数式の破壊が**構造上起こらなくなる**。事後検出と再訳の往復（1 回 320〜408 秒）が不要になる。
  - 入力トークンが減る。数式の多いセグメントほど効き、生成も短くなる。
  - 失敗したときの指摘が「どの印か」まで具体化され、小さいモデルでも直せる形になる。
  - 保護区間の走査に既存の実装を使うので、エスケープ・verbatim・未閉じ区切りの扱いは検証済みのものを継承する。
- トレードオフ
  - **モデルは数式の中身を見なくなる**。`we set $\alpha=0.05$` が `〔1〕を設定した` になるため、数式の内容に依存した訳し分け（単数複数・単位の言い回し）はできない。実測では助詞は自然に付いたが、これは 1 モデル 3 文での確認にすぎない。
  - 印を落とすモデルでは、従来は「数式が壊れた訳文」が出ていたところが「印の欠けた訳文」になる。**検出はより確実になるが、失敗の総数が減るとは限らない**（効果は実測で確認する）。
  - 原文が `〔` を含む論文（日本語混じりの原稿など）では保護が無効化され、従来の経路に戻る。黙って壊すよりは良いが、その論文では数式の失敗が残る。
