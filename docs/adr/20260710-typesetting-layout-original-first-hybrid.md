# 2026/07/10 組版レイアウト方針: 原プリアンブル温存を既定・共通テンプレへ明示的フォールバック（ハイブリッド）

# Status
- accepted

# Situation
- JPaper は source-first（arXiv LaTeX ソース有り）で和訳し、`assemble-latex` で訳文を組版して日本語 PDF を出す。取り込み・図は [翻訳パイプライン ADR](./20260708-translation-pipeline-ingestion-and-figures.md)、組版ゲートは [2層化 ADR](./20260709-quality-gate-two-layer-and-build-error-triage.md) で確定済み。
- 「できる限り原論文と同様のレイアウトにしたい」という要求が出た。現行の既定（`資料/` を継いだ `luatexja-preset` の共通 `main.tex`＋`chapters/`）は**共通テンプレへ組み直す**方式で、原論文の段組み・クラス体裁・フロート配置を再現しない。実装前に**レイアウト方針**を確定する必要が生じた。

# Context
- 設計メモに緊張関係がある: §3「クリーンな第二 LaTeX は**元 LaTeX そのもの**」（原構造を保てる）と §9「`assemble-latex`＝訳文＋manifest を **`main.tex`/chapters** に組み直す」＋取り込み ADR「共通プリアンブルは**共有テンプレート化**し論文ごとの再実装をなくす」（原プリアンブルを置換）。レイアウト忠実度をどちらに寄せるかが未定だった。
- source-first だからこそ原 `\documentclass`＋プリアンブルが手元にあり、**原レイアウト再現が原理的に可能**（PDF-only は原ソースが無く忠実化不可＝Phase2）。
- ただし和訳は文字量が変わるため**ページ単位の完全一致は不可能**。現実的目標は「同じ document class・段組み・フロート配置・体裁」までの best-effort 忠実化。
- 原プリアンブル温存には risk（原クラスと日本語フォントの衝突、独自マクロ/パッケージ、overfull、クラス依存のビルド不能）があり、共通テンプレは頑健だが原レイアウトを失う。共通化の動機（`\cit` 等の再実装排除）は、共有部分を**原プリアンブルへ注入**すれば温存できる。

# Material for decision
- 設計メモ [`translation-pipeline.md`](../design/translation-pipeline.md) §1（`資料/` は luatexja 共通 main.tex）・§3（元 LaTeX そのもの）・§9（assemble-latex）
- [翻訳パイプライン ADR](./20260708-translation-pipeline-ingestion-and-figures.md)（共通プリアンブルの共有テンプレート化・図はベクタ優先）
- [2層化 ADR](./20260709-quality-gate-two-layer-and-build-error-triage.md)（全文組版ゲート・ビルドエラー分類・構造/テンプレ起因は明示的失敗）
- [品質ゲート ADR](./20260708-quality-gate-machine-vs-llm-and-explicit-failure.md)（暗黙フォールバック禁止・失敗/劣化は surface）
- 会社A の要求（原レイアウトにできる限り寄せたい。性能が担保されないなら共通テンプレで可）

# Decision

## 決定 1: ハイブリッド（原プリアンブル温存を既定、共通テンプレへ明示的フォールバック）
- `assemble-latex` の**既定は原プリアンブル温存**: 原 `\documentclass`＋プリアンブルをそのまま使い、**日本語フォント対応（luatexja/CJK）と共有引用マクロだけを注入**して本文テキストを差し替える。段組み・クラス体裁・定理環境・フロート配置・番号を原論文に寄せる。
- **共通テンプレは保証されたベースライン**: 原プリアンブルでは日本語で組めない論文（クラス/フォント衝突・独自マクロのビルド不能）は、`資料/` 由来の共通 `luatexja` テンプレへ**フォールバック**する。
- 共通化の動機（論文ごとの `\cit` 等の再実装排除）は、共有部品を原プリアンブルへ**注入**する形で温存する（取り込み ADR の狙いと両立）。

## 決定 2: フォールバックは暗黙にしない（surface する）
- 原→共通テンプレの切替は**暗黙フォールバック禁止**（[品質ゲート ADR](./20260708-quality-gate-machine-vs-llm-and-explicit-failure.md)）に反しないよう、**明示的に記録・可視化**する: `RunSummary.layout`（`original`|`template`）に採用モードを残し、テンプレ簡略化時は訳注/サマリに「原レイアウトを再現できずテンプレに簡略化」を surface する。ユーザーが理由を追える。
- レイアウト忠実は best-effort であり、文字量差によるページ再流は許容（ページ一致は目標にしない）。

## 決定 3: 忠実度と工数の実測で既定を見直せる余地を残す（(B) PoC で評価）
- 原プリアンブル温存はビルドエラー分類（[2層化 ADR](./20260709-quality-gate-two-layer-and-build-error-triage.md) 決定4）の負荷を上げる。**広範に不安定なら、プロジェクト既定を共通テンプレへ寄せる判断を (B) の実測で行う**（会社A の「性能が担保されないなら共通テンプレで」を反映）。この見直しは新 ADR で記録する。
- 本方針は **source-first 限定**。PDF-only（Phase2）は原ソースが無く原レイアウト再現の対象外。

# Consequences
- 良い面
  - 既定で原論文の段組み・体裁に寄せられ、「原レイアウトにできる限り」という要求を満たす。
  - 組めない論文も共通テンプレで必ず PDF 化でき、可用性を落とさない。フォールバックは可視化され暗黙劣化にならない。
  - 引用・日本語フォントの共有は注入で温存し、共通化の利点を捨てない。
- トレードオフ
  - 原プリアンブル温存はビルド不能・overfull・クラス依存の調整を増やし、`assemble-latex` と全文ゲートのエラー分類＝**(B) T&M の工数を押し上げる**。
  - 2 経路（原/テンプレ）を持つ実装・テスト分岐が増える。`RunSummary.layout` の決定的テストが要る。
  - 忠実化の上限は文字量差により「同一体裁・best-effort」まで（ページ一致は不可）。
- 本 ADR は [翻訳パイプライン ADR](./20260708-translation-pipeline-ingestion-and-figures.md) の「共通プリアンブルの共有テンプレート化」を**改変せず具体化・上書き方針として拡張**する（原プリアンブル温存を既定に格上げし、共通テンプレはフォールバック/ベースラインに位置づけ直す）。値・(B) スコープの正本は [契約付録](../design/contract-appendix.md) §7。
