# 2026/08/16 保護区間の要否はモデルの能力で決まる（26B では既定へ戻す）

# Status
- accepted
- [保護区間は既定で切る ADR](./20260815-protection-was-compensating-for-encoding.md) の既定値を、その ADR 自身が定めた手順に従って戻す。

# Situation
- ベンチマーク対象を `gemma4:12b-it-qat`（dense・11.8 tok/s）から `gemma4:26b-a4b-it-qat`（MoE 活性 4B・28.1 tok/s）へ切り替えた（[OpenRouter ADR](./20260815-openrouter-provider-for-fast-iteration.md)）。
- 26B での通し実行（run4・arXiv 2203.06060・36 節）で 4 節が失敗した（seg-0018 / 0019 / 0021 / 0023）。いずれも改稿予算を使い切っている。

# Context
- 前 ADR は切り替えの判断基準を**先に**書いていた。

  > 保護が有効だった条件（符号化が壊れている・**モデルが書き写せない**）に戻ると、この既定は不利になる。**その判断材料は「1 節あたりの改稿回数」と「落ちた節の数」**で、切り替えは `PROTECT_SPANS` の 1 行。

- 落ちた 4 節の指摘を並べると、**根は同じ 1 種類**だった。

  ```
  訳文に無い数式: \mathrm{mHDeg}_{\mathrm{noise}}
  原文に無い数式: \mathrm{mHD95}_{\mathrm{noise}}
  ```

  この論文は似た綴りの指標略語が密集している（`mDDeg` `vDDeg` `mHDeg` `mHD95` `sHD95` `wmHD95` `wsHD95`）。モデルは `mHDeg` を `mHD95` へ寄せる。**指摘で名指ししても直らない**——自分の綴りを正しいと信じているため、改稿は同じ誤りを再生産する。書き写しの失敗そのもの。
- 保護あり・なしを同じモデル・同じ節で測った（`google/gemma-4-26b-a4b-it` / OpenRouter・各 1 稿）。

  | 節 | 保護あり | 保護なし |
  | --- | --- | --- |
  | seg-0021（印 35 個） | **指摘 0 件** | `math` + `symbol-command` の 2 件 |
  | seg-0023（印 33 個） | **指摘 0 件** | run4 で改稿 4 回を使い切って失敗 |

- **前 ADR が保護を切った理由は、26B では成立しない。** 当時の観測は「印 33〜35 個をモデルが捌けず位置を取り違える」だったが、26B は同じ印の数を 1 稿目で完璧に扱う。前提は**印の数ではなくモデルの能力**だった。
- ここで前 ADR の判断が誤りだったわけではない。12B に対しては保護を切るのが正しく（実測: 保護ありで改稿 4 回失敗 → 保護なしで 1 稿目通過）、26B に対しては入れるのが正しい。**同じ設定が両方のモデルで正しいということはない。**

# Material for decision
- [保護区間は既定で切る ADR](./20260815-protection-was-compensating-for-encoding.md): 切り替え条件と判断材料を定めた ADR。本 ADR はその手順の実行にあたる。
- [数式保護 ADR](./20260814-protect-math-spans-before-translation.md): 「書き写しの機会そのものを与えなければ、この失敗は原理的に起こらない」。印の形と保持率の実測。
- [エスケープ特殊文字保護 ADR](./20260815-protect-escaped-specials-too.md): `\%` の backslash 落ちは**ビルド成功のまま本文が PDF から消える**。
- [OpenRouter ADR](./20260815-openrouter-provider-for-fast-iteration.md): 上表の A/B を数分で回せたのはこの口があるため。ローカルだけなら 1 セル 5〜10 分で 4 セルを測るのに 1 時間近くかかる。
- 実測（本 repo・12B）: 保護ありで seg-0021 が改稿 4 回失敗、保護なしで 1 稿目通過。26B とは真逆。

# Decision
- **`PROTECT_SPANS` を `true` に戻す**（`src/workflows/section-loop.ts`）。数式とエスケープ済み特殊文字を印へ差し替えて translator へ渡す。
- **これはモデル依存の既定である**ことを明記する。判断材料は前 ADR と同じ「落ちた節の数」と「1 節あたりの改稿回数」で、切り替えは 1 行。小さいモデルへ戻すなら `false` へ戻す。
- **形式検査はすべて残す**。保護は「落とさせない」ためのもので、モデルが新たに生の `%` や `$` を持ち込む経路は塞げない。
- 前 ADR の本文は変えず `Status` だけ更新する。**12B に対する当時の決定は正しく、前提が変わっただけ**なので、経緯そのものが資産になる。

# Consequences
- 良い面
  - 書き写しの失敗が**原理的に起こらなくなる**。似た綴りの略語が密集する論文で、モデルが `mHDeg` を `mHD95` へ寄せる経路が消える。
  - 落ちた 4 節のうち 3 節（seg-0019 / 0021 / 0023）がこの経路の失敗で、実測で 2 節が 1 稿目通過に変わっている。
  - 改稿の往復が減る。ローカルでは 1 回 3〜5 分なので、通し実行の時間が直接縮む。
- トレードオフ
  - **translator が数式の中身を見られなくなる**。単位や単数複数の言い回しを数式に合わせて訳せない（数式保護 ADR と同じトレードオフ）。
  - **印の復元・欠落判定という失敗経路が本番へ戻る**。印を落とせば `describeMarkIssues` が名指しするが、経路が 1 つ増える。
  - **モデルを小さくすると不利になる**。この既定は 26B 級を前提にしており、12B では逆効果であることが実測で分かっている。モデルを変えるときは必ず測り直す。
  - 前 ADR と本 ADR で既定が往復した。以後、保護の要否は「決めるもの」ではなく**モデルごとに測るもの**として扱う。
