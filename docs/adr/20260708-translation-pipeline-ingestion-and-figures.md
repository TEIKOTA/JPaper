# 2026/07/08 翻訳パイプライン: ソース優先取り込み・図はベクタ優先・決定的処理のツール化

# Status
- accepted

# Situation
- JPaper は学術論文の和訳エージェントを構築する。基盤方針は [エージェント基盤 ADR](./20260708-adopt-deterministic-agent-architecture.md)（素の TS ワークフロー＋薄い自作ランタイム）で確定済み。
- 実装前に、既に "うまくいっている" 現行の和訳リポジトリ（`資料/`。Claude Code＋手順書で 20 本以上を和訳）を調査し、サブエージェントに U-Net の短い和訳＋図クロップを委譲して作業トレースを取得した（2026-07-08）。そこで具体的な非効率が判明した。

# Context
- 現行 `資料/` は arXiv の LaTeX ソースがあればそれを翻訳入力にし、無ければ PDF を LLM が直読する。図は PDF をラスタ化して手動座標でクロップし埋め込む。用語は論文ごとに `translation_glossary.md` をゼロから作る。
- U-Net デモで判明した無駄:
  1. `\cit{}` マクロを論文ごとに自作し、`.bbl` から引用番号を**人手で数えて**対応表を手書きした（機械的に定まる処理を LLM にやらせている）。
  2. ソースに図が**独立したベクタファイル**（`u-net-illustration-correct-scale2.pdf`）で同梱されているのに、PDF をラスタ化して手動クロップした（画質・工数の二重の無駄）。
  3. 共通用語（畳み込み・特徴マップ 等）を毎回入力し直した（横断辞書がない）。
  4. 節単位分割により範囲外図への `\autoref` が未解決になった（相互参照の構造的問題）。

# Material for decision
- 現行 `資料/` の手順書（`資料/AGENTS.md`, `資料/docs/agent/{new-translation-workflow,translation-workflow,image-crop-workflow}.md`）
- サブエージェントによる U-Net (1505.04597) デモの作業トレース（2026-07-08）。成果物 `資料/ja_translations/demo-unet/`（Abstract+Introduction＋Figure 1、LuaLaTeX ビルド成功）
- 基盤 ADR [エージェント基盤 ADR](./20260708-adopt-deterministic-agent-architecture.md)（配線=コード/判断=LLM）

# Decision
- **取り込み（ingestion）はソース優先**: 翻訳入力は arXiv の LaTeX ソースを最優先。ソースが無い論文のみ PDF を LLM が直読する（fallback）。数式・ラベル・引用・番号を保持でき、翻訳が壊れにくい。
- **図はベクタ優先・クロップは fallback**: ソースがある論文は**元の図ファイル（多くはベクタ: PDF/EPS/PGF）をそのまま再利用**して埋め込む。ラスタ render+crop は **PDF-only 論文のときだけの fallback** に格下げする。
- **決定的処理はツール化**: `.bbl`→引用番号の対応付けなど機械的に定まる処理は LLM に数えさせず、TS/スクリプトのツールで生成する。引用マクロ・共通プリアンブルは共有テンプレート化し、論文ごとの再実装をなくす（原則: 事実の確定はコード。基盤 ADR の「配線=コード」の延長）。
- **横断 用語 DB を最優先機能に確定**: confirmed/proposed を持つ横断 terminology DB（SQLite / `node:sqlite`、翻訳で出た新出語は `proposed` を自動追記）を translator に注入して一貫性を担保し、共通語の再入力をなくす。実装の第一歩とする。
- **相互参照は全文を 1 解決単位で扱う**: 節単位に分割しても `\autoref`/`\ref`/引用が解決するよう、参照解決は文書全体で担保する（分割は出力の都合であって解決単位ではない）。

# Consequences
- 良い面
  - 図: ベクタ再利用で画質向上＋手動クロップ工数の削減。
  - 引用: 番号を決定的に生成し、人手計数の誤りを排除。テンプレ共有で再実装ゼロ。
  - 用語: 横断 DB で一貫性＋再入力ゼロ。回すほど改善（proposed 蓄積）。
- トレードオフ
  - ソース図の形式は多様（PDF/EPS/PGF/外部生成）で、埋め込み時に latexmk 側の対応や軽微な調整が要る場合がある。
  - PDF-only 論文は依然ラスタクロップの当たり外れが残る（fallback として許容）。
  - `.bbl` パーサは bib スタイル差（番号順/著者年）への対応が要る。
- 本 ADR は現行 `資料/` の静的調査＋1 回のデモに基づく。実装時に各点を再検証する。図のベクタ再利用は「arXiv ソースがある」前提。
