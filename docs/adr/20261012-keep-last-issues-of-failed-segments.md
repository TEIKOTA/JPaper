# 2026/10/12 落ちた節の最後の指摘を出力先の .run に既定で残す

# Status
- accepted

# Situation
- arXiv 2209.04836（Sonnet・effort low）で 5 節が品質基準で落ち、その 5 節だけで 41 呼び出し・$1.18 を使った（#333）。
- 落ちた節は checkpoint に永続せず、evaluator の指摘は次の再訳の入力にしか使われない。run が終わると、なぜ落ちたかを確かめる手段が無く、原因は再構成した入力からの推定になった。

# Context
- 指摘の文面は論文由来の文字列（原文・訳文の引用）を含む。LLM トレースはメタデータのみ（[LLM トレース ADR](./20260722-llm-call-trace-local-jsonl.md)）、進捗も固定語彙のみ（契約付録 §8）という線を守る必要がある。
- 出力先には既に `notes.json`（evaluator の warn の文面）や訳文そのものが置かれている。出力先の中に論文由来の文字列を置くこと自体は新しくない。
- 契約に合わない生応答は `JPAPER_DUMP_RAW` を指定したときだけ保存する（opt-in）。全応答を保存する案はこれと同じく opt-in の領分。

# Material for decision
- issue #333 の実測（上記）と、再現した入力での用語行・訳注の矛盾。
- [改稿予算 ADR](./20260815-split-revision-budget-by-checker.md): 落ちた節の扱い。
- 契約付録 §8「落ちた節の指摘」「進捗には節ごとの合否を載せる」。

# Decision
- 落ちた節（タイトル節を含む）ごとに、最後の稿の指摘（evaluator の verdict と issues、または形式検査の指摘と差し替え記号の名指し）を `<outDir>/.run/failed-segments.json` へ**既定で**書く。`runId` と時刻を添える。
- 全節が通った run は前のファイルを消す。例外で中断した run は書きも消しもしない。
- 外向きの `RunError.message`・進捗・トレースには中身を載せず、置き場（固定文字列）だけを添える。
- evaluator の全応答や通った節の応答は保存しない（必要なら opt-in の診断として別に扱う）。

# Consequences
- 落ちた節の原因を、LLM を呼び直さずに事後に確かめられる。
- 出力先の `.run` に論文由来の文字列が 1 ファイル増える。出力先を共有・配布する利用者はこれを含めて扱う必要がある。
- 例外で中断した run の後には前の run の記録が残る。どの run のものかは `runId` で見分ける。
