# 2026/10/06 横長の対訳 PDF（A4 縦 2 枚分・左=原文／右=和訳）を標準の出力にする

# Status
- accepted（2026-10-07。仕様・出力形態・組版方式をユーザーが確定）

# Situation
- 個人利用。和訳 PDF を読んでいて気になる表現に出会ったとき、原文をすぐ確認できるようにしたい。現在の出力は和訳 PDF（原レイアウト温存またはテンプレ。[組版レイアウト ADR](./20260710-typesetting-layout-original-first-hybrid.md)）だけで、原文は別に開く必要がある。
- 和訳と英語は文字数が 1 対 1 に対応しないので、左右を単純に並べると対応する箇所がずれていく。

# Context
- 組版レイアウト ADR は「文字量が変わるのでページ単位の一致は目標にしない」と決めた。本件はそれを覆さない。目的は原レイアウトの再現ではなく、**対訳としての段落単位の対応づけ**であり、別の出力物として追加する。
- 横 420mm × 縦 297mm（A4 縦を 2 枚横に並べたサイズ）に、左半分に原文、右半分に和訳を置く。

# Material for decision
- 作業時のモック（仮データの HTML、リポジトリ未コミット）で見え方を確認した。段落ペアを 1 行にして左右の高いほうに揃え、短い側の下を空白にする形で、紙面に収まり読める。
- 既存の翻訳はセグメント単位で処理しており（`seg-NNNN`）、原文と訳文の対応は段落〜節の粒度で既に持っている。
- PoC (A)（2026-10-06、1810.11953 の本文 seg-0001〜0004、LaTeX の paracol）:
  - **段落の対応**: 全 41 セグメントで、原文と訳文の段落数（空行区切り）が一致した（41/41）。段落単位のペアは、この論文では機械的に取れる。他の論文・他のモデルでの一致率は未測定。
  - **組版**: neurips2019 クラスの原プリアンブルをそのまま使い、`\newgeometry` で 420mm × 297mm に上書きして A3 横で組めた。`\switchcolumn` + `\switchcolumn*` で段落ペアの上端が左右で揃い、短い側の下が空き、ページ末では文の途中で割れて左右とも続きが次ページへ流れた。脚注は各半分に別々に出る。数式番号は左右で一致した。
  - **ページ番号**: `eso-pic` で左右の半分に別々の番号（原文 p.N／和訳 p.N）を置けた。
  - **図・表**: paracol の中のフロートはページ全幅に左右 2 枚が縦に積まれて使えない。`figure` / `table`（`*` 付き含む）を `\@captype` を設定した非フロートの環境に差し替えると、左右の半分にそれぞれ置け、番号も一致した（paracol はカウンタを列ごとに持つ）。
  - 全 41 セグメントの通し（`latexmk -lualatex`、既存の翻訳ビルドと同じ経路）で 61 ページの A3 横 PDF が組めた。引用は bibtex を通して全て解決した（初回の PoC は `lualatex` を 1 回回しただけで `[?]` が残っていた。ビルド経路の問題で、方式の問題ではない）。表・サブ表・図は左右の半分にそれぞれ収まり、番号も一致した。
  - **段落の切り方**: 空行で割った段落は、`\begin` と `\end` の数が揃うまでつなぎ直す必要がある（表の中の空行で割ると、`tabular` の途中で左右が切り替わって組版エラーになる）。つなぎ直した後も、原文と訳文の段落数は全セグメントで一致した。
  - **マクロ定義の重複**: `\newcommand` が左右の両列で実行されて「定義済み」で落ちるので、和訳側は `\providecommand` に置き換える。`\label` は左右で二重定義になる（警告のみ。`\ref` の飛び先は和訳側に寄る）。
  - **キャプションの未訳**: 1810.11953 の出力（ローカルモデル＝`baseline` プロファイル）では、`figure` 環境内の literal なキャプションが原文のまま残った（「本文のみを訳す」指示のため）。claude / codex 向けの `adaptive` プロファイルには、キャプションを訳す指示が既にある（[ADR 20260913](./20260913-scope-log-derived-prompt-adaptations-to-frontier-models.md)）。PoC では、未訳のキャプションだけを別パスで訳して差し替えた（`captions_ja.json` にキャッシュ。LaTeX コマンドの個数が変わった訳は採用しない）。パイプライン本体で `baseline` にも広げるかは未決。
  - **タイトルページ**（2026-10-07 更新）: 上記のとおりタイトル・著者を左右に分け、タイトルは別パスで訳して置いた（PoC で確認済み。パイプライン本体でのタイトル翻訳は未実装）。以前の方式の記録: neurips の `\maketitle` は、脚注（`\thanks`・学会表記）の挿入物が次の paracol と衝突して空白ページが出た。PoC ではタイトルブロックだけを脚注抜きで全幅に置いた（折り目をまたぐ）。タイトルを左右に分けるか、脚注をどう出すかは未決。
  - 未検証: `wrapfigure`、訳注一覧（和訳のみのセクション）の扱い、段落数が一致しない論文、他の文書クラス。
- 関連: [組版レイアウト ADR](./20260710-typesetting-layout-original-first-hybrid.md)、[翻訳パイプライン ADR](./20260708-translation-pipeline-ingestion-and-figures.md)。

# Decision
確定した仕様（ユーザー回答）:
- **紙面**: 横 420mm × 縦 297mm。左半分に原文をそのまま、右半分に和訳。
- **揃え方**: 段落・見出し・数式・図＋キャプション・表・参考文献 1 件を「ペア」とし、1 ペア = 1 行とする。左右の高いほうに行の高さを揃え、短い側の下は空白にする。ペアの上端と下端は左右で一致させる。
- **ペアが 1 ページに収まらないとき**: 文の途中で割り、左右とも続きを次ページへ送る（ペアごと次ページへ送る案は採らない）。
- **図**: 左右とも同じ図を載せる。
- **空白が目立つ段落**: 許容する（文単位に刻んで揃える案は採らない）。
- **ページ番号**: 左右の半分に別々に付ける（原文 p.N／和訳 p.N）。
- **タイトルと著者**（2026-10-07 追加）: 左右の半分にそれぞれ置く。タイトルは訳し、著者は原文のまま両側に同じものを置く。各半分が単独で成り立つので、左半分だけ・右半分だけを切り出せば、原文だけ・訳だけの PDF も簡単に得られる。
- **キャプション**: 和訳側は日本語にする。翻訳指示への追加は [ADR 20261007](./20261007-translate-captions-in-all-prompt-profiles.md)（別ブランチ）で決めた。

出力と運用（2026-10-07 の認識合わせで確定）:
- **既定で出す**: 対訳 PDF は既定で作り、通常の和訳 PDF とあわせて出力する。`--no-bilingual` で作らない。
- **対訳の組版失敗は警告に留める**: 対訳 PDF の組版だけが失敗しても run は成功とし、和訳 PDF は出す。失敗は RunSummary とエラー出力に明示する（暗黙にしない）。
- **組版方式は (A) LaTeX の paracol**（PoC で成立を確認。下記）。
- **タイトルは訳し、通常の和訳 PDF にも反映する**: タイトル（前文の `\title{...}`）はコードで取り出し、既存の翻訳の経路（translator・形式検査・evaluator・改稿）に小さな 1 節として通して訳し、コードで差し戻す。用語集の訳語も効く。
- **原文だけ・訳だけの切り出しは今回作らない**: 左右の半分がそれぞれ単独で成り立つ構造（タイトル・著者・ページ番号が左右別）だけを保証する。

未決（実装前に PoC で決める。決まったら本 ADR の Status を更新せず、新 ADR に記録する）:
- 既存の組版ゲート（[2層化 ADR](./20260709-quality-gate-two-layer-and-build-error-triage.md)）との整合（対訳の組版エラーの分類）。
- 左半分（原文）を、原 LaTeX の組版結果から取るか、同じエンジンで組み直すか。

# Consequences
- 良い面:
  - 気になる表現を、別ファイルを開かずにその場で原文と突き合わせられる。
  - 段落単位で揃うので、左右の対応が長く読んでもずれない。
- トレードオフ:
  - 原文と和訳の文字量が違う段落では、短い側の下に空白が出る（許容と決めた）。
  - 文の途中で割るため、左右で割る位置を揃える処理（文の対応づけ）が要る。
  - 紙面が大きく、通常の A4 での印刷・閲覧には向かない。
  - 実装方式が未決で、数式・図・参考文献で崩れるリスクがある。PoC で評価する。
