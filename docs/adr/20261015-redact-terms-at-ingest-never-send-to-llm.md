# 2026/10/15 指定した文字列は取り込みの段で *** に置き換え、どの LLM 呼び出しにも渡さない

## Status
- accepted

## Situation
- JPaper は論文の本文を、翻訳・評価・用語集作り・用語の Web 検索・PDF の読み取りの各段で LLM（claude・codex・ollama・openrouter）に渡す。
- 著者ブロックを訳さずに原文のまま残す仕組み（[著者ブロック ADR](./20261008-keep-author-block-untranslated.md)）はあるが、伏せた部分も用語集作りや評価の入力には原文のまま載る。
- 利用者は、自分の名前や購入者の表示など、LLM に渡したくない文字列を事前に指定したい（2026-10-15 の相談。issue #388）。PDF 入力（[PDF 入力 ADR](./20261015-pdf-input-text-layer-as-source-llm-rebuilds-math.md)）ではテキスト層に加えてページ画像も LLM に渡す。

## Context
- 「渡さない」を保証するには、LLM を呼ぶ箇所ごとに伏せるのではなく、すべての呼び出しが見る入力そのものから消す必要がある。呼び出し箇所ごとの対策は、箇所が増えたときに漏れる。
- 伏せた語は、成果物（和訳 PDF・対訳 PDF の左右・用語集）・実行の記録・checkpoint にも残してはならない。checkpoint のファイル名（無効化キー）に語の素のハッシュを入れると、短い名前なら総当たりで戻せる。
- 指定した語を引数で渡すと、シェルの履歴とプロセス一覧に残る。

## Material for decision
- issue #388 の Scope（2026-10-15 に決定: ファイルで渡す・固定の `***`・画像は白で塗る・数だけを記録する・PyMuPDF と Python を使わない）。
- 取り込みの経路: `ingest`（`src/ingest/index.ts`）が展開したソースのディレクトリと `cleanLatex` を作り、下流はすべて `cleanLatex`（と組版で読む同梱ファイル）だけを見る。PDF 入力は `extractPdf` がテキスト層とページ画像を LLM に渡し、起こした `main.tex` を取り込みへ渡す。
- 却下した案:
  - 呼び出しごとに伏せる（翻訳・評価・用語集・検索の各プロンプトで置き換える）: 経路が増えたときに漏れ、成果物にも残る。
  - 消した語を元に戻して成果物に出す: 成果物とディスクに残る。利用者の要望は「渡さない・残さない」。
  - PDF の画像の墨消しに PyMuPDF を使う: AGPL と Python の依存が増える。poppler の `pdftotext -bbox-layout` で語の位置を取り、`pdftoppm` の画素を TypeScript で白く塗れば足りる。

## Decision
- 指定した文字列は、**取り込みの段で 1 か所だけ** `***` に置き換える。下流（翻訳・評価・用語集作り・用語の Web 検索・タイトルの翻訳・組版・対訳 PDF）は置き換えた後のものしか見ない。
  - LaTeX 入力: 展開したソースのテキストのファイル（`.tex`・`.bib`・`.bbl` など）をすべて書き換えてから `cleanLatex` を作る。利用者のディレクトリ（素の `.tex`・ディレクトリの入力）は書き換えず、run の作業領域へ複写してから置き換える。語が LaTeX のコマンド名の中にあれば、組版が壊れるので LLM を呼ぶ前に入力エラーで止める。
  - PDF 入力: LLM に渡すテキスト層を書き換え、ページ画像（読み取り用・原本の画像に落ちたページ・切り出した図）の、その語の位置（`pdftotext -bbox-layout` の語の矩形）を白で塗る。起こした `main.tex` も取り込みの段で同じく書き換える。
- 指定はファイル（`--redact-file <path>`、1 行 1 語）だけで受け、引数では受けない。語の比較は大文字と小文字を区別し、部分一致（語の中の一致も置き換える）。表記ゆれは利用者が別々に書く。
- 実行の記録（`RunSummary.redaction`）には語の数と置き換えた数だけを残し、語そのものは書かない。checkpoint の無効化キーには、語の一覧の**鍵付きの値**（checkpoint の署名鍵の HMAC）を入れる。誤りの文には語を載せない（行番号・ファイル名だけ）。

## Consequences
- 良い面: どの LLM 呼び出しにも、成果物・checkpoint にも、指定した語が渡らない・残らないことを、取り込みの 1 か所の検査で示せる。呼び出しの経路が増えても保証が崩れない。
- 受け入れたトレードオフ:
  - 部分一致なので、短い語は別の語の中も消す（`Ito` は `Itoh` の中も消す）。利用者は長めの語を書く。
  - テキスト層に無い文字（図の中の画像の文字・行末で分綴された語）は消せない。PDF 入力の画像の白塗りは語の矩形単位で、句読点が付いた語は語ごと白くなる。
  - 伏せ字を使った論文は、入力の署名が変わるので、用語集の編集（契約付録 §9）の組み直しの対象にならない（今どおり arXiv ID の入力だけが対象で、伏せ字を使わなかった run に限る）。
  - 入力のファイル名に語が含まれると、論文 ID と出力先の名前には残る（警告を出す）。
  - 消した語が文の主語などだと、訳文の意味が通りにくくなる。
