# 文脈の持ち越しは名前ではなく内容で判定する

## Status

accepted

## Situation

JPaper を web アプリの裏側のロジックとして出すための受け入れ判定で、外部の審査者が「同じ名前の別論文どうしで文脈が混ざる」ことを実測した。攻撃ではなく、**普通の運用で起きる**経路である。

## Context

[paperId 単射 ADR](./20260811-paper-id-must-be-injective.md) は、サニタイズによる多対一の潰れを直して paperId を単射にした。ただし同 ADR は「別ディレクトリの同名ファイルが同じ出力先を共有するのは従来どおり」を意図的な決定として残している（決定の範囲は**サニタイズの副作用**だった）。

問題は、[文脈の持ち越し防御](./20260709-carry-over-context-only-within-same-paper.md)（`.paper-id` の印が別論文なら既存 md を採用しない）が **paperId の一致だけを「同じ論文」の根拠にしている**ことである。`derivePaperId` はファイル名の stem から作るので、別内容の 2 論文がどちらも `main.tex` だと paperId が一致する。**`main.tex` は arXiv ソースで最も普通の名前**なので、これは稀なケースではない。

実測（受け入れ判定）: 論文 A（`thesis = ALPHA_SECRET_THESIS`）を実行した outDir で論文 B を実行すると、**B の translator プロンプトに A の thesis がそのまま載り、両 run とも `status=ok` / `exit=0`、警告ゼロ**。`brief` は全セグメントのプロンプトに載るので影響は全文に及ぶ。翻訳 checkpoint 自体は内容 sha256 で無効化されるため再利用はされず、汚染は `glossary.md` / `brief.md` / `style.md` の採用経路に限られる。

これは単射 ADR の Situation 節に書かれた実害そのものの再現である。単射化で塞いだつもりだった穴が、識別子の作り方（stem 由来）のせいで残っていた。

「web 層がテナントごとに outDir を分ける」（契約付録の必須注入）では塞がらない。**同じテナントが 2 本投稿するだけで起きる**。運用条件を「投稿ごとに outDir」に強めれば塞がるが、既定構成と CLI 利用が無防備なまま残る。

根本は、**識別子（どこへ出すか）と同一性（同じ論文か）を同じ値で兼ねている**ことである。前者は人間が読める安定した名前であってほしく、後者は内容で決まってほしい。両立させるには印に両方を持たせるしかない。

## Material for decision

- [同じ論文の中でだけ文脈を持ち越す ADR](./20260709-carry-over-context-only-within-same-paper.md)（`.paper-id` の印の由来）
- [paperId 単射 ADR](./20260811-paper-id-must-be-injective.md)（識別子側の決定。本 ADR はこれを置き換えない）
- 実測: `main.tex` 同士の 2 論文で、A の `thesis` が B のプロンプト 1/1 に載り、両方 exit 0・警告なし。
- 実測（本 ADR 適用後）: 同条件で汚染 0/1、専用の警告が出る。同一論文の再実行では既存 md を採用し続ける（人間の編集を捨てない）。

## Decision

`.paper-id` の印に **paperId と本文のダイジェストの両方**を持たせ、文脈の採用は両方の一致を条件にする。

- 印は 1 行目が paperId、2 行目が `cleanLatex` の sha256 先頭 16 桁。
- paperId が違えば従来どおり「別の論文」。**paperId が同じでもダイジェストが違えば「同じ名前で内容の違う論文」**として、既存 md を採用せず専用の警告を出す。
- **ダイジェストを持たない旧版の印は、従来どおり paperId だけで判定する**。既存の出力先を壊さず、人間が編集した md を黙って捨てないため。
- paperId の作り方（stem 由来・単射化）は変えない。出力先の名前は人間が読めるままにする。

## Consequences

- 同名の別論文による文脈汚染が既定構成で塞がる。web 層の運用条件（投稿ごとに outDir）に依存しない。
- **トレードオフ: 同じ論文を改訂して再投稿すると本文のダイジェストが変わり、人間が編集した `glossary.md` / `brief.md` / `style.md` が採用されなくなる。** 警告は出るが、編集を引き継ぎたい場合は利用者が md を新しい出力先へ持ち込む必要がある。汚染を通すよりは編集を作り直させるほうが安全と判断した。
- 印の書式が 1 行から 2 行に変わる。印を読むコードは 1 行目だけを見る。
- 内容が 1 バイトでも違えば別扱いなので、判定は保守的な側（採用しない）に倒れる。
