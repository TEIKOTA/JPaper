# worktree の標準配置・終了記録・安全な回収の採用

## Status

accepted

2026-10-02、ユーザーが `grill-me` の認識合わせサマリ（補完案を含む）に明示的に合意した。
本 ADR は方針の採択を記録する。管理コマンド・hook・手順の実装と既存分の棚卸しは [issue #105](https://github.com/TEIKOTA/project-template/issues/105) の後続作業であり、本 ADR の追加だけで適用済みとは扱わない。

## Situation

ユーザーはホーム直下に実装・独立レビュー・再レビュー用のディレクトリが散在している一覧を提示した。
テンプレートは各作業を専用 worktree に隔離する規律を採用しているが、配置と使用終了後の回収を結ぶ仕組みが不足している。
複数 repo で使える共通方式が必要であり、既存 repo への導入は段階的に進める。

## Context

`scripts/new-branch.sh` は home 配下の作成先を指定でき、一時領域や既存パスを拒否するが、配置先を一つの規約に統一していない。
`delegate-work` は read-only の調査・レビューにも専用 worktree を求める。
`scripts/hooks/session-start.sh` は worktree と未コミット差分を列挙するが、使用終了や回収可否は記録しない。

配置の統一だけでは使用済みのディレクトリが蓄積する。
一方、PR の merge/close、Git の clean 表示、子の自己申告だけでは、セッションの使用終了や成果物の保全を保証できない。
レビューが終わるたびに人の承認を待つ運用も、子専用 worktree の回収を滞らせる。
ユーザーは状態把握と安全な回収を目的にし、条件を満たす子専用 worktree の回収判断・実行を root に委ねることを選んだ。

## Decision

### 管理単位と配置

- テンプレートで各 repo 共通の方式を提供する。管理は repo 単位とし、全 repo 横断の管理ツールは作らない。
- 新規 worktree は `~/worktrees/<repo>/` 配下に置く。管理コマンドと対応するエージェント hook は標準外への新規作成を拒否する。例外はユーザーの理由付き明示承認を必要とする。
- 同名 repo の配置衝突や既存ディレクトリの上書きは検出して停止する。一時領域への配置は禁止のままとする。
- 既存 worktree の利用を止めない。人の手動 Git 操作を全面阻止する保証はしない。

### 使用状態と終了

- 管理コマンドに作成・一覧・保留・終了・回収候補確認・回収を集約する。状態記録は回収対象 worktree の外に保存する。
- 使用者（人または担当エージェント）が明示的に終了を記録する。記録のないものは要確認とし、PR の終了や経過時間だけでは使用終了扱いにしない。
- タスクの区切りでエージェントが回収候補と保護理由を提示する。
- レビュー用は結果・対象 SHA・必要な根拠を worktree の外に保存し、担当作業が終了していれば PR 未 merge でも回収可能とする。再レビュー時は新しい専用 worktree を作る。

### 回収の権限と安全条件

- 通常の worktree はユーザーが対象を承認した後に回収する。
- 子専用 worktree は、子の終了報告に加え root オーケストレーターが現物を再確認し、下記の安全条件を満たす場合に限り、root がユーザーへの個別確認なしで回収まで実行できる。子自身は回収しない。
- この例外を人の作業場所、他セッションの worktree、既存の所有不明 worktree に拡張しない。一般的な破壊的操作の許可や PR の merge 権限として扱わない。
- 終了記録だけでは回収しない。回収直前にも使用者・ジョブの終了、ファイル保護、commit の保持先、必要な成果物の退避を確認する。不明・競合を検出した場合は保護して停止する。
- 回収対象は worktree の作業ディレクトリと Git の登録だけとする。ローカル・リモート branch と退避済み成果物は残す。detached HEAD の必要な commit も保持先を確認し、単純な merge 済み判定で代用しない。
- 未コミット変更、未追跡・無視対象ファイルは原則保護する。事前に repo の規約で破棄可と指定した生成物だけ除去可能とし、未分類のファイルがあれば回収を止める。`.gitignore` は破棄許可ではない。secret の内容は読まない。
- テンプレートの破棄可能生成物の指定は空から始め、repo ごとに明示的に設定する。

### 導入と既存分

- 既存 repo にも段階的に導入できるようにする。一括導入は行わない。
- 既存 worktree は棚卸しと移行/回収候補・保護理由・影響の計画までを対象とする。移動・回収は対象一覧のユーザー承認後に別途実行する。
- 無条件の自動削除、branch 削除、remote 資源変更、既存分の一括移行は対象外とする。
- 実装と検証の scope・成功条件は issue #105 を入力にする。配置違反や安全条件違反で停止することをテストで確認し、ガード追加では退行注入 red→green を実証する。

## Consequences

- 良い面: ホーム直下の配置先を一つにまとめ、repo ごとに状態・回収候補・保護理由を確認できる。
- 良い面: 使用終了と削除可能を分けて扱い、条件を満たす子専用 worktree は root が回収して蓄積を抑えられる。
- 良い面: branch と退避済み根拠を残すため、レビュー後の作業場所を回収しても再確認の起点を保持できる。
- トレードオフ: 明示的な状態記録と終了報告、成果物の外部保存、回収直前の検査が必要になる。判定不明の対象は残り、手動確認を要する。
- トレードオフ: branch は回収対象外のため、ローカル branch の整理は別の課題として残る。
- 実装までの差: 現行 script・hook・AGENTS.md の配置と削除ガードはまだ旧運用である。状態記録の保存方式、活動確認・競合対策、具体的なコマンド名は後続で設計し、既存ガードとこの限定例外を整合させる。実装がない段階で新しい回収権限を先行行使しない。
- 本 ADR は配置・retention・authority に関わる決定である。合意の記録と実装の検証・PR 統合は分け、管理機能の完了と取り違えない。
