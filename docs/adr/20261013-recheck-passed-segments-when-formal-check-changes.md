# 2026/10/13 形式検査が変わったら、以前に通した節を LLM なしで検査し直す

# Status
- accepted

# Situation
- 節の checkpoint の無効化キーは原文・用語スライス・brief・style で、形式検査の版を含まない。通った節だけが残るが、「何を通過としたか」の定義が変わっても残り続ける（issue #254）。
- 実測: 引用・参照の検査（#248）を足したあと、前の run の checkpoint を持つ出力先で `\citep`→`\cite` の書き換えを含む節が再検査されずに成果物へ入った。

# Context
- 回避策の「毎回新しい出力先を使う」は、長い run を途中から再開する checkpoint の存在意義を捨てる。
- 形式検査の版を無効化キーに入れると、検査を変えるたびに全節を訳し直すことになる（論文 1 本あたり数ドル・ローカルなら数時間）。
- 形式検査は決定的で LLM が要らない。必要なのは「どの訳文を検査したか」で、復元済みの訳文からは保護区間（数式・伏せた著者やタイトル）を同じ形に戻せない。

# Material for decision
- issue #254 の案: ①手で上げる版の定数、②検査の種別の一覧から機械的に導く値。どちらも取りこぼしがある。
- 契約付録 §8（checkpoint の無効化）、§9（用語集の編集で LLM なしに組み直す）。

# Decision
- 通った節（タイトル節を含む）の checkpoint に、印のままの訳文（`marked`）と通した形式検査の版（`gate` = 手で上げる `FORMAL_CHECK_VERSION` と種別の一覧）を残す。版は無効化キーに入れない。
- checkpoint から読んだ節の `gate` が今と違えば、`marked` を節ループと同じ関数で今の形式検査にかけ直す。通れば `gate` を書き換えて使い、落ちればその節だけ訳し直す。`marked` から復元した訳文が checkpoint の訳文と一致しないときは再検査せずにそのまま使う。
- `marked` を持たない旧版の checkpoint はそのまま使う（保証の範囲はこの変更以降に通した節）。evaluator の判定はやり直さない。
- 用語集の編集は `marked` にも同じ置換をかけ、版が違い今の検査に通らない節があれば、組み直しの前に入力エラーで止める。

# Consequences
- 形式検査を厚くしても、以前に通した節が新しい検査を素通りしない。訳し直すのは今の検査に落ちる節だけで、通る節は LLM を呼ばない。
- `.run/steps` の節の checkpoint がおよそ 2 倍の大きさになる（`marked` は `ja` とほぼ同じ長さ）。用語集の編集のバックアップも同じだけ増える。
- 保護の規則（数式の保護・伏せる区間）を変えると印の番号がずれ、`marked` が `ja` に戻らなくなる。そのときは再検査されずに古い判定のまま使われる。
- 旧版の checkpoint と evaluator の判定は保証の外に残る。
