# 2026/10/15 PDF 入力は、本文の語句をテキスト層から取り、数式と構造だけを LLM にページ画像から起こさせる

# Status
- accepted

# Situation
- JPaper は LaTeX ソース（arXiv ID・アーカイブ・ディレクトリ・`.tex`）だけを入力に取る。`.pdf` を渡すと `未対応の入力形態です`（exit 2）で止まる。
- 契約付録の冒頭は「v1 = source-first に限定。PDF-only 抽出（Nougat/GPU/Docker/Python 依存）は Phase2」とし、設計メモ（`docs/design/translation-pipeline.md` §4・§5・§9）は、PDF だけの論文の数式を Nougat で起こし、本文を pdftotext、表を pdfplumber で取る計画を書いていた。§12 は、この計画の要否と依存の導入を「PoC に着手したときに決める」として保留していた。
- 利用者は、LaTeX ソースの無い論文（学会誌・出版社の版）に加えて、購入した書籍の章（数十〜数百ページ、数式が多い）も訳したい。手元の材料はテキスト層のある PDF（LaTeX から作られたもの）で、スキャン画像だけの PDF は当面の対象ではない。
- 実行は個人の Mac で、プロバイダは claude と codex の公式 CLI を主に使う（[既定モデル ADR](./20261013-default-to-latest-mid-tier-models-at-medium-effort.md)）。依存は TypeScript と poppler・LuaLaTeX の外部ツールに留めている。JPaper は MIT ライセンスで公開している。

# Context
- 2026-10-15 に、書籍の章（72 ページ）で「LLM にページ画像を読ませて LaTeX に起こす」方式を試した。数式・式番号はほぼ正確に起こせたが、**ページ先頭の、前のページから続く段落を丸ごと書き落とす**ことが確率的に起きた。語句の欠けは PDF の性質ではなく、テキスト層を使わずに画像から写させたことによる。
- テキスト層は本文の語句を正確に持つが、数式の構造（分数・添字・根号）は失われている。PDF と LaTeX の差は、本文の語句ではなく構造（レイアウト・数式）にある。
- 誤った訳を黙って通さないこと（[品質ゲート ADR](./20260708-quality-gate-machine-vs-llm-and-explicit-failure.md)）は、PDF の起こし直しにも当てはまる。一方、数百ページの書籍で 1 ページの失敗が run 全体を止めると、実用にならない。

# Material for decision
- 試験（`output/experiments/pdf-ingest-oss/`、手元のみ。claude-sonnet-5-5・effort medium・ツールなし・ページ画像 150dpi・ページ 1 枚ずつ）:
  - 画像だけ（72 ページ）: 本文の語の再現率 98.9%（pdftotext との多重集合の一致）、適合率 99.7%、式番号 113/113、ページ単体の組版 66/70（落ちた 4 ページはすべて `\tag` を数式環境の外に置いた）、合計 $2.51、1 ページ平均 7.9 秒。見本 4 ページを原本と目で比べ、数式の読み違いは見つからなかった。
  - 落としたページで同じ方式を繰り返すと、p.3 は 4 回中 3 回、p.10 は 4 回中 1 回、ページ先頭の段落（31〜37 語）を落とした。
  - 画像＋テキスト層（本文はテキスト層をそのまま使い、数式だけ画像から起こすよう指示）: p.3・p.10 とも 4 回すべて段落の欠けなし、組版も通った。1 ページ約 $0.034。
- Nougat は未検証で、Python・PyTorch に依存し、存在しない文を出す（幻覚）ことが知られている（設計メモ §4・§7）。
- 図の切り出しの先行例（手元の別プロジェクト）: PyMuPDF で画像と線をキャプションの上に寄せ集める方式。79 枚を切り出したが、Figure 1.1 が凡例だけになった（線のすき間の判定で図が分かれた）。PyMuPDF は AGPL。
- 2026-10-15 の利用者との認識合わせ（grill-me）の結論（issue #384）。

# Decision
1. **本文の語句はテキスト層を正本にする。LLM はページ画像とテキスト層を両方受け取り、数式・見出し・表・段落の区切りだけを LaTeX に起こす。** テキスト層は poppler の `pdftotext` で取る。Nougat は使わない（設計メモ §12 の PDF-only の保留は、この ADR で決着とする）。
   - 理由: 語句の欠けが起きるのは、画像から写させた場合だった。語句の正本を決定的に取れるものに置けば、LLM の確率的な書き落としを構造的に防げる。Nougat は依存が重く未検証で、LLM 方式は実測がある。
2. **起こした LaTeX は、テキスト層との語句の突き合わせとページ単体の組版で検査する。** 語句は順番を見ずに突き合わせ（読む順番は画像に従う。2 段組でテキスト層の行の順番が乱れるため）、**テキスト層の語が連続して 5 語以上欠けたら不合格**にする。ばらばらの 1〜2 語の不一致（引用キー・分綴・数式の中の語）は警告に留める。外れたら理由を伝えて読み直させる。それでも通らないページは、**原本のページ画像を貼って未訳とし、警告を出して実行の記録に残す。** 黙って通さず、1 ページのために run 全体も止めない。ただし**画像に落ちたページが読んだページの半数を超えたら、翻訳に進まずに失敗させる**（大半が未訳の成果物に翻訳の費用を払わない）。
   - 理由（連続した欠けで判定する）: 試験で起きた書き落としは 31〜37 語の連続だった。数え方の都合による不一致は散発的なので、厳密な一致で判定すると正しいページまで画像に落ちる。
3. **ページの境目で割れた段落・文・定理などの環境は、つないでから下流へ渡す。** LLM に「ページ先頭が前のページからの続きである」ことを示す印を付けさせ、組み立てるときに段落を切らずにつなぐ。印の有無はテキスト層（前のページの末尾が文末か、次のページの先頭が小文字か）と突き合わせる。前後どちらかのページが画像に落ちた場合はつながない。
   - 理由: 翻訳は段落単位なので、つながないと文の途中で切れた半文ずつを別々に訳すことになる。
4. **ページ画像を渡せるのは claude と codex にする。** ollama・openrouter で PDF が渡されたら、LLM を呼ぶ前に入力エラーで止める。
5. **ページ数の上限は設けず、100 ページを超えたら利用者に確かめる。** Web は送信前のダイアログ、CLI は端末なら y/N、端末でなければ明示の同意（`--yes`）が無いと待たずに入力エラー。範囲は利用者が PDF の何枚目か（1 始まり）で指定でき、100 ページは範囲で絞った後の読む枚数で数える。確認は LLM を呼ぶ前に行う。
   - 理由: 書籍を扱うので固定の上限は合わない。一方で誤って 1 冊を流すと費用と時間が大きい。Web は CLI を子プロセスで起動する（[Web アプリ ADR](./20261008-web-app-arxiv-search-and-translate-job-queue.md)）ので、CLI が端末でないときに入力を待つと止まる。
6. **毎ページ繰り返す上端・下端の行（柱・ノンブル・購入者の表示）は、LLM に渡す前に機械的に落とす。** LLM への指示に頼らない。
7. **起こした LaTeX を、今の取り込み以降（分割・用語・品質ゲート・組版・対訳 PDF）にそのまま渡す。** 対訳 PDF の左は起こした LaTeX を組んだものになる。表は LaTeX の表に起こし、参考文献の一覧は `thebibliography` として起こさせて訳さない（今の LaTeX 入力と同じ扱い）。画像に落ちたページは、対訳 PDF では左右の両方に置く。前文は決まった最小のものにする。
8. **図は、キャプションの上で、直前の本文ブロックの下端からキャプションの上端までを本文の幅で切り出す。** 位置は `pdftotext -bbox-layout` から取り、新しい依存（PyMuPDF・Python）は足さない。実装の前に、図の多い書籍で切り出しを目で確かめる。
9. **対象外**: テキスト層の無いスキャン PDF（入力エラーで止める）、原本レイアウトの再現、章の自動分割。

# Consequences
- 良い面
  - LaTeX ソースの無い論文と書籍を、今のパイプラインの資産（用語集・品質ゲート・対訳 PDF・用語集の Web アプリ）のまま訳せる。
  - 追加の依存は poppler の CLI だけで、Python・GPU が要らない。
  - 本文の語句の欠けは、検査で機械的に見つかる。
- トレードオフ
  - 見た目は原本を再現しない（柱・フォント・定理の書式）。対訳 PDF の左も原本ではなく起こし直した版になる。
  - 数式の正しさは機械では測れていない。LLM の読み違いは、語句の検査をすり抜けうる。
  - 読み取りに 1 ページあたり数セント・数秒かかる（翻訳の費用とは別）。
  - テキスト層には、画面に描かれない文字（白い文字など）が入りうる。画像に無い語は「足し」として検査で見えるようにするが、完全には防げない。
  - 論文由来のテキスト層を LLM の入力に載せるので、プロンプト注入の面が増える（[指示面へ載せない ADR](./20260811-untrusted-text-never-becomes-instructions.md) の扱いに合わせる）。起こした LaTeX は LLM の出力なので、今の安全検査を必ず通す。
  - PDF の読み取りは非同期で時間がかかるので、[ingest の有界時間 ADR](./20261013-keep-ingest-synchronous-with-bounded-time.md) の同期区間とは別の段として扱う。
- 後続: 実装は #385（CLI の取り込み）→ #386（図）・#387（Web のアップロードと確認）。LLM に渡したくない文字列を消す機能は、PDF と LaTeX に共通の別の決定として #388・#389 で扱う。
