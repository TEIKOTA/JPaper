# 2026/07/09 品質ゲートの2層化（節ループ＋全文組版ゲート）・再訳契約・組版エラー分類

# Status
- accepted

# Situation
- [品質ゲート ADR](./20260708-quality-gate-machine-vs-llm-and-explicit-failure.md) で「形式検査(TS)＝latexmk ビルド成功・全図・`\ref` 未解決なし・zod 適合」を機械判定に置いた。実装に渡す前に、外部ベンダー視点の仕様レビュー（会社B, Opus）を実施したところ、この形式検査が**単一レイヤに混在**しており、実装矛盾を生むと指摘された。
- 具体: `latexmk` ビルド・全図埋込・`\ref` 解決は**全文を組み上げて初めて判定できる**のに、翻訳ループの単位は**セグメント（節）**。1節だけでは判定できない項目を節ループ内に置くと実装が破綻する。

# Context
- セグメント内で即判定できる形式（zod 適合・数式保全・`keep-original` 一貫・段落欠落なし）と、assemble 後にしか判定できない全文形式（build/figure/`\ref`）は**別レイヤ**である。
- 2層に分けると、節ごとの翻訳＋evaluator は互いに独立した純変換になり、**並列実行（`Promise.all`）**できる。全文ゲートがその合流点（バリア）になる。ただし用語確定（glossary-builder が全文1回でロック）と初出判定は**並列翻訳の前に**済ませる必要がある。
- 再訳（evaluator が `revise` を返したとき）に translator へ何を渡すかが未定義だった。
- 全文ゲートのビルド失敗には2種類ある: 翻訳が壊した LaTeX 文法ミス（AI が最小情報で直せる）と、構造・テンプレ起因（図欠落・プリアンブルのバグ・切った節への参照＝再訳で直らない）。一律失敗にするとコスト/品質を損ね、一律 AI 修正にすると構造バグを AI が延々空回りする。

# Decision

## 決定 1: 品質ゲートを2層に分ける
- **節ループ内の軽い検査（セグメント単体で判定可）**: zod 適合・数式保全・`keep-original` の表記一貫・段落欠落なし＝形式[TS]、続けて evaluator[LLM] の品質判定。ここで差し戻し・再訳する。
- **全文組版ゲート（assemble 後・全文でしか判定不可）**: `latexmk` ビルド成功・全図埋込・`\ref`/`\autoref`/引用の解決。全節の翻訳完了後に1回、合流点で判定する。

## 決定 2: 節ごとの翻訳は並列化する
- glossary-builder による用語確定・ロックと初出判定を**先に**全文で済ませ、その後の節翻訳＋evaluator を `Promise.all` で並列実行する。確定済み辞書＋`firstOccurrence` フラグを注入するため、並列でも訳語はぶれない。全文ゲートがバリア。

## 決定 3: 再訳入力は translator の入力にオプション2枠を足す
- translator の入力を `{ segmentId, latex, glossarySlice, priorJa?, issues? }` とする。初回は `priorJa`/`issues` 無し、`revise` 時のみ前回訳と evaluator の指摘を渡す（＝赤ペンを戻す）。エージェントは1つのまま（別メソッドにしない）。

## 決定 4: 全文ゲートのビルド失敗はエラー分類して振り分け
- ビルドエラーを解析し**分類**する:
  - **翻訳起因（LaTeX 文法ミス）**: 失敗箇所のスニペット＋`latexmk` のエラー行**だけ**を translator に渡して修正（最小コンテキストでコスト/品質を両立）。
  - **構造・テンプレ起因**（図欠落・プリアンブルのバグ・実在しないラベルへの参照）: 再訳で直らないため**明示的に失敗**として人間に上げる。
- 無限ループ防止に `MAX_REVISIONS`（決定 5）を上限として適用する。

## 決定 5: MAX_REVISIONS はセグメントサイズ連動（3/4/5）
- 一定値でなく分量に応じる: 小（≤⅓ 予算）=3 / 中（≤⅔）=4 / 大（>⅔）=5。下限3・上限5。超過は failed。形式検査での差し戻しもカウント対象。

# Consequences
- 良い面
  - 全文でしか判定できない項目を全文ゲートに寄せることで実装矛盾が消える。節ループは純変換のまま保て、**並列化で高速化**できる。
  - 再訳が「前回訳＋指摘」で赤ペン方式になり、ゼロ再訳より速く正確。
  - ビルド失敗のエラー分類で、AI が直せる文法ミスは安く直し、構造バグは握りつぶさず人間へ（明示的失敗の原則を保つ）。
  - MAX_REVISIONS のサイズ連動で、長い節に手直し余裕を与えつつコストを抑える。
- トレードオフ
  - 全文ゲート→翻訳起因修正のフィードバック経路（エラー箇所→該当セグメント特定）の実装が要る。エラー分類のヒューリスティックに漏れ・誤分類の余地がある。
  - 並列翻訳は用語確定・初出判定を必ず前段で完了させる順序制約を課す。
- 本 ADR は [品質ゲート ADR](./20260708-quality-gate-machine-vs-llm-and-explicit-failure.md) を**改変せず具体化・拡張**する（形式検査を2レイヤに分割し、再訳契約とビルドエラー分類を追加）。値・スキーマの正本は [契約付録](../design/contract-appendix.md)。
