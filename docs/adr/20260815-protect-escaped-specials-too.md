# 2026/08/15 エスケープした特殊文字も保護区間に含める

# Status
- superseded
- 既定値は [保護区間は既定で切る ADR](./20260815-protection-was-compensating-for-encoding.md) が置き換える（本 ADR の前提だった「モデルが書き写せない」は、実際には Ollama の `format:"json"` による符号化の破壊だった）。

# Situation
- ローカル LLM 単独（`gemma4:12b-it-qat` / MacBook Air M4 24GB、11.8 tok/s）で arXiv 2203.06060 を訳し切る運用中。翻訳 1 呼び出しは 35〜226 秒。
- [数式保護 ADR](./20260814-protect-math-spans-before-translation.md) で数式を印へ差し替えたあと、記号だけの制御綴りの検査（`symbol-command`）と引用・参照の検査（`reference`）を足した。

# Context
- 保護と検査を入れた run3 で最初に落ちた 2 節は、どちらも**コホート記述の段落**だった。

  ```
  [翻訳 6/36] seg-0005 失敗 reference, symbol-command (改稿 3/6)
  [翻訳 8/36] seg-0007 失敗 math, symbol-command (改稿 3/6)
  ```

  seg-0007 の原文は 1 段落に `\%` が 4 個・`\citep` が 2 個・数値が 15 個入っており、**書き写しの密度が最も高い**。形式の改稿予算 3 回を使い切っても揃わなかった。
- `\%` `\&` `\#` `\$` `\_` `\{` `\}` は**訳す対象ではない**。原文のまま持ち越すのが正しいと分かっているものを、モデルに書き写させて事後照合している——数式について前 ADR が述べたのと同じ構図が、そのまま残っていた。
- 検査を緩める選択肢は無い。`\%` の backslash が落ちると行の残りがコメント化し、**ビルドは成功したまま本文が PDF から消える**（実測: claude 訳 seg-0014 で段落の残りが消えていた）。
- 前 ADR は「verbatim・lstlisting は保護対象に含めない」と決めたが、**エスケープした特殊文字は検討していない**。verbatim を外した理由（中身が一様でなく、コメント行は訳す価値がある）は、1 文字の literal には当てはまらない。

# Material for decision
- [数式保護 ADR](./20260814-protect-math-spans-before-translation.md): 「書き写しの機会そのものを与えなければ、この失敗は原理的に起こらない」。印の形（`〔n〕`）と保持率の実測（4 形式とも 9/9）もここ。
- [品質ゲート ADR](./20260708-quality-gate-machine-vs-llm-and-explicit-failure.md): 機械で確定できる欠陥に LLM コストを払わない。
- 実測（run3）: 落ちた 2 節はいずれも形式の予算を使い切っての失敗で、品質の予算は手つかずだった。
- 実測（run1・claude 訳）: `symbol-command` が検出した実欠陥は local 4 節・claude 2 節。うち `\%` → `%` は両プロバイダで起きている。
- checkpoint の無効化キーは `hashContext(原文, 用語スライス, brief, style)` で、**伏せた本文は入っていない**。保護の範囲を変えても進行中の run の checkpoint は無効化されない。

# Decision
- **数式区間の外にあるエスケープ済み特殊文字（`\%` `\&` `\#` `\$` `\_` `\{` `\}`）も印へ差し替える**。正本は `src/segment/protect.ts` の `escapedSpecialSpans`。
- **`\\`（行終端）は含めない**。位置が意味を持ち、セル本文は翻訳対象なので、表ごと伏せると訳せなくなる（前 ADR の判断を踏襲）。`\\` の直後の `%` は綴りではなくコメント開始なので、綴りの開始と誤認しない。
- **数式区間・verbatim 区間の中は対象外**。数式は既に区間ごと保護されており、verbatim は前 ADR で対象外と決めた。
- **印の番号は原文の出現順**（数式と特殊文字を混ぜて 1 本の列にする）。復元は既存の `restoreMath` をそのまま使う。
- 検査（`symbol-command`）は**残す**。保護は「落とさせない」ためのもので、モデルが新たに生の `%` を持ち込む経路は塞げない。

# Consequences
- 良い面
  - `\%` の backslash 落ちが**構造上起こらなくなる**。両プロバイダで起きていた「ビルド成功のまま本文が消える」事故が、事後検出ではなく設計で消える。
  - 印が落ちたときの指摘が「`〔3〕` が消えています」になり、`symbol-command` の「`%` src=0 ja=1」より具体的になる。
  - 書き写しの密度が高い節（コホート記述）で、形式の改稿予算を数式以外に食われなくなる。
- トレードオフ
  - **印の数が増える**。seg-0007 のような段落では 1 段落に 6 個以上の印が並び、モデルが位置を取り違える余地も増える（数式と違い、印が語の途中に挟まる: `61〔1〕`）。効果は実測で確認する。
  - `\{` `\}` を伏せると、訳文で括弧の対応を調整したい場合に手が出せなくなる。学術論文の literal な波括弧は稀なので影響は小さいと判断した。
  - モデルは `\%` が「パーセント」であることを見なくなる。`61〔1〕 male` から「男性 61〔1〕」を作る際、単位の言い回しに手が入らない。前 ADR の数式と同じトレードオフ。
