# 2026/10/07 図表のキャプションは全プロバイダの翻訳指示で訳す

# Status
- accepted

# Situation
- 対訳 PDF（横長の対訳 PDF の ADR 20261006。別 PR で追加）の PoC で、和訳側の図のキャプションが英語のまま残っていた。
- 1810.11953 の出力はローカルモデルで作られ、`figure` 環境内の literal なキャプションが未訳だった。

# Context
- 翻訳指示（初稿）は「本文のみを日本語に訳し」で、キャプションを含めていなかった。モデルはキャプションを訳さず原文のまま残した。
- ログ由来の追加指示は frontier モデルだけに置く方針（ADR 20260913。claude / codex / OpenRouter の GPT・Claude 系にだけ有効な `adaptive` プロファイル）がある。`adaptive` にはキャプションを訳す指示がすでにある。
- 読者に見える文章であるキャプションを訳さないのは、プロファイルの出来の差ではなく、基本の指示の欠落である。

# Material for decision
- 1810.11953（ローカルモデル）の出力: 図 1 のキャプションが英語のまま。
- 修正後の live 確認（claude）: `\caption` の中身だけが日本語になり、`figure*`・`\includegraphics`・`\label` は原文のまま残った。
- ユーザー判断（2026-10-07）: 「baseline の指示にも『キャプションを訳す』を足す」。

# Decision
- 初稿の翻訳指示を「本文と図表のキャプション（`\caption` の中身）を日本語に訳し、LaTeX の構造・制御綴り・参照・数式・図のパスは原文どおり残す」とし、**プロファイルによらず**全プロバイダに適用する。
- ログ由来の追加指示を `adaptive` に限る方針（ADR 20260913）に対する、キャプション翻訳についての例外とする。他のログ由来の指示は従来どおり `adaptive` に置く。

# Consequences
- 良い面: 和訳 PDF と対訳 PDF の図表キャプションが、プロバイダによらず日本語になる。別パスでキャプションだけを訳す必要がなくなる。
- トレードオフ:
  - ローカルモデルでの有効性は未検証（claude でのみ確認した）。小さいモデルで指示追従を悪化させる可能性は残る。ローカルモデルで同じ論文を回して確認する。
  - マクロの引数経由のキャプション（`\caption{#3.}` のような定義側）は、この指示では訳されない。呼び出し側の引数が訳されるかは別に見る。
  - 形式検査（未翻訳検査）はキャプションを対象にしていない。キャプションが訳されたかを機械的に検査する仕組みは、この ADR の範囲外。
