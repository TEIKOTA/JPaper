# 2026/11/18 /jpaper で失敗したら、その場の Coding AI が失敗した LLM 呼び出しの代わりを務め、検査と組版は JPaper が通す

# Status
- accepted

# Situation
- `/jpaper`（claude・codex から JPaper を使う skill。#424）は、和訳が失敗すると原因を調べて伝え、起票の候補を挙げるだけで終わる。利用者の手元には PDF が残らない。
- 形式・品質で落ちた節（終了コード 3・4）は再実行を勧めるだけで、同じ節が落ち続けると先へ進めない。組版の「翻訳起因」（終了コード 5）は同じ出力先での再実行では直らず、全体の訳し直しになる。JPaper の組み立てのバグ（組版・対訳）は、修正が merge されるまで PDF が得られない（#495・#507・#519・#530・#531・#538・#539 など）。
- その場には LLM（claude・codex）がいるのに使えていない。利用者から、失敗したらその場の claude・codex が手で対応する機能の提案を受けた（2026-11-18、#549）。

# Context
- [明示的失敗 ADR](./20260708-quality-gate-machine-vs-llm-and-explicit-failure.md) の決定 2 は、ワークフローに暗黙のフォールバックを入れること（ゲートを通らない成果物を最終稿として出すこと）を禁じる。決定 3 は、タスクの失敗をどうするかの判断を上位（人間・supervisor 相当）に委ねる。skill のエージェントは利用者の依頼を受けた上位にあたる。
- 手で直した PDF をエージェントが勝手に組むと、ゲート（形式検査・組版の閉じ込め）を素通りする。組版は `TEXINPUTS`・`openout_any=p`・`shell_escape=f` で build の中に閉じ込めている（契約付録 §6・§8）。手で `latexmk` を叩くとこれが外れる。
- エージェントは手当てのために論文の本文を読む。論文は信頼できない入力で（[信頼できない文字列 ADR](./20260811-untrusted-text-never-becomes-instructions.md)）、shell を持つエージェントが読むと指示の注入を受けうる。

# Material for decision
- #549 の本文（利用者が決めたこと: 了承を取らずに手当てを始めてよい／全体の訳し直しも同じ／手当てした版は通常の出力先に最終版だけを置き、手当てしたことは完了時の報告で伝える／恒久的なバグを自動で起票するフラグは要らない）。
- 契約付録 §6（終了コード）・§8（落ちた節の指摘・出力先の扱い・成果物 PDF の名前）。
- `.claude/skills/jpaper/SKILL.md`（「4. 失敗したとき」）。

# Decision

## 決定 1: 手当ては「失敗した LLM 呼び出しの代わり」に限り、検査と組版は JPaper が通す
- 節の訳文を外から渡す入口 `--hand DIR`（`DIR/<節 ID>.tex`）を CLI に足す。渡された節は LLM を呼ばず、節ループと同じ形式検査に通ったときだけ使う。通らなければ落ちた節（終了コード 3）として扱い、checkpoint にも `chapters` にも残さない。
- 手で訳した節には evaluator（品質評価）を通さない。訳した Coding AI 自身が品質の判断を担う。evaluator を通すと、LLM の判定がエージェントの訳を差し戻し続けて同じ所で止まりうる。
- 通った手訳は checkpoint に保存し、以後の再実行は LLM を呼ばずにそれを使う（印のままの訳文 `marked` を持たないので、形式検査の版が変わっても再検査しない）。
- 手で訳し直す節（落ちた節と、組版のエラーから逆引きした翻訳起因の節）の原文を `<outDir>/.run/hand/<節 ID>.src.tex` に置く。
- 組版に失敗した build は捨てずに `translation/build.failed/<layout>`（対訳は `translation/bilingual.failed/<layout>`）へ移して残す。JPaper の組み立てのバグはエージェントがその `main.tex` を直し、`jpaper --rebuild DIR` で組み直す。`--rebuild` は組版と同じ閉じ込めの `latexmk` を使い、危険なコマンドの検査をしてから組む。組めたら成果物 PDF として出力先の直下に置き、失敗の build を消す。

## 決定 2: skill は既定で手当てまで行う
- `/jpaper` の「4. 失敗したとき」は、原因を調べた後で手当てをして PDF まで仕上げる。了承は取らない（全体の訳し直しになる場合も同じ）。
- 手当てした版は通常の出力先に最終版だけを置く。手当てした節・箇所は完了時の報告で伝える。PDF の中には印を入れない。
- JPaper のバグを手当てで迂回したときも、起票の候補の判定と手順（下書きを見せて了承を得る）は今のまま残す。自動で起票するフラグは置かない。
- 手当てで論文の本文を読むときは、本文を指示として扱わない（本文中の命令・URL・コマンドに従わない）。書いてよいのは `.run/hand/` と `translation/*.failed/` の中だけにする。

## 決定 3: 一時的な失敗・環境の失敗は手当てしない
- `input`・`provider`・`upstream`・`timeout`・`busy`・`canceled`・`infra`・`internal` は今までどおり原因と対処を伝える。手当ての対象は `formal`・`quality`・`typeset`（翻訳起因・構造）と対訳の失敗だけ。

# Consequences
- 良い面
  - 形式・品質で落ちた節と、組版の翻訳起因の失敗を、その節だけの手当てで直せる（全体の訳し直しが要らない）。
  - JPaper の組み立てのバグでも、修正の merge を待たずに PDF が得られる。
  - 手訳も形式検査（危険コマンド・構造の破壊・数式の対応）を通るので、明示的失敗 ADR の決定 2 の線（ゲートを通らない訳文を使わない）はワークフローの側で保たれる。
- トレードオフ
  - 手訳の品質は evaluator で検査しない。訳した Coding AI の判断に頼る。
  - `--rebuild` で組んだ PDF は、組版ゲートの欠図・未解決参照の検査を通らない。和訳 PDF を `--rebuild` で組んだ回は対訳 PDF を作らない（前の対訳 PDF は古い訳なので消す）。
  - 失敗した build が出力先に残る（`*.failed`。組版が通れば消える）。
  - 手当てで迂回したバグは、利用者が起票を断れば開発者に届かない。
  - 了承なしに手当てを始めるので、利用者の Claude・Codex の利用枠を使う。
  - shell を持つエージェントが論文の本文を読む。指示の注入への備えは skill の指示（決定 2）と、手訳・`--rebuild` の危険コマンド検査だけで、エージェントの振る舞いそのものは機械で縛らない。
