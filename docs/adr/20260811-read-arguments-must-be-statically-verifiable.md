# 読み込みコマンドの引数は静的に検証できなければ拒否する（main.tex のみ）

## Status

accepted

## Situation

JPaper を web アプリの裏側のロジックとして出すため、攻撃者が投稿した論文アーカイブだけを入力とする敵対的検査を継続している。組版はマルチテナントの同一ホストで走る。

## Context

[読み込みコマンド ADR](./20260811-read-commands-judged-by-argument-not-name.md) は「名前ではなく引数の形で判定する」を決めた。その直後の検査で、判定が見ていない引数が 2 系統あることが実機の latexmk で示された。どちらもホストの任意ファイルを読んで PDF に流出させられ、`findUnsafeTexCommands` は `[]` を返していた。

1. `\import{⟨dir⟩}{⟨file⟩}` は 2 引数コマンドで、走査は第 1 引数しか見ていなかった。`\import{./}{../host/secret}` は第 1 引数だけ見ると無害に見える。マクロも `\csname` も要らない。
2. 引数が制御綴りのとき（`\def\p{/abs}\input\p`、`\InputIfFileExists{\p}{}{}`）、走査の引数パターンがバックスラッシュを排除していたため、コマンドがヒットとして登録すらされなかった。`expandInputs` の正規表現も同じ理由で畳まない。

前 ADR が「残存リスク」として挙げた `\input{\p/passwd}` は、実際には `expandInputs` が ingest 時に削除するため到達しない。想定していたリスクの綴りと、実際に生き残る綴りがずれていた。

引数がマクロなら展開結果は静的には分からない。TeX の展開規則を再現しない限り、「安全である」と示せない。一方で、配布クラス／パッケージは `\InputIfFileExists{\@filef@und}` のような動的引数を日常的に使う（実測: 18 件中 10 件）。同じ規則を同梱支援ファイルへ適用すると、会議テンプレを同梱した正規の論文が落ちる。

## Material for decision

- [読み込みコマンド ADR](./20260811-read-commands-judged-by-argument-not-name.md)
- [支援ファイル ADR](./20260811-support-files-are-part-of-the-inspection-surface.md)（誤検知を実測して対象を絞る方針）
- 実測: 新規則による同梱支援ファイル扱いの誤検知は 18 件中 0 件。実論文（arXiv 2203.06060）も 0 件。
- 実測: `\import{./}{../host/secret}` と `\def\p{…}\input\p` は実機ビルドで PDF へ流出（修正前）。

## Decision

1. 多引数の読み込みコマンド（`import` / `subimport` / `includefrom` / `subincludefrom`）は**全ての引数**を検査し、連結した経路でもビルドツリー外への逸脱を判定する。単一引数コマンドは引数を 1 つだけ読む（多く読むと、直後に続く別のコマンドを引数と誤認して正規の論文を落とす）。
2. **main.tex では、引数が制御綴りを含む読み込みを拒否する**。著者が書くプリアンブルで読み込み先をマクロで組み立てる理由が無く、静的に検証できない以上「安全」とは言えないため。
3. **同梱支援ファイル（.sty/.cls）には 2 の規則を適用しない**。配布クラス由来のファイルは動的引数を日常的に使う。支援ファイルでは引き続き、絶対パス・`..` と `\csname` 難読化だけを落とす。

## Consequences

- 実機で流出を確認した 2 系統を、LLM を呼ぶ前に `kind="input"` で止められる。
- 検査面が著者のプリアンブルと同梱支援ファイルで非対称になる。支援ファイルにマクロで組み立てた絶対パスを書く経路は残る（`\def\p{/etc}\input\p` を .sty に入れる）。これは意図的なトレードオフで、支援ファイルまで strict にすると正規の論文が落ちるため。**組版を隔離環境で動かす前提は取り下げない**。
- 引数の解析は TeX の展開規則の近似に留まる。catcode 変更や `\scantokens` で組み立てる経路は依然すり抜けうる（未再現）。
