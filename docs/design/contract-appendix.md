# 契約付録（実装契約の正本）— source-first コア v1

> 会社B（実装ベンダー）へ渡す**実装契約の正本**。ADR が「なぜ」を、本書が「何を・どの形で・どの値で」を固定する。zod は実装時に `src/` へ写し、ここを唯一の参照元とする。乖離は変更管理の対象。
> スコープ: **v1 = source-first（arXiv LaTeX ソース有り）に限定**。PDF 入力は [PDF 入力 ADR](../adr/20261015-pdf-input-text-layer-as-source-llm-rebuilds-math.md) で方針を決めた（本文の語句はテキスト層、数式と構造は LLM がページ画像から起こす。Nougat は使わない）。契約は実装（#385）と同時に本書へ追記する。関連 ADR: [基盤](../adr/20260708-adopt-deterministic-agent-architecture.md) / [品質ゲート](../adr/20260708-quality-gate-machine-vs-llm-and-explicit-failure.md) / [2層化](../adr/20260709-quality-gate-two-layer-and-build-error-triage.md) / [用語](../adr/20260709-terminology-architecture-two-tier-classified-glossary.md) / [プロバイダ](../adr/20260709-llm-provider-abstraction-local-ollama-and-cloud-cli.md) / [UI/配置](../adr/20260709-user-interface-file-layout-and-cli.md)。

## 1. エージェント I/O（zod スキーマ）

純変換器（ツール無し・入力→JSON テキスト出力→zod 検証）。LLM 出力はプロンプトで JSON を指示し、`result` テキストを zod で検証、壊れていたら形式検査で弾いて再訳。

```ts
// 用語（per-paper 確定辞書の1エントリ。translator へ注入する形）
const TermClass    = z.enum(["established", "paper-defined", "proper-noun", "do-not-translate"]);
const Rendering    = z.enum(["translate", "bilingual", "keep-original"]);
const ResolvedTerm = z.object({
  src: z.string(),
  form: z.string(),                 // 確定訳/表記（例: "アテンション" / "値(Value)" / "Transformer"）
  class: TermClass,
  rendering: Rendering,
  firstOccurrence: z.boolean(),     // このセグメントで初出か（決定的インデクサが算出）
  note: z.string().optional(),      // 訳注の文面（LLM 生成）。preserve/低確信の理由。trigger 該当時に surface
});

// translator: 入力→出力。priorJa/issues は再訳(revise)時のみ埋める
const TranslatorIn  = z.object({
  segmentId: z.string(),
  latex: z.string(),                // クリーンな原文 LaTeX（当該セグメント）
  glossarySlice: z.array(ResolvedTerm),
  priorJa: z.string().optional(),   // 再訳時: 前回の訳
  issues: z.array(z.string()).optional(), // 再訳時: evaluator の指摘
});
const TranslatorOut = z.object({ segmentId: z.string(), ja: z.string() });

// evaluator: 品質判定。数値閾値は持たない（品質は LLM の verdict）
const EvalIssue   = z.object({
  severity: z.enum(["error", "warn"]),
  message: z.string(),
  span: z.string().optional(),
});
const EvaluatorIn  = z.object({ segmentId: z.string(), srcLatex: z.string(), ja: z.string() });
const EvaluatorOut = z.object({
  verdict: z.enum(["pass", "revise", "fail"]),  // pass=抜ける / revise=issuesで再訳 / fail=即failed
  issues: z.array(EvalIssue),
});

// glossary-builder: 収集済み候補＋本文の抜粋→per-paper 確定辞書（1 回でロック）
const GlossaryBuilderIn  = z.object({
  paperId: z.string(),
  excerpt: z.string().optional(),   // §4「本文の抜粋」。abstract・見出し・各節の冒頭
  candidates: z.array(z.object({    // 収集[決定的]の結果＋global 候補の retrieval
    src: z.string(),
    globalCandidates: z.array(z.object({ ja: z.string(), domain: z.string().optional(), description: z.string().optional() })),
    definedInPaper: z.boolean(),    // "we define/call", \newcommand, 強調初出 で検出
  })),
});
const GlossaryBuilderOut = z.object({
  resolved: z.array(ResolvedTerm.omit({ firstOccurrence: true })), // note は残す（訳注の文面）
  brief: DocumentBrief,             // 決定1: 全文パスの副産物（全 translator に注入）
  style: StyleContract,             // 決定1: 文体契約（既定=である調・常体）
});
// firstOccurrence は翻訳配線側の決定的インデクサが後付け（translator に判定させない）
// 節に効く用語（slice）と初出の節は src/terminology/term-coverage.ts で決める:
//   ラテン文字端の語は語の一部に当たらない（末尾 s / es は同じ語）／同じ rendering の複数形の語は除く／
//   節での出現がすべてより長い用語の中にある語はその節では除く。keep-original の出現数も同じ数え方。
//   数えるのは translator が訳す本文だけ（keep の \title と frozen の著者・所属・注記の中は数えない。src/workflows/step-keys.ts の translatedLatex）。
// \def / \newcommand などの定義命令だけの節は LLM へ送らず原文のまま通す（src/segment/macro-only.ts）。

// 文書ブリーフ（brief.md の正本。可視・編集可）
const DocumentBrief = z.object({
  thesis: z.string(),                                        // 論文の主張の核
  sectionRoles: z.array(z.object({ id: z.string(), role: z.string() })), // 各節の役割
  notationConventions: z.array(z.string()),                  // 記法規約（変数・記号の使い方）
  claimStrengthNotes: z.array(z.string()).default([]),       // 主張強度/hedging の注意
});
// 文体契約（style.md の正本。可視・編集可。既定は register=plain=である調・常体）
const StyleContract = z.object({
  register: z.enum(["plain", "polite"]).default("plain"),    // plain=である調・常体
  tensePolicy: z.string(),                                   // 時制方針（例: 結果=過去）
  headingStyle: z.string(),                                  // 見出し訳の方針
  numberStyle: z.string(),                                   // 数字・単位表記
  notes: z.array(z.string()).default([]),
});

// 訳注（uncertainties）。採否=trigger は決定的 / 文面=LLM（heading-untranslated のみ決定的）。data=(A) / render=(B)
const NoteTrigger    = z.enum(["paper-defined-preserve", "low-confidence", "evaluator-warn", "heading-untranslated"]);
const TranslatorNote = z.object({
  id: z.string(),
  trigger: NoteTrigger,
  src: z.string().optional(),       // 対象語（term 系 trigger のとき）
  segmentId: z.string(),
  firstOccurrence: z.boolean(),     // 文書全体で初出か（脚注はここだけ・巻末は1エントリ）
  text: z.string(),                 // 文面（LLM 生成: term=ResolvedTerm.note / warn=EvalIssue.message。heading-untranslated のみ決定的テンプレ）
});
```

## 2. 用語 DB（SQLite / `node:sqlite`）

- 置き場: グローバル共有 `~/.jpaper/glossary.db`（`JPAPER_HOME` で上書き可）。
- **実装は `node:sqlite`。これは Node 22.5+ を要するため `package.json` の `engines` は `>=22.5`**（node:sqlite を維持し追加依存ゼロを保つ判断。2026-07-09 確定）。
- global term テーブル（`src` に UNIQUE を張らない＝1語=複数候補を許す）:

```sql
CREATE TABLE term (
  id          INTEGER PRIMARY KEY,
  src         TEXT NOT NULL,
  ja          TEXT,
  class       TEXT NOT NULL,          -- established|paper-defined|proper-noun|do-not-translate
  rendering   TEXT NOT NULL,          -- translate|bilingual|keep-original
  domain      TEXT,
  description TEXT,
  aliases     TEXT,                   -- JSON 配列
  status      TEXT NOT NULL CHECK(status IN ('confirmed','proposed')),
  source      TEXT                    -- 初出/追記元の paperId
);
CREATE INDEX idx_term_src ON term(src);
-- dedup キー = (src, ja, domain)。書き戻しは status='proposed' で追記、既存(src,ja,domain)は再追記しない。
```

- **論文のマクロは全体 DB へ書き戻さない**: `\` で始まる語（`\newcommand` で論文が定義したマクロ。収集は `src/terminology/collect.ts`）は、論文の用語集では「訳さず残す」語として translator に渡すが、その論文の中でしか意味を持たないので `isAcceptableTerm` で弾き、`proposed` の書き戻しにも Web からの登録にも使わない（#338）。

- per-paper 確定辞書は人間可読・編集可能な `./article/<paper>-ja/glossary.md`（正本）＋ `.run/` 内の派生キャッシュ。ユーザーが `glossary.md` を編集→再実行すると durable が未影響ステップを skip し訳語だけ差し替わる。
- **機械出力の md は run が最後まで到達したときだけ outDir へ確定する**（`glossary.md` / `brief.md` / `style.md`）。中断・例外で抜けた run の中間物を残すと、人間が一度も見ていない機械出力が次の run の正本になり、入力を直しても差し替わらなくなる。**組版に失敗した run（exit 5）でも確定しない**（確定は組版の後に置く）。翻訳自体が失敗して組版へ進まなかった run は最後まで到達しているので確定する。LLM の成果は `.run/steps` の checkpoint に残るため、確定を見送っても再実行のコストは増えない。確定時に `<outDir>/.paper-id` へ論文 ID を記録し、**別の論文が同じ outDir を使うときは既存 md を採用しない**（警告を出して作り直す）。採用しないと、論文 A の brief が論文 B の全 translator プロンプトへ注入される。印が無い出力先（旧版が作ったもの）はこれまでどおり採用する。
- 初期シード: **v1 は空で開始**し、翻訳のたびに `proposed` を蓄積して育てる（同梱シードなし）。`input/` は空のまま（`.gitkeep` のみ）。人間が `proposed`→`confirmed` に昇格。

## 3. 品質ループ（値の正本）

- 単位: セグメント（節）。2層＝[節ループ軽検査＋evaluator] と [全文組版ゲート]（[2層化 ADR](../adr/20260709-quality-gate-two-layer-and-build-error-triage.md)）。
- `MAX_REVISIONS`: セグメントサイズ連動 **小=3 / 中=4 / 大=5**（下限3・上限5）。区分は**絶対トークン閾値**（プロバイダ非依存＝決定的テストのゴールデン値が揺れない）: 小 `<1500` / 中 `<3500` / 大 `>=3500`（§4 の自前推定器で計測）。超過→failed。**この予算は形式検査と品質評価がそれぞれ独立に持つ**（[改稿予算 ADR](../adr/20260815-split-revision-budget-by-checker.md)）。共有していた頃は、形式で手こずった節が品質の改稿を 1 度も試せずに落ちた（実測 seg-0007: 形式で 3 回差し戻し、4 回目で形式を通過した瞬間に残高ゼロ）。「品質のために 1 回取っておく」案は取れない——形式に 3 回必要な節は実在する（実測 seg-0009 はそれで通過した）。節あたりのコストの上限は `1 + 形式上限 + 品質上限` 回の translator 呼び出しで、形式と品質を往復してもそれぞれの予算が単調に減るので停止する。`SectionLoopResult` の `usedRevisions` / `maxRevisions` は**両方の合計**で返す（checkpoint スキーマと進捗表示を変えずに済む）。
- evaluator の合否は**不変条件**で決める（`verdict` 単独では決めない）: **出版可能＝`verdict≠fail` かつ `error` 級 `issue` が無い**。この時のみ pass（`warn` は非ブロッキングで訳注へ流す）。それ以外は `issues` を translator の再訳入力へ回す。**`verdict=fail` にも品質の予算が残る限り再訳を与える**（[改稿予算 ADR](../adr/20260815-split-revision-budget-by-checker.md)。`fail` は「この訳が不可」であって「この節が訳せない」ではない。指摘を渡さずに捨てるのは、1 呼び出しを節約するために節 1 本を失う取引になる。実測 seg-0005 は evaluator の 1 度目の `fail` で、translator が指摘を 1 度も見ないまま落ちた）。`fail` を pass にはしない（不変条件は変えない）。`MAX_REVISIONS` 超過は failed。`error` 級 issue があれば `pass` verdict でも通さない（重大問題の素通しを防ぐ）。**severity の正しい割当は evaluator の責務**（下の rubric で規定）で、意味反転など地の文の意味的欠陥に対する決定的検出器は存在しないため、決定的ハードゲートは §7 の形式検査に限る。実装が持つ検査は `math` / `graphics` / `label` / `paragraph` / `keep-original` / `bilingual` / `untranslated` / `unsafe-command` / `structure` の 9 種（正本は `src/workflows/quality-gate.ts`）。`math` は**個数だけでなく本体も multiset で照合する**（個数だけを数えていた頃は `$\alpha < 0.05$` → `$\alpha > 0.95$` の不等号反転も表示数式の空洞化も `[]` だった。学術論文の翻訳では数式は原文のまま持ち越すのが正しいので決定的に照合できる）。正規化で潰すのは区切り・空白・間隔マクロ（`\,` `\;` `\quad` 等）と数式内の地の文（`\text{}` / `\mbox{}` の中身は訳してよい）だけ。`math` は再訳で直せるので従来どおり再訳の対象に留める。`structure` は訳文が原文に無い文書構造コマンド（`\end{document}` / `\begin{document}` / `\endinput` / `\iffalse`）を持ち込んだ場合で、`unsafe-command` と同じく**再訳せず即失敗**にする。LaTeX は `\end{document}` 以降を無視するので組版は正常終了し、実測で exit 0 / `buildOk: true` のまま PDF に最初の節しか出なかった（`\iffalse` を先頭・`\fi` を末尾に置けば中間を丸ごと消せる）。直せる誤りではなく成果物を壊す綴りなので再訳の対象にしない。`unsafe-command` は訳文が持ち込んだ危険コマンド、`untranslated` は原文のままの残留を捕まえるが担う。`untranslated` の判定に使う「地の文」からは**訳す対象でない環境**（`thebibliography` / `verbatim` / `lstlisting` / `minted` / `alltt`）を除く。除かないと、参考文献やコード片の英字が地の文として数えられ、本文を丸ごと未訳のまま残した訳文が未訳率の閾値を下回って pass する（除去は線形走査で行う。正規表現で環境を畳むと入れ子・未閉じで二次になる）。**地の文の抽出は行コメントを先に落とす**（`%` でコメントアウトした `\begin{verbatim}` に反応すると、囲まれた英語＝PDF には出る本文が地の文から消える）。**判定の入口は原文側の地の文の量**にする（訳文側の語数を入口にすると、訳文で地の文を消すだけで検査ごと無効化できる。実測: 訳文「あ」1 文字とコメント囲みの 2 通りで 8 種すべて `[]`・exit 0）。原文に `MIN_PROSE_WORDS` 以上の地の文があるとき、訳文の日本語が原文 1 語あたり 0.5 文字を下回れば `untranslated` とする（実訳は 1 語 ≒ 1.5〜2.5 文字。下限は目標値ではなく床として大きく余裕を取る）。**「地の文」から除く環境には表・アルゴリズム・図も含める**（`tabular` / `tabularx` / `tabulary` / `longtable` / `array` / `algorithmic` / `algorithm` / `tikzpicture` / `Verbatim`）。手法名・データセット名・指標名を日本語化するのはむしろ誤訳なので、表の中身を地の文と数えると**忠実な訳ほど落ちる**（実測: 見出し・キャプション・地の文をすべて正しく訳した節が、表の行数 20 で「ラテン語優位」、40 で「日本語が見合わない」。表単独の節は 3 行でも発火。翻訳者に直しようがなく exit 3）。**「日本語の量」を数える側も、PDF に描画されない引数を除く**（`\index` / `\label` / 参照系 / `\hypersetup` / `\newcommand` / `\def` 等）。除かないと `\index{ひらがな}` を足すだけで検査を無効化できた（実測: 全文が英語原文のままの訳文に `\index{あ×52}` を足すと `formalCheck` が `[]` を返した。`\printindex` が無ければ 1 文字も描画されない）。さらに、日本語の量だけを見る 2 本の判定は**英語を 1 語も消さずに日本語を足すだけで**通せるので、**原文のラテン語が 9 割以上そのまま残っていること自体**を独立した `untranslated` の証拠にする（忠実な訳でも keep-original の術語は残るため、閾値は余裕を持って置く）。**語数を数えるときは、確定辞書で `keep-original` の語（語境界で一致する分）を原文・訳文の両方から除く。照合は地の文と辞書語に同じ正規化（`proseOf`・ダッシュ `--` `---` `–` `—` の統一・空白の連続の圧縮）をかけた後で行い、正規化で英字が残らない辞書語は使わない**（人名と CRediT 役割名だけを並べた `description` の節を原文のまま残した忠実な訳が、地の文の英単語と数えられて落ち、論文が exit 3 で止まった。issue #455。`description` を地の文から外す環境には入れない。定義リストに地の文がある論文の未訳を見逃すため。除くのは辞書の語そのものだけで、その外の地の文は数える）。この変更で `FORMAL_CHECK_VERSION` を 2 に上げた。
- **evaluator 応答の上限**: `EvalIssue.message` / `span` は `MAX_ISSUE_CHARS`（500 文字）、`issues` は `MAX_ISSUES`（20 件）。プロンプト膨張（＝コスト増幅）と指示文の埋め込みを抑えるため（[信頼できない文字列は指示にしない ADR](../adr/20260811-untrusted-text-never-becomes-instructions.md)）。正本は `src/runtime/untrusted.ts`。
- **evaluator rubric（明示軸・[翻訳一貫性 ADR](../adr/20260710-translation-consistency-brief-style-and-annotations.md) 決定2）**: 従来の「自然さ・専門用語妥当性・原意保持」に加え ①**主張強度・hedging の保持**（断定/限定/推量を原文どおり）②**統計語の忠実**（`significantly`=有意・p 値の含意）③**単位・記法の正しさ**（SI＝立体・`°K`→`K`・数値と単位の間隔）を判定する。②③の一部で決定的に落とせるものは §7 (B) の言語整合 lint に回す。
- **evaluator が従う指示の優先順位**（issue #333）: 確定用語の各行の指示（訳語・併記・原表記）＞ 訳注（どの行に付いたものでも）・文書ブリーフ・文体契約。後者は参考情報で、確定用語の指示に従った訳を違反にしない（訳注が別の語の訳し方を指定していても、その語の行の指示が勝つ）。ブリーフ・文体契約の方針から外れただけの点は `warn` までとする。ただし原文と照らして上の rubric の `error` に当たるもの（意味・主張強度・hedging の反転、数値・単位の誤り）は、ブリーフ・文体契約に関わる事項でも `error` のまま。確定用語違反は**その原語そのもの**に対して訳語・併記・原表記のいずれかの指示に反した場合に限り、用語が大きな句の一部になっている・活用している場合に、確定訳語の主要部を保ったまま句に合わせた形（例: steepest descent→最急降下法 に対し direction of steepest descent→最急降下方向）は違反にしない。食い違う指示を同じ重さで採点すると、どちらに直しても差し戻され、改稿の予算を使い切って品質基準で落ちる（実測: 2209.04836・Sonnet effort low で 5 節が落ち、その 5 節だけで 41 呼び出し・$1.18。用語行の併記「線形モード接続されている(linearly mode connected)」と同じ語の訳注「『線形にモード接続されている』と訳す」が矛盾し、「Steepest Descent→最急降下法」が direction of steepest descent にも当てられていた）。glossary-builder には、`note` を読者向けの訳注（定義・由来・訳語の理由）に限り、`form` と違う訳し方や別の語の訳を書かないよう指示する。正本は `src/runtime/system-prompt.ts` の `EVAL_PRIORITY` と `src/agents/glossary-builder.ts`。
- **warn→訳注の連動**: pass に至ったセグメントに残った `warn` の `issue` は、`TranslatorNote{ trigger: "evaluator-warn", text: issue.message }` として §8 の訳注に流す（`verdict` が `pass`/`revise` いずれでも、`error` を含まず上の不変条件で pass すれば warn を可視化）。品質は落とさず読者に見せる。
- 全文ゲート失敗の分類: 翻訳起因の LaTeX 文法ミス→失敗スニペット＋エラー行のみで再訳 / 構造・テンプレ起因→明示的失敗。

- **数式は翻訳前に保護する**: 数式区間を `〔n〕` へ差し替えて translator へ渡し、`formalCheck` と成果物の直前で復元する（正本は `src/segment/protect.ts`、判定は `tex-spans.ts` の `mathSpans`／数式環境の一覧も同ファイルが正本）。節ループは**印のまま**回す（差し戻す前回訳も印のまま）。印が落ちたら番号で名指しして差し戻す。原文が `〔` を含む場合は保護しない（復元で原文を上書きしないため）。verbatim は対象外。決定と根拠は [数式保護 ADR](../adr/20260814-protect-math-spans-before-translation.md)。
- **用語集の内部矛盾は機械で拾う**: `resolved` の訳語に含まれる**片仮名の連なり**（4 文字以上）を集め、編集距離 1 の組が同居していたら警告する（正本は `src/terminology/consistency.ts`）。用語集は全セグメントのプロンプトへ載るため、矛盾はそのまま訳文全体へ伝播する（実測: ローカルモデルが「ハウスドルフ距離」と「ハウスドッフ距離」を 1 つの用語集に入れた）。**落とさず警告に留める**（「ベクタ / ベクター」のような語形差も距離 1 で拾うが、断定はしない）。比較は 5 文字以上に限る（「パス / バス」のような別語の衝突を避ける）。`keep-original` は原表記なので比較しない。併記形からの訳語の取り出しは**末尾**の括弧で切る（先頭の括弧で切ると「修正（95パーセンタイル）〜」が「修正」になり検出から漏れる）。

## 4. セグメント分割・トークン予算（モデル非依存）

- 境界: `\section`/`\subsection` を第一境界。1セグメントがトークン予算超過なら段落境界で再分割。分割は決定的関数（テスト対象）。
- **分割の前に、本文（`\begin{document}` より後）の無効ブロックを取り除く**（`src/ingest/disabled-blocks.ts`。取り込み時、本文の大きさの上限を検査した後に `cleanLatex` へ適用。条件分岐の開始と `\fi` の対応、偽の枝の波括弧の釣り合い、`\end{document}` をまたぐかは 1 回の走査で決め、verbatim・`\verb`・コメントの中の綴りと波括弧は数えない）: `\iffalse … \fi` と `\if 0 … \fi`（`\if` の後の `0` に空白が続く形。0 と空白を比べるので常に偽）。`\else` の枝があればその中身を残す。入れ子の条件分岐（TeX の基本命令と `\newif` の綴り）は 1 つのブロックとして数える。閉じない・偽の枝の波括弧が釣り合わない・`\end{document}` をまたぐブロックは残す（残したブロックの内側にある無効ブロックは取り除く）。節の境界で `\if 0` と `\fi` が別の節に割れると、片側の脱落で組版が落ちるため（#332）。取り込みの checkpoint は入力の署名で無効化されるので、既に取り込んだ論文には効かない（新しく取り込むときから効く）。
- 予算はモデルのコンテキスト窓 `CW` から逆算:
  - 原文セグメント上限 `segmentBudget = min(0.30 × CW, 8_000)`。8,000 は 1 節の訳出が呼び出し期限（claude 300 秒）に収まる上限（[節の予算の上限 ADR](../adr/20261007-cap-segment-budget-by-output-time.md)）。
  - 訳出予約 `= 1.5 × segmentBudget`、思考余白 `= max(2_000, 0.15 × CW)`、残りを システム/辞書オーバーヘッド＋安全に充てる。
  - `CW` は**プロバイダ設定の定数**（claude subprocess はモデルを渡さないので保守的に既定 `200_000`、Ollama はモデルの context を設定に明記）。実行時に設定から取得。
- **トークン計測は JPaper 自前の決定的推定器**（プロバイダのトークナイザに依存しない固定実装＝分割・MAX 判定が決定的でテスト可能）。プロバイダを変えても分割結果は変わらない。
- **glossary-builder に渡す本文の抜粋**（issue #258、正本は `src/terminology/paper-excerpt.ts`）: 本文そのものは渡さず、決定的に取り出した抜粋を渡す（「全文1回」は「1 回の呼び出し」の意味で、本文全体を渡すことではない）。中身は abstract（本文の `abstract` / `abstract*` 環境、空か無ければ前文の `\abstract{…}`。3,000 字まで）、`\section` / `\subsection` / `\subsubsection` の見出し（必須引数を題にし 200 字まで。深さを `§` の数で示す）、各見出しの直後の 2 文（400 字まで。`e.g.`・`et al.`・`Fig.` などの略語では切らず、全角の終止符でも切る）。冒頭文を取る前に行コメント・verbatim・図表とコードの環境（figure・table・wrapfigure・algorithm・comment・lstlisting・minted）・`\label` を外す。全体は 12,000 字（約 3,000 トークン）まで。**見出しはすべて入れ**、冒頭文は残りの字数に浅い見出しから順に足す（見出しだけで超えるなら入る見出しまで）。各行は 1 行化（制御文字を空白に）し、プロンプトでは `\r`・NEL・U+2028/2029 も行の区切りとして各行の先頭を `> ` にして見出しの偽装を防ぎ、「brief は抜粋に書かれていることから書く。抜粋に無い内容を推測で足さない。sectionRoles の id は抜粋の見出しを使う」と指示する。抜粋が無いと brief は用語候補だけからの推測になる（実測 2203.06060・Sonnet low: 抜粋なしで thesis・sectionRoles が空、ありで主張と節の役割が埋まる。gemma4:12b は存在しない論旨を書いた）。**用語集の checkpoint の無効化キー（原文のハッシュ）は変えない**（進行中の run の節の checkpoint を無効にしないため）。完了した run は出力先の `brief.md`・`glossary.md` を正本として使うので、抜粋は出力先に `brief.md` が無く用語集の checkpoint も無い run（新しい論文・出力先を変えた再実行）から効く。既存の論文に効かせるには、出力先の `brief.md`（必要なら `style.md`・`glossary.md`）と `.run/steps/glossary.*.json` の両方を消して再実行する（brief が変わるので全節が訳し直しになる）。文脈窓の小さい設定（ollama で 32,768 未満）では抜粋と用語候補が 30% を超えうる（未対応）。
- **出力先の brief.md・style.md の読み方**（issue #442。正本は `src/terminology/glossary-io.ts` の `briefFromMd`・`styleFromMd`）: 出力先の brief.md・style.md を使う run（2 回目以降・用語集の編集）は、md が checkpoint の値（用語の検証の値があればそれを先に、次に用語集の生成の値。用語集の編集の計画では書き直した用語集の値）のどれかを書き出したものと一字一句同じなら、読み戻さずにその値を使う。違えば（人が編集した）md を読み戻す。読み戻しには損失がある（節の役割は最初の「: 」で節名と役割に分けるので節名の「: 」が役割へ移り、style の備考は「 / 」で分ける）ため、読み戻した値では節の checkpoint の無効化キーが変わり、編集していない再実行でも全節を訳し直していた（実測: 2011.03395）。translatePaper と用語集の編集は同じ関数で読む（鍵を食い違わせない）。
- **用語の検証**（issue #309・[用語の検証 ADR](../adr/20261013-verify-unconfirmed-terms-with-cli-web-search.md)。正本は `src/terminology/verify.ts`・`src/agents/term-verifier.ts`）: 用語集を作った直後、翻訳の前に 1 回だけ呼ぶ。**条件**: `TranslateOptions.verifyTerms !== false`（CLI `--no-verify-terms` で false。真偽値以外は `kind="input"`）かつプロバイダが claude・codex で、client を内部で作った run（注入した client は `TranslateDeps.webSearch: true` のときだけ）、かつ出力先の glossary.md を使わない run（新しく作る用語集だけ。人の編集は検証しない。既に訳した論文を直すには glossary.md を消して再実行する）。arXiv 以外の入力では、検索する run で、用語と abstract の冒頭が検索に出ることを `onError` で 1 度知らせる。**対象語**: 全体の用語 DB に承認済みの訳が無く、`rendering` が translate・bilingual、`class` が established・paper-defined で `isAcceptableTerm` を通る語。上の抜粋に語として（前後が英数字でない位置で）多く出る語から、同数なら paper-defined、用語集の順で `MAX_VERIFY_TERMS`（10）語まで。対象が無ければ呼ばない。**呼び出し**: role `term-verifier`（meta の phase は `verify`）。user は論文の分野（抜粋を 1 行化して 600 字まで）と、対象語と訳案の一覧（1 行化）と探し方。`LlmRequest.webSearch: true` で、その呼び出しだけ Web 検索を許す（claude は `--tools WebSearch`・`--allowedTools WebSearch`・`--max-turns 12`、codex は `-c web_search="live"`。§5）。再試行は 1 回まで。応答は `TermVerifyOut`（語ごとに、見つけた日本語の表記の候補 `candidates`＝`{form, sources: [{url, quote}]}`。割れていても全部返させ、モデルには選ばせない）。候補・出典・引用・表記の上限（5・5・400 字・200 字）を超えた分は切り詰めて読む（1 か所の超過で応答全体を捨てて検索し直さない）。**採否（決定的）**: 応答の `src` は大文字小文字を無視して対象語に当て、重なれば先のもの。候補の表記と引用は、空白をまとめ、英数字と日本語の間の空白を除いて比べる（「Rashomon 集合」と「Rashomon集合」は同じ表記）。表記は 40 字以内・かな・漢字・々・長音・中黒・英数字・空白・ハイフンだけ・日本語を含むものだけを数える（句読点・括弧・記号を含む表記は数えない）。表記ごとに、https の出典で引用にその表記が含まれるものを、ホスト名（先頭の `www.` だけを除く。サブドメインは別のサイト、同じホストの別の著者は同じサイト）ごとに 1 サイトと数える。サイトの数が最も多い表記を採り、最多が並べば unverified（`conflicting`）。採った表記が用語集の訳（bilingual は日本語部分）と同じなら confirmed（1 サイト以上）。違えば `MIN_REPLACE_SITES`（2）サイト以上のときだけ replaced で、translate は表記そのもの、bilingual は `表記(原語)` に差し替える（足りなければ unverified の `few-sites`。原語と合わせて 200 字を超える場合も同じ）。採れる候補が無ければ unverified の `not-found`。同じ元の訳の対象語どうしで採った表記が違えば（confirmed の表記＝元の訳も含めて）、サイトの数の最も多い表記の語だけを採り、ほかの語は unverified（`conflicting`）。最多が並べばその元の訳の語は全て `conflicting` で差し替えない。**差し替えの波及**: 差し替えた語の元の訳（日本語部分）を、ほかの語の訳（元の訳を含む語＝「経験的ラショモン集合」・同じ訳の語。keep-original の語と confirmed の語は除く）・brief・style・全語の訳注の中で新しい訳に書き換える（長い元の訳から当てる。confirmed の語の訳と、先に当てた新しい訳の中は書き換えない）。揃えた語は `via`（差し替えを決めた語）付きの replaced として結果に残し、glossary.md の「検証」の欄に「用例に合わせた <語> の訳に揃えた（元の訳: …）」と書き、`onError` で知らせる（`RunSummary.terms` の件数には数えない）。unverified の対象語を揃えたときは unverified のまま `via`・`original` を付け、「検証」の欄の未確認の理由に「。<語> の訳に揃えた（元の訳: …）」を続ける（件数には数える）。書き換えで brief・style・訳注が上限を超えるなら、その run の差し替えを全て取り消して unverified（`few-sites`）にする。**結果**: 差し替えた用語集・brief・style で翻訳する。glossary.md に「検証」の欄（6 欄目。読み戻しは先頭 5 欄だけ）を足し、replaced は「用例に合わせた（元の訳: …） 出典: URL…」、confirmed は「用例と一致 出典: URL…」、unverified は理由ごとの「未確認（…）」。unverified の語で本文に出るものは、訳注（trigger `unverified-term`）を決まった文面「<原語> の訳語「<訳>」は、Web 検索で既存の日本語の用例を確かめられなかった（未確認）」で付ける（モデルの note・low-confidence・preserve の訳注より優先し、その語には他の訳注を付けない）。検証した run は語ごとの結果を step `term-checks`（キャッシュには使わない。呼び出しが失敗した run も残す）に書き、用語集を新しく作って検証しない run は空にする。出力先の glossary.md を使う run（2 回目以降・用語集の編集の組み直し）も、`term-checks` のうち、今の glossary.md の訳が同じままの unverified の語には同じ訳注を付ける（人が訳を直した語は外す）。`RunSummary.terms = { checked, confirmed, replaced, unverified }`（検証を呼ばなかった run は `null`）。差し替えと未確認は 1 語ずつ `onError` で知らせる。全体の用語 DB には confirmed として登録せず、差し替えた訳も他の語と同じく proposed として書き戻す。**checkpoint**: step `term-verify`（値は検証の後の用語集・brief・style とこの値（あれば）のどちらかと一致すれば未編集とみなす。呼び出しが失敗したら（中断・期限超過は除く）対象語を全て unverified（`failed`）として進め、`onError` で知らせ、checkpoint には残さない（その run の glossary.md は確定するので、やり直すには glossary.md を消して再実行する）。
- glossary-builder の「全文1回」も同 30% ルール。超える論文は候補集合を共有したまま確定パスを分割。**分割時の合流規則（[翻訳一貫性 ADR](../adr/20260710-translation-consistency-brief-style-and-annotations.md) 決定1 の大域一貫を守る）**: ①`resolved` の語衝突は**初出パス優先**で確定（後続パスは既確定語を再確定しない）／②`brief`/`style` は**最終統合パスで1回だけ確定**（各分割パスは `resolved` のみ返し brief/style を出さない）。これにより長い論文でも文書ブリーフ・文体契約が1つに定まる。

## 5. プロバイダ・CLI 契約

- **ollama は `/api/chat` を `stream: true` で受ける**。まとめ受けだと Node の `fetch`（undici）が持つ 300 秒の既定タイムアウトに掛かり、生成が長いだけで接続ごと落ちて `fetch failed` としか分からなくなる（実測: ollama 側に `500 | 5m0s | POST /api/chat`、run は `llmCalls: 7` で provider 失敗）。チャンクが流れ続ける限り無通信タイムアウトは発火せず、**期限は `withCallTimeout` だけが持つ**。NDJSON を行単位に組み立て、`message.content` を連結、統計（`prompt_eval_count` / `eval_count`）は最終チャンクから取る。`MAX_RESPONSE_CHARS` の打ち切りは連結後の本文と**未改行バッファの両方**に掛ける（行が来ないまま膨らむ応答を止められないため）。HTTP 200 で始まった後の `{"error": ...}` 行は provider エラーにする。
- 実装 = **4つ**: `ollama`（local, オンデマンド daemon）/ `claude`（cloud, `claude -p --output-format json` の `result` を抽出）/ `codex`（cloud, `codex exec` の最終メッセージ）/ `openrouter`（OpenAI 互換 API）。
- `--provider {ollama|claude|codex|openrouter}` は **必須（既定なし）**。省略はエラー（終了コード §6）。**受理値の正本は `src/types/contract.ts` の `Provider`**（[UI/配置 ADR](../adr/20260709-user-interface-file-layout-and-cli.md) の例示 `local|cloud` は概念軸）。
- claude CLI は純変換器化して使う: `--append-system-prompt` で役割注入、`--max-turns 1`、内蔵ツール無効化（`--tools none`。`--allowedTools ""` はツールを無効化できずモデルが tool_use を試みて `error_max_turns` になるため不可。SHOW 検収で判明）。例外は `LlmRequest.webSearch: true` の呼び出し（§4「用語の検証」）だけで、`--tools WebSearch`・`--allowedTools WebSearch`（利用者の権限設定によらず確認なしで使わせる）・`--max-turns 12`（`WEB_SEARCH_MAX_TURNS`。検索 1 回で 1 ターン使う）にする。対応 CLI バージョンはレンジ指定し、出力 JSON 形式は統合テストで回帰検知。
- **claude CLI へのプロンプト本文（`req.user`）は stdin で渡す**（`-p` の位置引数にしない）。引数で渡すと論文によっては引数長の上限を超えて起動できない（実測: cmux のシム経由で上限 122,880 バイト、用語集構築で exit 2）。子プロセスが本文を読まずに終了したときの `EPIPE` は捨て、失敗は終了コードで provider エラーにする（[landmines](./landmines.md)）。`--append-system-prompt`（system）は引き続き引数で渡す。
- **claude CLI は `--safe-mode` 付き・作業ディレクトリ `os.tmpdir()` で起動する**。利用者・プロジェクトの CLAUDE.md、hook、git status などを毎回の呼び出しの文脈に載せない（実測: repo の中では約 15,400 入力トークンで「読み込んでいる指示」を答え、分離後は約 2,100 トークンで「なし」。issue #306、[landmines](./landmines.md)）。
- **codex CLI は利用者の設定・ルールを読まずに起動する**（[codex プロバイダ ADR](../adr/20261008-add-codex-provider-isolated-from-user-config.md)）: `codex exec --ephemeral --sandbox read-only --skip-git-repo-check --ignore-user-config --ignore-rules -c features.<名前>=false … -c web_search="disabled" [--model ID] [-c model_reasoning_effort="LEVEL"] -C <一時ディレクトリ> -o <一時ファイル> -`。**ツールを止める**: シェル（`shell_tool`・`unified_exec`）・画像の閲覧・apps・plugins・hook・memories・複数エージェント・ブラウザ・computer use などの機能を `-c features.<名前>=false` で切り、Web 検索も切る（一覧の正本は `src/providers/codex.ts` の `CODEX_DISABLED_FEATURES`）。例外は `LlmRequest.webSearch: true` の呼び出し（§4「用語の検証」）だけで、`web_search="live"` にする（他の機能は止めたまま）。`--sandbox read-only` はコマンドを読み取り専用で走らせるだけでツールを消さない（実測: 止めない codex は論文の指示どおり `ls ~` を実行して答え、止めると「実行不可」と返した）。`--disable <名前>` は codex が知らない名前でエラーになるが、`-c features.<名前>=false` は無視されるので、版が変わっても起動は壊れない。**cmux の合図を渡さない**: 環境変数 `CMUX_*` を落として起動する（cmux の codex ラッパーは `CMUX_SURFACE_ID` があると `exec` にも hook と computer use の引数を差し込む）。stdin の書き込み失敗（codex が入力を読まずに終わったときの EPIPE）は握りつぶし、終了コードで失敗を返す。stderr は末尾 8,000 字だけを診断用に持ち、量で打ち切らない。system と user は 1 本のプロンプトに `<system>`・`<input>` で包んで stdin で渡し、最終メッセージを `-o` のファイルから読む。作業ディレクトリは呼び出しごとの一時ディレクトリで、終わったら消す（実測: 利用者の設定ありで 11,458 トークン、なしで 2,003 トークン。訳文と使われたモデルは同じ）。`CodexConfig { model?, effort? }` は指定された値を渡し、未指定の項目は translatePaper が既定で埋める（次項）。`--effort` の値は TOML の文字列として埋め込むので `CLAUDE_EFFORT_PATTERN`（英小文字のみ）で検証する。コンテキスト窓は `DEFAULT_CODEX_CW`（200,000）、呼び出しの期限は `DEFAULT_CODEX_REQUEST_TIMEOUT_MS`（300 秒）。usage・費用はトレースに残さない（サブスクリプション利用）。checkpoint の無効化キーに model / effort を含めないのは claude と同じ。
- モデル ID: claude(subprocess) は `ClaudeConfig { model?, effort? }` を `--model` / `--effort` で claude CLI へ渡す（[claude のモデル・推論強度 ADR](../adr/20261007-pass-claude-model-and-effort-via-cli-args.md)）。**claude・codex で未指定の model・effort は translatePaper が既定で埋める**（[既定の model・effort ADR](../adr/20261013-default-to-latest-mid-tier-models-at-medium-effort.md)、正本は `src/providers/defaults.ts`）: claude は別名 `sonnet`（claude CLI が最新の Sonnet に解決する）、codex は `$CODEX_HOME/models_cache.json`（既定 `~/.codex`）のうち隠されていない Sol 系（`gpt-<版>-sol`）で版が最も新しいもの（版は数値で比べる）、effort はどちらも `medium`。明示した値が優先する。codex の一覧が読めない・Sol が無いときは model を渡さず（codex の既定）effort は `medium`、警告を出す。注入クライアント（`deps.client`）には足さない。claude のトレースの `model` は応答の `modelUsage` の鍵（実際に使われたモデル）。ollama は設定でモデル ID 明示（例 `llama3.1:8b`、変更可）。

- **Windows での外部コマンドの起動と停止**（正本は `bin/spawn-cli.mjs`、issue #462）: Windows（`process.platform === "win32"`）では、claude・codex・pnpm・latexmk を shell（cmd.exe）を介さずに起動する。PATH と PATHEXT の順に実体を探し、`.exe`・`.com` は直接起動する。npm・pnpm が置く `.cmd`・`.bat` の shim は、`%*` の直前に書かれた対象のパス（`"%dp0%\…"`・`"%~dp0\…"`）を読み、対象が `.js`・`.cjs`・`.mjs`（拡張子の無い対象は shim が node で起動しているときだけ）なら jpaper を動かしている node で、`.exe` ならそれを直接起動する。どちらでもない `.cmd` は理由つきの provider エラー（終了コード 2、再試行しない）。cmd.exe を介すと、claude に引数で渡す複数行の `--append-system-prompt` を壊す（cmd.exe の引数は改行を運べない）。見つからなければ名前のまま起動し、従来どおり「見つかりません」になる。止めるときは `taskkill /pid <pid> /T /F` で子孫ごと止める（プロセスグループが無く、shim を解いた後でも node の子の native の CLI（codex）が残るため）。`detached` は使わず（新しいコンソールのウィンドウを開くため）`windowsHide` を付ける。`jpaper web` は Ctrl+C（SIGINT）を子へ渡さない（同じコンソールの子にも届くため）。組版の `TEXINPUTS` などの区切りは `path.delimiter`（Windows の kpathsea は `;`）。macOS・Linux の振る舞いは変えない。
- **`--context-window` は `--provider ollama|openrouter` 専用**。claude・codex と併用したら黙って捨てず入力エラー（終了コード 2）にする（「指定したのに効かない」を作らない）。ollama で `--model` / `--context-window` の片方だけ指定した場合、もう片方は `DEFAULT_OLLAMA` の値を使う。どちらも無指定なら `ollama` を渡さず既定に委ねる。
- **claude・codex の `--model` / `--effort`**（[claude のモデル・推論強度 ADR](../adr/20261007-pass-claude-model-and-effort-via-cli-args.md)、codex は [codex プロバイダ ADR](../adr/20261008-add-codex-provider-isolated-from-user-config.md)）: `--provider claude` では `--model ID` と `--effort LEVEL` を受け、`TranslateOptions.claude` 経由で claude CLI の `--model` / `--effort` にそのまま渡す。どちらも無指定なら `claude` を渡さない（`undefined`）。**`--effort` は claude と codex 専用**で、他の provider と併用したら入力エラー（終了コード 2）。値は**英小文字の水準名**（`CLAUDE_EFFORT_PATTERN` = `^[a-z]+$`。正本は `src/config.ts`）だけを受け、水準の列挙はしない（claude CLI の受理値に追随する保守を持たない。未知の水準は claude CLI 側のエラーとして provider 失敗で返る）。モデル ID は空・空白のみ・先頭が `-` の値を拒否する（`isClaudeModelId`。claude CLI の引数列でオプションと取り違えさせない）。同じ検証を `translatePaper` の入口（`entryError`）にも置く。コンテキスト窓は model を指定しても `DEFAULT_CLAUDE_CW`（200,000）のまま。
- **checkpoint の無効化キーに claude の model / effort を含めない**: 同じ `--out` で model / effort を変えて再実行すると、通過済みの節の checkpoint をそのまま使い、未通過の節だけを新しい設定で訳す。①既存の provider・`ollama.model`・`openrouter.model` もキーに含めておらず、通過済みの節は形式検査と evaluator を通った訳文なので、設定を変えた再開でも「続きから訳す」を既定にする。②未指定のときのモデルは別名（claude の `sonnet`）やモデル一覧（codex の最新の Sol）で解決され、モデルの更新で変わるので、キーに含めてもモデルを代表できない（未指定→同じモデルを明示しただけで全節をやり直す一方、別名の解決先の変化は検知できない）。このため、旧版で途中まで訳した出力先を再開すると、残りの節だけが新しい既定（最新の Sonnet・Sol と medium）で訳され、1 本の論文の中でモデルが混ざりうる。モデルを変えて全体を訳し直すときは `--out` を変える（別の `.run`）。
- **`--context-window` の受理範囲は `MIN_CONTEXT_WINDOW`〜`MAX_CONTEXT_WINDOW`（1024〜1,000,000。正本は `src/config.ts`）**。セグメント予算が 0.3×CW なので、下限未満は本文を刻み切れず `maxSegments` 超過に化け、`0` は「本文が空」（§6 の別の失敗）に化ける。同じ検証を `translatePaper` の入口（`entryError`）にも置き、web からの直接呼び出しでも `kind="input"` で返す。
- **未知のオプション（`--modell` 等の綴り違い）は `<input>` の位置引数に落とさず入力エラーにする**。落とすと「arXiv ID として解釈できない」という無関係な失敗に化ける。
- **思考（`--think` / `--no-think`、`OllamaConfig.think`）**: thinking 対応モデルは既定で `message.thinking` に思考を出し、JPaper は `message.content` しか読まないので**生成時間を払って捨てる**（実測: gemma4:12b-it-qat / M4 24GB で 4,000 字のセグメント 1 本に 244.5 秒、うち思考 4,321 字・訳文 2,199 字）。`/api/show` の `capabilities` に `thinking` が無いモデルへ `think` を送るとエラーになりうるため、**能力を引いてから送る**（構造化出力 ADR と同じ「プロバイダ能力で分岐」）。能力の問い合わせはモデル単位で 1 回だけキャッシュし、**問い合わせに失敗したときは結果をキャッシュせず `think` も送らない**（一度の失敗で「思考なし」を焼き付けない）。`think` 無指定なら能力も引かずモデル既定に委ねる。**既定は `think: false`**（同一セグメントの比較で 244.5 秒 → 99.2 秒、訳文 2,199 字 → 2,175 字、LaTeX コマンド 19 個の保持は両方とも完全で差が出なかったため。n=1 の計測なので、品質差が見つかれば `--think` で戻せる）。

## 6. CLI 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功（和訳 PDF 生成・全ゲート通過） |
| 1 | 想定外エラー（`internal`）／実行環境の障害（`infra`＝権限・容量・パス衝突。コードのバグと区別するため `kind` で分ける） |
| 2 | 入力形態の判定不能 / `--provider` 未指定・不正（`input`）／作業ディレクトリの `.env` を読めない（§8「.env の読み込み」。stdout は空）／出力先が使用中（`conflict`）／上限超過（`too-large`）／一時的な過負荷（`busy`）／外部サービス障害（`upstream`）／LLM プロバイダ利用不能（`provider`） |
| 3 | 節ループの形式検査が MAX_REVISIONS 内に通らず failed／PDF 入力で、原本のページ画像に落ちたページが読んだページの半数を超えた（`formal`。§8「PDF 入力」） |
| 4 | 品質未達（evaluator が pass に至らず MAX_REVISIONS 超過 or `fail`） |
| 5 | 全文組版ゲート失敗（構造・テンプレ起因のビルド/欠図/未解決参照） |
| 6 | 呼び出し側の中断（`AbortSignal`＝`canceled`。web の切断）／run 全体の期限超過（`timeout`） |

- stdout: 最終成果パスとサマリ JSON。stderr: 進捗・エラー。
- 組版失敗の理由の要約は、翻訳起因（`failedSegments`）か構造の誤り（`structuralErrors`）で組版が途中で止まったときは未解決参照を並べない（止まった位置より後の引用がすべて未定義になるだけで、原因ではない）。

## 7.5 (A) コアの受け入れ条件（(B) 非依存で定義）

(A) は組版=(B) を持たないため「main.pdf 生成（終了コード0・`buildOk`・`pdfPath`）」に単体で到達できない。(A) の完成を (B) から切り離して定義する（R1 解消）。

- **(A) の成果**: 節ループ品質ゲートを通過した**訳文セグメント群**（`translation/chapters/*` 相当の中間物）＋ per-paper 確定辞書（`glossary.md`）＋ **文書ブリーフ `brief.md`・文体契約 `style.md`**（[翻訳一貫性 ADR](../adr/20260710-translation-consistency-brief-style-and-annotations.md) 決定1）＋ **訳注データ `notes.json`**（決定3。PDF 描画は (B)）＋ `RunSummary`。**組版・PDF は含まない**。
- **(A) 単体の終了コード**: `0`=全セグメントが節ループ通過（翻訳完了・組版前）／`2`=入力・プロバイダ／`3`=形式検査が MAX 内に通らず failed／`4`=品質未達 failed。`5`（全文組版ゲート）・`pdfPath`・`buildOk` は **(B) 結合後に評価**（(A) 単体では `RunSummary.buildOk = null`）。
- **(A) の検収**: ①`FakeLlmClient` 注入で配線・段階遷移・checkpoint の idempotent-skip・`MAX_REVISIONS` 到達 failed が決定的に再現（**両プロバイダの配線とも Fake で検収**）、②**実 LLM 検収は `claude` プロバイダ**（会社A の claude code CLI ログインセッション）で訳文セグメント＋`glossary.md`＋`brief.md`/`style.md`＋`notes.json`＋`RunSummary` が生成されること。組版通過は (B) 検収項目。
- **プロバイダ別の (A) 完了範囲（A-1 決着）**: `ollama` プロバイダの**実装（`LlmClient` 実装・オンデマンド daemon・設定契約）は (A) に含む**が、**実機（実モデル）検証は後回し**（別途）。`claude` を実 LLM 検収の基準プロバイダとする。両者の配線の決定的検収（①）は (A) 必須。

## 8. 追加契約（新B レビュー反映）

- **core API**: `translatePaper(input: JpaperInput, opts: TranslateOptions, deps?: TranslateDeps): Promise<Result>`。`TranslateOptions = { provider; outDir?; ollama?; openrouter?; claude?; concurrency?; signal?; timeoutMs?; bilingual? }`、`TranslateDeps` は web が差し替える依存（`client` / `trace` / `cacheKey` / `db` / `dbPath` / `ingest` / `limits` / `work` / `gate` / `onError` / `onProgress` / `latexRunner`）。`Result = { status: "ok"|"failed"; pdfPath?: string; exitCode: number; error?: RunError; summary: RunSummary }`（`pdfPath` は出力先の直下の和訳の成果物 PDF。下の「成果物 PDF の名前」）。CLI・GUI はこの1関数を呼ぶ薄い皮（[UI/配置 ADR](../adr/20260709-user-interface-file-layout-and-cli.md) 決定4）。例外は投げず `status/exitCode` で表現（§6 と対応）。
- **stdout サマリ JSON**: `RunSummary = { paperId, outDir, segments: {total, passed, failed}, revisions: {max, used}, glossary: {proposedAdded}, terms: {checked, confirmed, replaced, unverified}|null, notes: {total, byTrigger}, layout: "original"|"template"|null, buildOk: boolean|null, bilingual: {status, pdfPath?, message?, pairs, fallbackSegments}, sharedDefaults: ("db"|"cacheKey"|"outDir"|"limits"|"work")[], llmCalls, title: "translated"|"failed"|"absent"|null, exitCode }`（zod 定義を実装時に写経）。`layout` は採用した組版モード（[組版レイアウト ADR](../adr/20260710-typesetting-layout-original-first-hybrid.md)。`original`=原プリアンブル温存／`template`=共通テンプレへフォールバック）。組版は (B) のため **(A) 単体では `layout=null`**（`buildOk=null` と同様）。`notes` は §1 `TranslatorNote` の件数集計（本体は `notes.json`）。`byTrigger` は `paper-defined-preserve|low-confidence|unverified-term|evaluator-warn|heading-untranslated` 別の件数。`terms` は §4「用語の検証」の件数（`{checked, confirmed, replaced, unverified}`、検証しなかった run は `null`）。`title` は論文タイトルの翻訳結果（下記「論文タイトルの翻訳」。`translated`=タイトルの訳を得て組版へ渡した（PDF に入ったかは `buildOk` と組み合わせて判断する。`buildOk=true` なら訳が入っている。本文の節が落ちて組版しなかった run（`buildOk=null`）や組版が失敗した run（`buildOk=false`）でも `translated` のまま）／`failed`=タイトルを訳せなかった、または訳入りの組版が翻訳起因で落ちて原題で組み直した（組版したなら原題）／`absent`=訳す `\title` が無い（効く `\title`＝本文中の `\title`、無ければ前文の `\title` が、無い・空・地の文を含まない）／`null`=例外で中断し summary を部分的にしか作れなかった run。取り込み・用語集の段階で終わった run に加え、本文の翻訳中・組版中の例外（プロバイダ例外・中断など）で終わった run も、タイトルを訳し終えていても `null`）。
- **論文タイトルの翻訳**（ADR 20261006-bilingual-side-by-side-pdf「タイトルは訳し、通常の和訳 PDF にも反映する」。正本は `src/tools/paper-title.ts` と `src/workflows/translate-paper.ts`）: セグメント化は本文（`\begin{document}` 以降）だけが対象なので、前文の `\title` は誰も訳さない。タイトルはコードで取り出して既存の節ループ（translator・形式検査・evaluator・改稿）に小さな 1 節として通し、組版時にコードで前文（本文中の `\title` なら本文の `\title`）へ差し戻す。
  - **抽出**: `extractPreamble` で得た前文のうち、コメント・エスケープの外にある**最後の** `\title`（LaTeX は後の定義が勝つ）の本題を取る。`\iffalse` から対応する `\else` / `\fi` まで（入れ子の条件分岐は TeX の基本命令と前文の `\newif` で作った綴りを数える）と `\begin{comment}` から `\end{comment}` までも無効なブロックとしてコメントと同じく読み飛ばす（AAAI の author kit は本物の `\title` の後ろに `\iffalse \title{My Publication Title …} \fi` の例示ブロックを持ち、これを拾うと例示を訳して本物の題を英語のまま残す）。`\iftrue` やマクロで切り替える分岐の評価はしない。短縮タイトル `\title[短縮]{本題}` の `[..]` は読み飛ばし（波括弧の中の `]` は閉じとみなさない。`MAX_OPTIONAL_ARG` 1000 文字まで）、本題は入れ子の波括弧を数えて読む。本題中の行コメントは TeX と同じく「`%` から次行の行頭空白まで」落とし、空白は 1 つに畳む。`\title` が無い・中身が空（`\thanks` だけを含む場合も）なら何もしない。本題が地の文を含まない（制御綴りを除くと文字・数字が残らない。`\title{\papertitle}` のようなマクロ参照だけの形）なら翻訳へ送らず、`notify` で警告して原題のまま組版する（`RunSummary.title="absent"`。訳文も `\title{\papertitle}` のまま返り形式検査・evaluator に掛からないため、送ると LLM を呼んだうえで「訳せた」と誤報告する。マクロ定義まで追って訳すことは対象外）。`\titlerunning` 等の別綴り、`\renewcommand{\title}` のような引数を伴わない出現、定義命令（`\newcommand` / `\renewcommand` / `\providecommand` / `\DeclareRobustCommand` / `\let` / `\def` / `\gdef` / `\edef` / `\xdef`。`*` と空白・コメントを挟んでよい）の直後に来た `\title`（波括弧なしの `\renewcommand\title[1]{…}` や `\let\title=…`。`[1]` を短縮タイトルと読むと定義本体を本題として訳し、上書きしてしまう）は拾わない。本文中に効く `\title` があれば前文は見ない（次項）。
  - **前付けの型**（[前付けの型の表 ADR](../adr/20261011-drive-frontmatter-by-template-profile-table.md)。正本は `src/tools/frontmatter.ts` の `detectProfile`、調査表は [`frontmatter-commands.md`](./frontmatter-commands.md)）: `\documentclass`・`\usepackage` の名前と特徴的な命令（コメントの外）から論文の型を 1 つ選び、タイトルの命令・組む位置・前文の差し替え・対訳のタイトルの取り出しはその型を引く。ICML（`icml\d{4}` か `\icmltitle`）はタイトルが `\icmltitle` でその場で組む（組む位置は命令の直後）。AISTATS（`aistats\d{4}` か `\aistatstitle`）は `\aistatstitle` で同じ。iopart は `\title` がその場で組み、`\maketitle` は組む位置にしない（対訳でもタイトルブロックに置き換えない）。MDPI は前文の `\Title`。elsarticle は `\title` を連結するので、組む位置までに（前文なら前文に）2 つ以上あれば訳すタイトルは見つからない扱い（`absent`）にする。どれにも当たらなければ既定の型（`\title`、組む位置は `\maketitle`・`\end{frontmatter}`）。以下の `\title` は型のタイトルの命令と読む。
  - **本文中の `\title`**（arXiv の arxiv_style テンプレートや IEEEtran・revtex・elsarticle の `frontmatter` 環境など、`\title` を `\begin{document}` の後に書く論文。実例 PathoROB 2507.17845）: **本文で最初にタイトルを組む位置（コメント・無効ブロックの外の最初の `\maketitle` または `\end{frontmatter}`）より前にある最後の `\title` を、前文の `\title` より優先して**タイトルとする（LaTeX ではそちらが後に定義され `\maketitle` に効く）。探索は本文の節を順に見て、組む位置を含む節で止める（`findBodyTitle`。抽出の規則は前文と同じ）。組む位置が本文に無い、または `\title` がその後ろにしか無いなら前文の `\title` を使う。本題が空なら `absent`、地の文を含まなければ前文と同じく訳さず `absent`。
    - **方式（a）を採る**: 本文の `\title` も title 節として 1 回だけ訳し、組版時にその位置の本題を差し替える。その節の translator には `\title[..]{..}` 命令全体を保護区間の印 1 つ（`Segment.keep`→`protectMath({ keep })`。中に入る数式・記号の区間は keep に含めて二重に伏せない。`PROTECT_SPANS` を切っても keep は伏せる）で渡し、原文のまま復元する。印の欠落・重複は形式検査 `title` として名指しで差し戻す（予算切れならその節は exit 3 で落ちる）。復元した `\title` 命令は形式検査・evaluator へ渡す原文・訳文の両方から取り除く（訳されていないのが正しいので未翻訳と判定させない）。checkpoint の無効化キーに keep の範囲を足す（修正前に本文側で訳した結果を再利用しない）。
    - **（b）本文セグメントの訳に任せる案を採らない理由**: 本文の訳で `\title` の中身が訳されるか英語のまま残るかはモデル次第で、形式検査にも evaluator にも「タイトルが訳されたか」を確かめる手段が無い。summary の `title` を本文の訳文から推測して報告することになり決定的に言えない。前文の `\title` と同じ経路（用語集の `firstOccurrence=false`・`\thanks` の取り外し・原題での組み直し）を本文の `\title` にもそのまま使えるのは（a）だけで、本文側の訳と title 節の訳が食い違うことも二重に訳すことも構造的に起きない。
    - **組版での差し戻し**: 訳文の節（訳注の脚注を挿す前）から、原文どおりに復元された `\title` 命令を綴りの一致で探し（同じ綴りが複数あれば原文と同じ順番のもの）、その本題だけを訳題に差し替える（`placeBodyTitle`）。前文は原文のまま。訳注の脚注は原文のまま残した `\title` 命令の中には挿さない（`injectFootnotes` の `skip`。前文のタイトルと同じく訳注を持たない）。`translation/chapters/` の訳文は原題の命令のまま書き出す。命令が見つからない（原文が印 `〔` を含み保護できなかった節など）ときは警告して原題のまま組版し `title="failed"`。訳題入りの組版が翻訳起因で落ちたときの原題での組み直しは前文の場合と同じ。
  - **翻訳へ送る形**: `segmentId="title"`、原文は `\title{本題}`（命令で包んでタイトルだと分かる形にする）。訳文は `\title{…}` の中身だけを取り出して使い、包みが無い・中身が空なら失敗として扱う。**`\thanks{…}` / `\footnote[..]{…}` は翻訳へ送らず**取り外し、訳したタイトルの末尾へ原文の綴りのまま出現順に戻す（`\thanks` の翻訳は issue #294 の対象外。地の文に数えると 12 語以上のタイトルで未翻訳検査の分母が膨らむ。途中にあった脚注記号は末尾へ移る）。`\\` 改行・数式・`\texorpdfstring` などは本題に残し、形式検査（`\\` の個数一致・数式照合）で原文どおり残ったかを確かめる。訳題と同時に成果物 PDF の短い英語名の行も出させ、形式検査の前に取り外す（下の「成果物 PDF の名前」）。
  - **用語集**: 本文と同じく `ctx.resolved` のうち原文に現れる語の slice を渡す。**`firstOccurrence` は常に `false`**（タイトルでは併記形 `値(Value)` を使わず日本語部分だけにする。初出の併記は本文の初出セグメントが担う）。
  - **形式検査の誤発火の確認**: 1 行のタイトルでも各検査は調整不要。未翻訳検査は原文の地の文が 12 語以上のときだけ働き、下限（日本語 0.5 文字/語・ラテン語優位・9 割残存）はタイトルの訳でも満たす（`src/tools/paper-title.test.ts` で 16 語の例を固定）。段落・参照・図・ラベルは 1 行では差が出ない。bilingual は上の `firstOccurrence=false` と整合する。
  - **並行と checkpoint**: タイトルは run 内の並列度（`mapLimit`）の枠を本文セグメントと共有し、先頭に積む（ollama の既定並列度 1 を破らない）。checkpoint の stepId は `title`、無効化キーは本文セグメントと同じく「原文＋slice＋brief＋style」に版 `TITLE_STEP_VERSION`（`pdf-name-v1`。成果物 PDF の名前を持たない旧 checkpoint を使わない）を足したもの。通過し、かつ中身が取り出せた結果だけを保存する（下の「成果物 PDF の名前」の名前も結果 `pdfName` として一緒に保存し、名前が無い・不正でも保存する）。`pruneSteps` の保持集合に `title` を含める。
  - **失敗の扱い**: タイトルだけが失敗した場合（形式・品質の予算切れ、包みの欠落、プロバイダ例外）は**原題のまま組版**し、`notify` で警告して `RunSummary.title="failed"` にする。`exitCode`・`segments`・`revisions` の集計には入れない。中断（`signal` が中断済み）だけは握り潰さず run の中断として扱う。タイトルの訳文が `unsafe-command` / `structure` で落ちたときは「汚染の疑い」と明示して警告する（使われるのは原題なので run は落とさない）。タイトルの `warn` 級 issue は訳注へ流さない（訳注は本文セグメントへ挿す設計のため）。
  - **組版での差し戻し**: 前文の `\title` は `assembleWithMap({ title })` が前文の最後の `\title` の本題だけを差し替える（本文中の `\title` は上の項）（短縮タイトル・他の行は原文のまま）。`original` は原前文、`template` は引き継いだ原前文の `\title` を差し替える（テンプレ既定の `\title{}` より後にあるので訳が勝つ）。訳したタイトルの組版エラーは `\maketitle` が展開される本文セグメントの行に出るため、**訳したタイトル入りの組版が翻訳起因（`failedSegments` 非空）で落ちたときだけ、同じレイアウトを原題で組み直す**。原題で組めたら原題を採用して警告し `title="failed"`、原題でも落ちたら元の失敗をそのまま返す。構造起因の失敗では組み直さない（テンプレ fallback の論文で毎回 latexmk が 1 回増えるのを避ける）。
- **訳注の生成契約（[翻訳一貫性 ADR](../adr/20260710-translation-consistency-brief-style-and-annotations.md) 決定3・採否=決定的 / 文面=LLM）**: trigger を次の決定的規則で採る。①`paper-defined` で `rendering∈{keep-original,bilingual}` に確定した語 ②**低確信=`class="established"` かつ global DB に `status="confirmed"` の一致が無く `proposed` のみ or 未ヒットで preserve に倒した語**（DB 状態から決定的に判定）③evaluator の `warn` issue ④**heading-untranslated=見出し（`\section` 等）の可視テキストが未訳の可能性（`untranslatedHeadings` の決定的検査。非ブロッキングで再訳ゲートには載せない）**。文面 `text` は term 系＝`ResolvedTerm.note`、warn 系＝`EvalIssue.message`、heading 系＝決定的テンプレ（LLM 非依存）。`firstOccurrence`（文書全体基準）で本文脚注は初出1回のみ、巻末一覧は語ごと1エントリ。**描画の切り替え**（issue #439・#445）: 本文脚注は `TranslateOptions.pageNotes === true`（CLI `--page-notes`）のときだけ挿す（既定 false。CLI の `--no-page-notes` は明示の既定で、`--page-notes` と同時に指定すると入力エラー）。`endNotes === false`（CLI `--no-end-notes`）なら巻末一覧の節を足さない（既定 true）。真偽値以外は `kind="input"`。既定を脚注なしにしたのは、脚注が下端の行を取ると対訳 PDF で右の段の段落が次のページへ送られ、左の段に空白が出るため（#445）。`notes.json` と `RunSummary.notes` は切り替えに依らず同じ。脚注だけにすると、本文に挿す位置を見つけられなかった訳注は PDF に載らない。④の決定は [見出し未訳検査 ADR](../adr/20260721-heading-untranslated-nonblocking-note.md)。
- **run-context 注入（brief/style）**: `DocumentBrief`＋`StyleContract` は全 translator へ渡すが、**載せる先は system ではなく user メッセージ**である。論文由来・LLM 由来の文字列は指示にしてはならないため（[信頼できない文字列は指示にしない ADR](../adr/20260811-untrusted-text-never-becomes-instructions.md)）。system は run をまたいで固定の文字列だけで構成し、それがキャッシュ prefix の安定化を担う（[プロンプトキャッシュ再利用 ADR](../adr/20260722-prompt-cache-reuse-stable-system-prompt.md)）。per-segment の確定用語ブロック（rendering 指示）も user 側。トークン予算は §4 の 30% 圏内で管理する。**超過時の圧縮は「要約」ではなく切り詰め**（`MAX_BRIEF_CHARS` / `MAX_BRIEF_ITEMS` でスキーマ側から縛る。要約は LLM 呼び出しを増やすうえ、圧縮結果が非決定になる）。
- **リトライ（`isTransient`）**: 対象＝ネットワーク瞬断・タイムアウト・HTTP 429/5xx・Ollama 一時的接続不可。回数3・指数バックオフ（初期 1s, ×2, 上限 10s）。それ以外（タスク失敗）はリトライせず surface。
- **形式検査の合否規則（節ループ内・決定的）**: 数式保全＝原文と訳文で `$...$`／`\[...\]`／`\begin{equation|align|...}` の**個数一致**（中身は問わない）。段落欠落なし＝**訳文段落数 ≤ 原文段落数**（日本語で複数段落を自然に統合するのを許容。分割・水増しは不可）。ただし訳文段落数が原文の **50% 未満**なら明らかな欠落として error。`keep-original` 一貫＝当該語が全出現で原形のまま。zod 適合＝§1 スキーマ。（大セグメント `>=3500` がトークン予算 `0.30×CW` を超える場合の段落境界での再分割は §4 の core 実装＝(A) に含む。）

- **用語集の上限**: `GlossaryBuilderOut.resolved` は件数 `MAX_TERMS`（500）、`src`/`form` は `MAX_TERM_CHARS`（200）、`note` は `MAX_NOTE_CHARS`。空の `src` は弾く。用語スライスは `seg.latex.includes(t.src)` で選ぶため、空や短い綴りを大量に返されると全セグメントのプロンプトに全件乗る（実測: 2 万件で 275 バイトの入力から 1 run 560 万文字、共有 DB に 2 万行）。`maxLlmCalls` は回数しか見ないのでバイト単位の増幅は素通りする。件数上限は proposed 書き戻しの件数上限も兼ねる。 `brief` / `style` も同じ理由で縛る（`thesis` などの文字列は `MAX_BRIEF_CHARS`=2000、配列は `MAX_BRIEF_ITEMS`=100）。brief は全セグメントの translator プロンプトに載るため、用語集と同じ増幅経路になる。
- **訳注の脚注を挿してよい位置は「不可視引数の外」**: 保護対象は数式・verbatim・環境名・制御綴りに加えて**参照・パス系コマンドの引数の中身**（`\label` / `\ref` 系 / `\cite` 系 / `\includegraphics` / `\url` / `\input`）。制御綴りそのものしか守らないと、keep-original の英語語がラベル名や図パスと一致したときに引数の内側へ脚注が入り、`\label{fig:overview\footnote{…}}` を生成して組版が落ちる（実測）。**品質ゲートの multiset 検査を通過した後の破壊**なので、ゲートでは捕まえられない。同じ「不可視引数」概念を未訳見出し lint（`visibleText`）も使う。
- **TeX の対区間（数式・環境）の走査は 1 箇所に集約する**（`src/tools/tex-spans.ts`）: 遅延量指定子で区間を拾うと、閉じが無い入力に対して開始位置ごとに末尾まで走査して二次になる。同じ罠を `sanitizeMath` と `stripNonProseEnvs` で個別に直したあと、`protectedMask`（訳注の脚注挿入）と `visibleText`（未訳見出し lint）に手つかずで残っていた（実測 128KiB で 1,079ms / 250KiB で 4,157ms）。入力は translator 出力なので上限は `MAX_RESPONSE_CHARS`（100 万文字）× `maxSegments`。**サイト単位ではなくパターン単位で潰す**。集約した以上、**この走査は TeX の字句規則を知っていなければならない**（1 個のバグが品質ゲートの誤検知と訳注挿入の組版破壊に同時に出る）。3 つを満たす: ①**エスケープ判定**（`\\[2pt]` は行送りの間隔指定であって表示数式の開始ではない。直前のバックスラッシュが奇数個なら区切りでない。実測: `tabular` の `\\[2pt]` があるだけで、数式を原文どおり持ち越した正しい訳が `math` 不一致で落ち、翻訳者には直しようがないので再訳を使い切って exit 3）②**verbatim 先行**（`lstlisting`/`verbatim`/`\verb|…|` の中の生の `$` を区切りと読むと `$` のペアリングが 1 個ずれ、以降の保護が全部ずれる。実測: `echo $HOME` の listing があるだけで後続の `$\mathrm{attention}(Q,K,V)$` の**内側**へ `\footnote` が入り、品質ゲート通過後に組版が落ちた）③**`$` の未閉じは fail-closed**（同じ綴りが開閉を兼ねるので「以降にも無い」が成り立たない。打ち切って素通しにせず末尾までを数式とみなす）。共有入口は `mathSpans(tex, envs)` / `verbatimSpans(tex)`。**④閉じない区切りで打ち切る**（`\verb` 系の区切り探索は、閉じが無ければそこから末尾までを 1 区間として返し**その場で走査をやめる**。続けると候補ごとに `indexOf` が末尾まで走り、さらに末尾までの区間を候補数だけ積んで `maskChars` も候補数×長さになる＝二次。実測: 閉じない `\lstinline{` の羅列 512KB で `mathSpans` 5,545ms、2.2MB で **99 秒・`exit 0`**、8MiB への外挿で約 21 分。打ち切っても結果は同じ＝後続の候補はその区間の内側にある）。**このモジュールは意味論だけでなく計算量も回帰テストで縛る**（集約した二次が新しい実装で戻ってくるのを、意味論テストは検知できない。実際に ④ は集約後に入った回帰だった）。**入力の上限は `MAX_RESPONSE_CHARS` ではない**: `formalCheck` は `mathBodies(srcLatex)` を呼ぶので、原文側は `maxLatexBytes`（既定 8MiB）まで来る。
- **正規表現で読む「1 引数」は長さの上限を書く**（`MAX_INLINE_ARG` 200）: `[^\]]*` / `[^}]*` のように上限を書かないと、閉じない `\includegraphics[` や `\ref{` の羅列で開始位置ごとに末尾まで走査して二次になる。実測: 512KB で `formalCheck` 6,406ms・`untranslatedHeadings` 6,418ms・`injectFootnotes` 20,731ms（1MiB で 89 秒）。ラベル・パス・オプション引数はこれより遥かに短いので、上限で取りこぼさない。**「拒否できている」は可用性の答えにならない**（`too-large` を返す入力でも、返るまでの同期停止は同じだけ起きる）。上限を入れた後の実測: 8MiB で `formalCheck` 496ms、1MiB で `injectFootnotes` 91ms。
- **同期領域には `timeoutMs` も `AbortSignal` も配送されない（一般則）**: 取り込み・安全検査・用語候補収集・品質ゲートは `async` の中にあるが中身は完全同期なので、**期限は同期区間に割り込めない**。個別の対策（下の各項）は「1 回の同期区間を短くする」ことしかできず、ゼロにはできない。運用条件として次を前提にする。①**現状の最悪値**（実測・上限内の敵対的入力 1 本、7.5〜7.7MiB・gzip 数十 KB）: `translatePaper` 1 本の全経過が **949ms**（この間タイマーの発火 0＝完全同期）。個別の同期区間の最悪は約 1.6 秒。`timeoutMs` を指定しても同期区間には割り込めない（`kind="timeout"` / exit 6 の分類自体は正しい）。（issue #154。修正前は 2.5 時間／205 秒／94 秒だったので桁違いに改善しているが、ゼロではない。）②停止時間は `maxLatexBytes`（既定 8MiB）にほぼ比例するので、**プラン別上限が唯一の実効的な緩和策**。③**取り込みは worker 化しない**（[有界時間 ADR](../adr/20261013-keep-ingest-synchronous-with-bounded-time.md)）。今の Web アプリは翻訳ジョブを CLI の子プロセスで動かすので、翻訳ジョブの取り込みは API のイベントループを止めない。API の中で同期に走る処理（用語集の編集の組み直し、論文一覧の全論文の走査、用語集一覧の全論文の走査。用語集一覧は 1 回の一覧で論文ごとにタイトルと取り込みの checkpoint を 1 回だけ読む（issue #375））はその利用者自身の操作で、待たされるのもその利用者だけ。複数の利用者を 1 プロセスで捌く構成に変えるときは、core を worker プール／別プロセスへ逃がす（その時は新しい ADR を足す）。逃がさずに同一プロセスで捌くと、他テナントのリクエストはこの時間だけ待たされる。④本文全体を走る同期パスを足すときは、線形時間の回帰テスト（入力を倍にしたときの時間の比、または 1MiB 規模の入力）を同じ変更に含める。
- **注入クライアントが投げた例外の `message` はそのまま外向きに出る**: `kind="provider"` に写して exit 2 を返す規則（下記）の帰結として、例外の文面が `Result.error.message` に載る（絶対パスの伏字と制御文字の除去は通るが、それ以外は残る）。実測: `401 Unauthorized for tenant key sk-abc` がそのまま載った。**テナントの資格情報を例外の文面に入れないのは呼び出し側の責務**。プロバイダ SDK が鍵をエラーに含める場合は、注入するクライアントの中で包み直すこと。
- **本文全体を走る同期パスの正規表現は量指定子を有界にする**: 攻撃者が制御する文字列に対して終端の無い量指定子（`[^}]+`・`.+?`・`[\s\S]*?`）を使うと、開始位置ごとに末尾まで走査して二次になる。用語候補収集（`src/terminology/collect.ts`）がこれで、実測 512KiB で 35,510ms・上限の 8MiB へ外挿して**約 2.5 時間**の同期停止だった（`checkpoint` は async だが中身は完全同期なので `timeoutMs` も `AbortSignal` も効かない）。**このペイロードは gzip 約 14KB** で、`maxArchiveBytes`・`maxTotalBytes`・`maxEntries`・`maxLatexBytes` のどれにも触れない＝サイズ上限では止まらない。上限は「量」だけでなく「1 文字あたりの計算量」にも要る。候補は `MAX_TERM_CHARS` に切られるので、それを超える長さを探すこと自体が無駄。**有界にしただけでは足りない**: 上限付きでも、遅延量指定子と可変長の空白が隣り合うと開始位置ごとに（長さ × 空白長）の後戻りが起きる（実測: `we refer to` ＋空白 21 の反復 8MiB で 20,354ms。二次ではないが定数が大きい）。中間は「同一文の中」に限り（`[^.\n]`）、隣接する可変長の空白は 1 つに畳む（同 1,482ms＝13.7 倍。正規の言い回しの取りこぼしは無い）。
- **安全検査の走査コストの上限**: 読み込みコマンドの引数は `MAX_ARG_CHARS`（1024 文字）までしか探さず、候補数も `MAX_READ_CANDIDATES`（20,000 件）で抑える。閉じ波括弧を末尾まで探すと、閉じない `\input{` を並べるだけの入力でマッチ数 × 末尾走査 = O(n²) になる（実測 4MiB で 20,040ms、6.3KB のアップロードで 40 秒イベントループ停止）。長さの上限だけでは候補が線形に増えるので件数側にも要る。**支援ファイルは `maxLatexBytes` の対象外**（上限は `maxEntryBytes` だけ）なので、走査対象サイズにも上限（8MiB）を掛け、超えるものは読まずに危険として扱う。**打ち切りは必ず fail-closed**（`MAX_ARG_CHARS` 内で引数が閉じなければ、strict / 支援ファイルの区別なく危険として落とす）。打ち切り時に「引数を読めていない＝無害」と扱うと、引数の先頭を空白で 1024 文字以上詰めるだけで検査を外せる（実測 `\InputIfFileExists{<空白1100>/etc/passwd}` がファイルを読み PDF に出た）。空白詰めは正規の書き方ではないので支援ファイルにも例外を設けない（TeX Live 配布 6,570 件で誤検知の増分 0 件を実測）。`\csname` 側も同型で、本体長 `MAX_CSNAME_BODY_CHARS`（1024 文字）と件数 `MAX_CSNAME_CANDIDATES`（20,000 件）で抑える（正規表現で `\endcsname` を探すと、閉じない `\csname` の羅列でマッチ位置ごとの末尾走査になり実測 1MiB で 144,204ms）。窓の起点は**制御綴り直後の空白を読み飛ばした位置**に置く（TeX のトークナイザと同じ挙動。生の位置から数えると空白 1024 文字で本体を窓外へ押し出せる）。本体が窓内で閉じない場合は、綴りが 1024 文字を超える＝denylist と一致しないので名前照合からは外し、制御綴りを含むなら展開結果が短い綴りになりうるので main.tex では `csname` として落とす。
- **LLM 応答の上限**: 応答は `MAX_RESPONSE_CHARS`（100 万文字）で打ち切る。プロバイダ側（claude の stdout 連結、ollama の本文読み出し）でも同じ上限で受信を止め、超過は provider エラーにする。加えて `extractJson` の候補走査に仕事量の上限を掛ける。閉じない括弧が並ぶ応答は候補ごとに末尾まで再走査するため、長さの上限だけでは二次が消えない（実測: 50 万文字で 25,629ms、`withRetry` の 4 試行で 4 倍。`timeoutMs` は同期処理に割り込めない）。
- **取り込み上限の注入**: `TranslateDeps.limits?: IngestLimits` を `ingest`（アーカイブ展開）と `fetchArxivSource` の両方へ通す。**素の `.tex` とディレクトリ入力にも掛ける**（web で最も普通の入力形態がアップロード済みファイルのパスであり、そこが無検査だとプラン別に締めても素通りする。実測: 40MB の `.tex` で RSS 456MB、拒否前に 42MB の checkpoint 書き込み）。判定は**checkpoint を書く前**に置く（拒否した入力にディスクを使わない）。**`\input` 展開は第 2 の増幅段**なので、展開器自身に予算（累積バイト・展開回数・**解決の試行回数**（後の 2 つは `maxExpansions`＝既定 5000 を共用する別カウンタ）・深さ 32 段）を持たせ、超えた瞬間に `too-large` を投げる。解決の試行を数えないと、不在先への `\input` を並べるだけの入力（展開回数もバイト数も増えない）が素通りする（実測: 3.8MB の羅列が 1,096ms 同期でブロックし、47 バイトを返して成功していた）。`stack.includes` は直接の循環しか止めず、各ファイルが次を 2 回読むダイヤモンド型は指数的に膨らむ（実測: 508 バイトの入力が同期処理でイベントループを 205 秒占有し、`timeoutMs` も中断も一切効かなかった）。LaTeX 本文には図（バイナリ）と別枠の `maxLatexBytes`（既定 8MB）を持たせる。図と同じ上限で見ていたため、40MB の `.tex` が既定で通り 415MB の RSS を使っていた。main.tex 検出は各 `.tex` の**先頭 256KB だけ**を 1 回読み、件数も `maxEntries` で抑える（本文から参照されないファイルは `maxTotalBytes` に数えられないので、全文を読むと上限が効かない）。読んだ前文は**保持しない**（件数ぶんため込むと上限件数で約 2.5GB になり、実測 1,200 件・256MB ヒープで OOM 死した）。**図の解決も増幅段**なので、basename 索引を 1 回だけ作り（参照ごとにツリーを再走査すると O(参照数 × ファイル数)。実測: 100KB の入力で 3 秒、タイマー発火 0）、参照件数自体も `maxFigureRefs`（既定 5000。数えるのはユニークな `(bases, ref)` 組で、同じ参照の羅列は 1 件に畳む）で抑える（索引化しても 1 参照あたり `existsSync` が拡張子ぶん走るため、上限いっぱいの入力が 6.4 秒残る）。`\graphicspath` は重複を落として実在ディレクトリだけに絞り、件数を 64 で抑え、図の解決で叩く `existsSync` の総回数にも上限（20 万回）を掛ける（**`\graphicspath` の宣言ごとの実在確認も同じ予算に計上する**。ディレクトリ数を 64 で抑えても、宣言そのものは `maxLatexBytes` まで並べられる。実測: 8MiB の入力で `existsSync` 92 万回・1,081ms）。参照件数だけでは 1 参照あたりのコストが bases に比例して伸びる（実測: 4,000 dirs × 1,000 refs の 39KiB 入力で 36,769ms、タイマー発火 0）。**memo キーは base 列を世代番号で代表する**（参照ごとに `bases` を直列化すると、`\graphicspath` 1 本あたりの文字列長に上限が無いぶん二次になる。`"./"` の繰り返しは既存ディレクトリへ解決するので実在確認を通り、文字列としては相異なるので重複排除も効かない。実測 8MiB で 94,071ms）。**「回数の上限」を入れても「1 回あたりのコスト」に上限が無ければ意味が無い**、が反復して現れる教訓。既定は `DEFAULT_LIMITS`。web ではプラン別に締められる。
- **中断（`AbortSignal`）**: `TranslateOptions.signal` を受け、LLM 呼び出し・全文組版・arXiv 取得へ伝播する。中断は `kind="canceled"`（期限超過だけ `kind="timeout"`）/ **終了コード 6** で返し、リトライ対象にしない（`isTransient` は false）。単一終了コード決定規則では `6` を最優先にする（中断された run の中で起きた他の失敗より、中断された事実のほうが呼び出し側に必要）。伝播は境界 1 箇所（`withSignal` による `LlmClient` のラッパ）で行い、エージェントの関数シグネチャは増やさない。組版は中断時にプロセスグループごと `SIGKILL`（タイムアウトと同じ扱い）。実装の正本は `src/runtime/cancellation.ts`。
- **arXiv 取得の待ち行列の上限**: 3 秒間隔（本節「arXiv ID 取得」）は予約方式で直列化するため、同時要求が増えるほど後発の待ち時間が線形に伸びる。予約時点で待ち時間が `maxQueueWaitMs`（既定 30 秒）を超えるなら**待たずに `kind="busy"` で失敗**させ、自分のぶんで待ち行列をさらに伸ばさない。待機中に中断・失敗したら**予約を巻き戻す**（返さないと、接続してすぐ切るだけで＝fetch を 1 度も起こさずに待ち行列を伸ばし、他の全リクエストを拒否させられる）。
- **run 全体の期限（`TranslateOptions.timeoutMs`）と枠の解放**: 期限は run 層で 1 度だけ用意し、呼び出し側の `signal` と OR で合流させる（web ハンドラごとに `setTimeout` を書かせない）。超過は中断と同じ exit 6 で返るが、`kind` は `timeout` に分ける（web が 504 と 499 を出し分けられるように）。**期限の印は内部タイマーだけが付ける**（呼び出し側が渡す `reason` は信用しない。信用すると、client 由来の値で切断が期限超過に化ける）。**不正な `timeoutMs`（`NaN`・`Infinity`・0 以下・文字列）は黙って「期限なし」にせず `input` で拒否する**（無期限に化けた run が枠を握ると他テナントを止める）。`2^31-1` を超える値はクランプする（`setTimeout` が 1ms に丸め、指定した瞬間に abort されるため）。あわせて、**中断されたら下位の呼び出しが決着しなくても中断ラッパから抜ける**。注入クライアントは任意の実装であり、契約は `signal` の尊重を強制できない。await し続けると同時実行ゲートの枠が返らず、実測で `active=1 / waiting=1` のまま恒久的に 1 枠失われた（リクエストを重ねれば全テナントが停止する）。漏れた呼び出し自体は止められないので、**枠だけ返し、遅れて来る rejection は握り潰す**。abort listener は決着時に必ず外す。実装の正本は `src/runtime/cancellation.ts`。
- **1 run の仕事量の上限（`TranslateDeps.work?: Partial<WorkLimits>`）**: `IngestLimits` はバイト数とエントリ数しか見ないため、**サイズ上限を全て満たしたまま呼び出し回数だけが爆発する入力**（節を大量に含む小さな `.tex`）を止められない。実測で 49KiB の入力から 1601 回の呼び出しが出た。`maxSegments`（既定 150）はセグメント化直後に判定し、節ループを 1 本も回さずに `too-large` で落とす（超過が確定した入力に課金しない）。`maxLlmCalls`（既定 600）は run 内の全 LLM 呼び出しをラッパで数え、超過分は下位クライアントへ届けない。**リトライ・再訳・評価も 1 回として数える**（課金されるのは試行回数）。既定値は実論文（arXiv 2203.06060、本文 109KiB＝35 セグメント / 96 呼び出し）の 4 倍前後に置く。同時実行ゲート（前項）は同時数を抑えるだけで総量を抑えないため、両方要る。**設定値は個別に検査し、不正値で黙って緩めない**: 明示的な `undefined`・`NaN`・`Infinity`・0 以下・数値以外は既定へ戻し、過大な値は上限の上限（`WORK_LIMIT_CAPS`）で切る（spread マージだと `work: { maxSegments: plan.maxSegments }` の 1 行で上限が丸ごと消え、実測で 801 回の呼び出しが素通りした）。実装の正本は `src/runtime/work-budget.ts`。
- **引用・参照・脚注を照合する（`kind: "reference"`）**: `\includegraphics` と `\label` は見ていたのに、**引用・参照・脚注・URL は見ていなかった**。落ちても組版は成功するので、本文が黙って PDF から減る。実測（2203.06060）——local 訳は `\footnote` を 1 つ落とし、`\citep`/`\citet` を `\cite` へ書き換えて（9→5・3→0・0→7）**引用を 5 つ純減**させた。natbib では `\citet{a}` が「Smith (2019)」、`\cite{a}` は「(Smith 2019)」に組まれるので、綴りが変わるだけで日本語として不自然な組版になる。対象は cite 族・`\footnote` / `\footnotemark` / `\url` / `\href` と参照族（`\ref` `\autoref` `\eqref` `\cref` `\Cref` `\pageref` `\nameref`）で、**綴りごとに個数一致**を要求する（族の合計ではなく綴り単位。合計だと `\citet`→`\cite` の化けが素通りする）。**強調系（`\textit` / `\emph` / `\textbf` / `\textsuperscript`）は対象にしない**——claude 訳自身が `\textit` を 6 個・`\textsuperscript` を 1 個落としており、対象にすると参照実装が不合格になる。強調の付け外しは訳し方の選択で、組版も内容も壊さない。**見出し・`\item` / `\caption` も当面は対象にしない**（両 run で差が 0 ＝失敗の実績が無く、既存の fixture を大量に壊すだけ）。差し戻し文には綴りごとの個数を書く（`\citep src=3 ja=0 / \cite src=0 ja=3`）。この規則で claude 訳 36 節の誤検出は 0、local 訳では 3 節の実欠陥を検出した。
- **保護区間の要否はモデルの能力で測って決める**（正本は `src/workflows/section-loop.ts` の `PROTECT_SPANS`、切り替えは 1 行）: 数式とエスケープ済み特殊文字を `〔n〕` へ差し替えて translator へ渡すか否かは、**設計で決めるものではなくモデルごとに測るもの**（[保護の要否はモデルの能力で決まる ADR](../adr/20260816-protection-depends-on-model-capability.md)）。同じ設定が両方のモデルで正しいということはない——実測で真逆になった。

- **エスケープした特殊文字も保護区間に含める**: `\%` `\&` `\#` `\$` `\_` `\{` `\}` は訳す対象ではないので、数式と同じく翻訳前に `〔n〕` へ差し替える（[エスケープ特殊文字保護 ADR](../adr/20260815-protect-escaped-specials-too.md)）。**`\\`（行終端）は含めない**（位置が意味を持ち、セル本文は翻訳対象）。数式区間・verbatim 区間の中は対象外。印の番号は数式と混ぜて原文の出現順に振る。検査（`symbol-command`）は残す——保護は「落とさせない」ためのもので、モデルが新たに生の `%` を持ち込む経路は塞げない。**保護の範囲は checkpoint の無効化キーに入らない**（キーは原文・用語スライス・brief・style）ので、進行中の run の checkpoint を無効化せずに変えられる。
- **本文中の著者・所属・注記は訳さず原文のまま残す**（[著者・所属を原文のまま残す ADR](../adr/20261008-keep-author-block-untranslated.md)・[前付けの型の表 ADR](../adr/20261011-drive-frontmatter-by-template-profile-table.md)）: 前付けの型の表（`src/tools/frontmatter.ts` の `keptSpans`。全型共通）が挙げる命令（`\author`・`\affil`・`\affiliation`・`\institute`・`\address`・`\email`・`\thanks`・`\fntext`・`\cortext`・`\icmlauthor`・`\icmlaffiliation` など。必須引数の数は命令ごと）と環境（`icmlauthorlist`・`affiliations`）を、命令全体（任意引数・入れ子の波括弧を含む。任意引数は `MAX_OPTIONAL_ARG` 1000 文字までに閉じたものだけ読み、超えたら伏せずに訳文側へ回す。2 つ目以降の必須引数が無ければ読めたところまで。正本は `src/tools/tex-spans.ts` の `commandSpans`）または環境全体の区間にする。区間が重なれば外側だけを使い、keep（本文の `\title`）の中のものは除く。区間は分割の段階で節ごとに決めて `Segment.frozen` に持たせる（`planSegments`。分割を経ない節は既定の型で決める）。キーワード（`\keywords`・`keyword` 環境）と PNAS の significance statement は訳すので入れない。この区間を、`\title` の keep（§8）と同じく丸ごと 1 つの印で伏せて translator へ渡し、原文のまま復元する（`protectMath({ frozen })`。中の数式・記号の区間は二重に伏せない。`PROTECT_SPANS` を切っても伏せる）。印の欠落・重複は形式検査 `author` として名指しで差し戻す。復元した区間は形式検査・evaluator へ渡す原文・訳文の両方から、空白 1 つに置き換えて取り除く（`\title` の keep も同じ。詰めると `\fi\author{A}and` が `\fiand` になり、前後の綴りがつながって数え違える）。`\authorrunning` など英字が続く命令は対象外。checkpoint の無効化キーには入れない（既に訳した節の著者表記は次に訳し直すまで残る）。伏せた区間の用語は節の用語に数えない（§1。`translatedLatex` は `Segment.frozen` を使う）。
- **条件分岐の個数を照合する**（形式検査 `conditional`）: 原文と訳文で `\if…`（素の `\if` と、`\if` に英字・`@` が続く綴り。`\ifthenelse`・`\iff` も含む。数式を復元してから両側を数えるので `\iff` は両側で同数になる）と `\fi` の個数が違えば改稿へ回す（汚染ではないので即失敗にはしない）。節の端に単独で残った `\if…` / `\fi` をモデルが落とすと、組版で `Extra \fi` 等になり、原因でない節に帰属するため（#332）。
- **記号だけの制御綴りを照合する（`kind: "symbol-command"`）**: `usedCommands` は `\[a-zA-Z]+` で綴りを拾うので、`\\` や `\%` のような**記号だけの綴りはどの検査にも掛かっていなかった**。`structure`（汚染扱いで再訳しない）とは分けて独立の種別にする。照合は**壊れ方に合わせて非対称**にし、正しい訳に再訳を課さない（ローカルモデルでは再訳 1 回が 300 秒超）。
  - **個数一致を要求する**: 行終端 `\\` だけ。`\` に縮むと表の行構造が壊れ、形式検査は通るのに組版が Fatal error で落ちる（実測: seg-0004 で 15 個すべてが消え `Misplaced \noalign`、PDF が出なかった。同じ論文で claude 側は 62 個すべて保持）。
  - **増加だけを落とす**: 数式区切り `\(` `\)` `\[` `\]` と、**エスケープされていない生の `%` `#` `$`**。訳文が原文より多く持つと組版が落ちるか本文が黙って消える。実測 2 件——ローカル seg-0007 が原文に無い `\)` を 3 個作り `Bad math environment delimiter`、**claude 訳 seg-0014 が `50\%` を `50%` にして段落の残りがコメント化し、ビルドは成功したまま本文が PDF から消えていた**（`pdftotext` で当該文が 0 件）。後者は provider 共通の欠陥で、ビルド成功を根拠にした検査では捕まらない。
  - **減少は落とさない**: `\&` `\_` `\{` `\}` `\#` などが訳文から消えるのは正しい訳であることが多い（実測: 原文 `review \& editing` を「査読・編集」と訳した節が `\&` を 13 個落とす）。個数一致を課すと、この訳に再訳を課すだけで組版は 1 mm も良くならない。危険なのは「消える」ではなく「エスケープが外れて生の特殊文字になる」ほうなので、上の増加検査がその形だけを捕まえる。
  - 生の特殊文字は**コメント除去前の本文で数える**（`stripLineComments` が `%` 自身を剥がしてしまうため）。
  - 保護区間の対象にはしない（`\\` は位置が意味を持ち、セル本文は翻訳対象なので表ごと伏せると訳せなくなる）。
- **数式の指摘は差分を添える**: 数式が合わないときの `FormalIssue.message` には、**欠けた式・増えた式を実際に列挙する**（正本は `src/workflows/quality-gate.ts` の `describeMathDiff`）。件数だけを返すと、差し戻された側は全部を見直すしかない（実測: ローカルの 12B は改稿上限 4 回を使い切っても直せず、落ちた 4 セグメントすべてが `math` だった）。列挙は 3 件・1 件 60 文字までで、残りは件数で示す（プロンプトを膨らませない）。この文字列は user プロンプトへ戻るだけで、**外向き出力には出さない**（原文由来の文字列だが、原文自体が同じプロンプトに既に載っているので新たな露出は生まない）。
- **失敗の列挙は `failCode` で分ける**: 終了コードは優先順位で 1 つに決まる（3 > 4）が、**報告からもう一方を消してはいけない**。`!passed` だけで並べると品質で落ちた節が「形式検査を通過しない」の一覧に混ざり、運用者は存在しない形式的欠陥を探すことになる（実測: `seg-0019` が種別なしで形式の一覧に並んだが、実際は改稿上限に達した品質の失敗だった）。形式・品質の両方が起きた run では、選ばれなかった側も同じメッセージに添える。`failCode` を持たない古い checkpoint 由来の結果は形式側に倒す。
- **形式検査の失敗は種別付きで返す**: `formal`（exit 3）のメッセージは `seg-0005(math, paragraph)` のように**落ちた検査の種別を添える**。種別は固定語彙なので外向きに出しても論文由来の文字列は混ざらない。ID だけだと手掛かりが 1 つも残らない（失敗した訳文は `chapters/` へ書き出さず、失敗結果は checkpoint にも永続しないため。実測: ローカルモデルで 8 本落ちたが、数式・未翻訳・段落数のどれで落ちたのか分からず次の手が決められなかった）。`FormalIssue.message` 本文の露出は別問題（論文由来の文字列が混ざるため検疫の設計が要る）。
- **汚染は品質の失敗と区別できるように返す**: `unsafe-command` / `structure` は「直せる誤りではなく汚染の兆候」として再訳せず落とすのに、返るのは他の形式エラーと同じ `failCode: 3` で、`FormalIssue.message` はどこにも出力されていなかった（`warnIssues` は失敗時 `[]`）。運用者はプロンプトインジェクション／モデル汚染が起きたことを知る手段が無い。落ちた検査の種別を `SectionLoopResult.failedKinds` で返し、汚染系が 1 つでもあれば `Result.error.message` を専用の文面にし、**exit code が他の失敗に持っていかれても警告（`notify`）で必ず観測できる**ようにする。あわせて**落ちたセグメントの訳文は `translation/chapters/` へ書き出さない**（run は exit 3 で失敗しても、成果物ディレクトリに `\write18{...}` 入りの `.tex` が残り、利用者が手で組版すれば発火した）。
- **`paperId` の規則は入力の種別によらず 1 つ**（[単射 ADR](../adr/20260811-paper-id-must-be-injective.md)）: サニタイズで名前が変わったら元名のダイジェストを付ける。**ダイジェストを条件付きで付ける規則は、ダイジェスト付きの形自体が不動点になる**ので、既に `-<8桁hex>` で終わる名前は変換不要でもダイジェストを付け直す（攻撃者は出力名を直接付けられる。実測: `a b.tex`→`a_b-c8687a08` と `a_b-c8687a08.tex` が衝突、`hep-th/9901001`→`hep-th_9901001-e87280ea` と同名の `.tar.gz` が分岐を跨いで衝突）。arXiv 分岐だけ `/`→`_` に潰していた頃は、`math/0309136` と `math_0309136` が同じ出力先・同じ `.run/steps`・同じ `run.lock` へ写る規則だった。**arXiv ID の形式検査は `derivePaperId` の入口＝副作用より前**に置く（`fetchArxivSource` の中に置くと、出力先の決定と run lock の `mkdir` の後になる。呼び出し側は `JpaperInput` を自前で組めるので、実測で検証前に制御文字入りのディレクトリが cwd 直下に作られ、`RunSummary.paperId` にも生のまま載った）。
- **本文が空になる入力は成功にしない**: 完了判定の `failed === 0` はセグメント 0 件でも真になる。`\input` の解決失敗は黙って空文字列に置換されるため、本文を別ファイルに持つ論文の同梱漏れで本文が丸ごと消え、**空の PDF が exit 0 の「成功」として返り glossary 1 回ぶんだけ課金された**（実測: `segments: 0/0/0` / `buildOk: true` / `llmCalls: 1` / `exitCode: 0`、警告なし）。セグメント 0 件は `kind="input"`（exit 2）で拒否し、判定は `maxSegments` と同じく LLM を 1 回も呼ぶ前に置く。あわせて**解決できなかった `\input` / `\include` の件数を `Ingested.unresolvedInputs` で返し、0 でなければ警告する**（本文が残っていても一部は欠けている。黙って空にする挙動が本文消失の直接の原因だった）。
- **checkpoint の無効化キーは入力の内容を代表しなければならない**: `ingest` の `invalidation` を `(path, mtimeMs, size)` にしていた頃は、同一パス・同一サイズ・秒単位で同じ mtime の別論文が同じ入力とみなされ、**論文 B を投げた利用者に論文 A の訳文が exit 0 で返った**（LLM 呼び出し 0 回・`paperId` もファイル名 stem 由来なので `.paper-id` の印も発動しない）。`tar -x` / `cp -p` / `rsync -t` / `docker cp` は mtime を復元するので、アップロードを固定パスへ展開する web パイプラインではこれが常態になる。署名（HMAC）の破綻ではなく**署名対象が内容を代表していない**設計の穴なので、`inputSignature` は内容の sha256 を使う（ディレクトリ入力は相対パスと内容の畳み込み）。走査は上限（512MB・10,000 エントリ）で抑え、超える入力は取り込み側が `too-large` で落とすため部分ハッシュのままでよい。**`arxiv` 分岐は ID のみのハッシュなので、版を省いた ID（`2203.06060`）で論文が改訂されると旧 checkpoint を再利用する**（既知の残存リスク）。
- **取り込みの checkpoint のパス**（issue #447。正本は `src/workflows/step-keys.ts` の `rebaseIngest`）: 取り込みの checkpoint は `sourceDir`・`mainDir`・`figures` を書いたときの絶対パスで持つ。出力先を改名・移動すると、checkpoint は当たったまま古い場所を指し、図が見つからない・組版が落ちる・古い場所に残ったファイルを黙って使う。そこで、取り込みが今の出力先の `.run/source`・`.run/pdf-source` へ展開する入力（arXiv・アーカイブ・PDF と、伏せ字の指定でソースを `.run/source` へ写す入力。translatePaper の `ingestsIntoRunDir`）と用語集の編集（§9。arXiv の入力だけ）に限り、読んだ値の `sourceDir` が別の出力先の `.run/source`・`.run/pdf-source` 配下を指していれば、その配下にあるパスを今の出力先の同じ配下へ付け替えて使う。保存済みの checkpoint は書き換えない（署名も無効化キーもそのまま。既存の出力先も取り込み直さずに効く）。付け替えるのは旧い `.run/source`・`.run/pdf-source` の中に収まるパスだけで、付け替えた先は今の `.run/source`・`.run/pdf-source` の外を指さない。ディレクトリ・素の `.tex` の入力（伏せ字の指定なし）は、ソースを入力の場所から直接読むので付け替えない。ほかの出力先の `.run/source` をディレクトリ入力として訳すと、保存値はその場所を指す。付け替えると、本文はその論文なのに図や `.sty` は今の出力先に残った別論文のものになる（新しく取り込んだ直後の run でも起きる）。旧い配下に収まらないパスと、今の出力先に付け替え先の `sourceDir` が無いときも、保存された値をそのまま使う。
- **`.run` の保持ポリシー**: checkpoint のファイル名は `<stepId>.<無効化ハッシュ>.json` なので、論文を直して再投入するたびに旧世代が残る（実測: 8 世代で 228KB→1208KB と線形に増加）。**新しい世代を書いたら同じ step の旧世代を削除する**。GC は最善努力で、失敗しても run は続行する（増えるだけ）。セグメント数が減った再投入では使われなくなった `seg-*` が残りうるが、`maxSegments` で件数は有界。`llm-trace.jsonl` は 1 ファイル 5MB で 1 世代だけ退避する（合計は `2×maxBytes + 1 行`で有界。ローテ直後の 1 行は無条件に書く）。**上限が効くのは既定シンクだけで、`TranslateDeps.trace` を注入した場合の保持は呼び出し側の責務**。判定は**実ファイルのサイズ**で行う（シンクごとのカウンタだと、同じファイルへ複数のシンクを向けた瞬間に上限が壊れる）。集計ツールは退避ファイル（`.1`）も読む。checkpoint だけ GC しても、トレースが増え続ければ `.run` は線形に増える。旧世代を消す以上、**入力を A→B→A と往復させると A は再計算＝再課金になる**（世代を残さないこととのトレードオフ）。`.run` 全体の寿命（run 完了後にいつ消すか）は呼び出し側の責務。 加えて、run が正常に完了した時点で**今回使わなかった stepId の checkpoint を消す**。旧世代 GC は同じ stepId しか見ないため、節が減る再実行では孤児が残り続ける（実測: 8 節→1 節に縮小しても 10 ファイル 4.2MB のまま、うち 7 件が前回の訳文）。paperId が衝突すると、これがそのまま別論文の内容の残留経路になる。
- **観測（トレース・進捗・呼び出し回数）**: web はテナント別の資格情報のためにクライアントを必ず注入するので、プロバイダ生成側にだけトレースを配線すると**課金の記録が構造的に消える**。`translatePaper` は注入クライアントにも `withTrace` を掛ける（usage/コストは注入側の内部にしか無いので、run 層が残すのは回数・latency・呼び出し文脈）。宛先は `TranslateDeps.trace` で差し替えられる（既定は `<outDir>/.run/llm-trace.jsonl`）。`RunSummary.llmCalls` に実際に発行した回数を載せる（**失敗した run でも返す**＝どこまで課金相当の仕事をしたか）。**通知チャネル（`onError` / `onProgress`）とトレース（`TraceSink`）の例外は run を壊さない**。web の SSE 切断・宛先のディスクフルなどで投げても結果を変えず、外へも出さない（§8 の「例外は投げず戻り値で表現」）。トレースを保護しないと、観測チャネルの故障が **`kind="provider"` の run 失敗**として報告され、運用者は LLM ベンダを疑う（実測: `trace` が投げると `llmCalls=1` で exit 2）。**`TranslateDeps.gate` にプロセスゲートそのもの（`llmGate()`）を渡しても二重に掛けない**（ゲートは非再入。外側で取った枠を内側で待って自己デッドロックする。実測: limit 1 のプロセスゲートを渡すと全 run が「LLM 同時実行の待機」で期限切れ、`timeoutMs` 未指定なら永久ハング）。`onError` も `outwardMessage` を通す。進捗は `TranslateDeps.onProgress`（`ingest`/`context`/`translate`/`typeset` と `done/total`）で通知する。
- **落ちた節の指摘**（issue #333・[ADR 20261012](../adr/20261012-keep-last-issues-of-failed-segments.md)）: 落ちた節（タイトルの節を含む）ごとに、最後の稿に付いた指摘を `<outDir>/.run/failed-segments.json` へ書く。形は `{ runId, createdAt, segments: [{ segmentId, failCode, failedKinds, usedRevisions, maxRevisions, lastIssues }] }`（`runId` は LLM トレースの `runId` と同じ）。`lastIssues` は品質で落ちた節なら `{ by: "evaluator", verdict, issues }`（最後の evaluator 応答）、形式で落ちた節なら `{ by: "formal", issues: [{ kind, message }], marks }`（`marks` は落とした・重ねた差し替え記号の名指し）。落ちた節が無い run は前の run のファイルを消す。**例外で中断した run は書きも消しもしない**（前の run の記録が残る。どの run のものかは `runId` で見分ける）。品質・形式・汚染の失敗の `RunError.message` と、タイトルが節ループで落ちたときの警告に置き場（`.run/failed-segments.json`）を添える。書き出しに失敗しても run の結果は変えず、警告だけ出す。落ちた節は checkpoint に永続しないので、これが無いと失敗の原因を事後に確かめられない（evaluator の指摘は再訳の入力にしか使われず、捨てられていた）。中身は論文由来の文字列を含むので、外向きの `RunError`・進捗・LLM トレースには載せず、出力先の中だけに置く（`notes.json` が evaluator の `warn` の文面を持つのと同じ扱い）。契約に合わない生応答の保存（`JPAPER_DUMP_RAW` による opt-in）とは別で、こちらは既定で書く。
- **形式検査の版**（issue #254・[ADR 20261013](../adr/20261013-recheck-passed-segments-when-formal-check-changes.md)、正本は `src/workflows/quality-gate.ts` の `FORMAL_GATE` と `src/workflows/translate-paper.ts` の `recheckCached`）: 通った節（タイトル節を含む）の checkpoint に、印のままの訳文（`marked`。数式・保護区間を `〔n〕` に差し替えたままの translator の出力）と、通した形式検査の版（`gate` = `FORMAL_CHECK_VERSION` と検査の種別の一覧）を残す。checkpoint から読んだ節の `gate` が今の版と違えば、LLM を呼ばずに `marked` を今の形式検査にかけ直す（節ループと同じ関数）。通れば `gate` を書き換えて使い、落ちればその節だけを訳し直して知らせる。`marked` から復元した訳文が checkpoint の `ja` と一致しなければ再検査せずにそのまま使う（保護の規則を変えて印の番号がずれた場合など）。節の checkpoint は `marked` のぶん約 2 倍の大きさになる。版は checkpoint の無効化キーに入れない（入れると検査を変えるたびに全節を訳し直すことになる）。`FORMAL_CHECK_VERSION` は検査の規則（閾値・対象の一覧・判定）を変えたら上げる。種別を足したときは一覧が変わるので、上げ忘れても拾える。**保証の範囲**: `marked` を持つ checkpoint（この変更以降に通した節）だけを再検査する。それ以前の checkpoint は今までどおりそのまま使う（訳し直したければ出力先を変える）。evaluator の判定はやり直さない（LLM が要る）。用語集の編集（§9）は `ja` と同じ置換を `marked` にもかけ、版が違い今の検査に通らない節があれば、組み直しの前に「節 X は今の形式検査に通りません。CLI で再実行してから編集してください」の入力エラーで止める（組み直しの中で訳し直しに入ると LLM が要るため）。
- **進捗には節ごとの合否を載せる**: translate フェーズのセグメント完了イベントに `passed` / `failedKinds` / `usedRevisions` / `maxRevisions` を添える。**落ちたセグメントは checkpoint に永続しない**（本節）ので、載せないと「どれが落ちたか」を実行中に知る手段が存在しない（実測: ローカルモデルで 1 本 2〜3 時間かかる run で、`.run/steps/` に checkpoint が無いセグメントを数えて逆算するしかなかった。落ちた検査の種別は最後まで分からない）。載せるのは `FormalIssue["kind"]` の固定語彙・生成された ID・回数だけで、**`FormalIssue.message` 本文は載せない**（論文由来の文字列が混ざる）。`failedKinds` が空の失敗は品質（evaluator）の失敗を意味する。`SectionLoopCache` の `failedKinds` は `string[]` のままにする（種別を足した版が書いた checkpoint を、古い版が読めなくならないように）。CLI はこれを 1 イベント 1 行の平文で stderr へ出す（正本は `src/cli.ts` の `formatProgress`。ANSI は使わない＝ログへリダイレクトしても読める）。
- **入口の検証**: `translatePaper` は `JpaperInput` / `provider` / `concurrency` / `outDir` を入口で検証し、不正なら `kind="input"` の `Result` を返す。**生の例外を web ハンドラへ漏らさない**（`{ kind: "path", path: undefined }` で `TypeError` が漏れていた）。未知の provider を既定へフォールバックさせない（`"openai"` が claude 扱いで通り、コンテキスト窓だけ Ollama のものになっていた）。
- **失敗の構造化（`Result.error`）**: `Result` に `error?: { kind, code, message, detail? }` を持たせる。`status="failed"` のとき必ず入る。`kind` は `input`（入力が不正）/ `conflict`（出力先が使用中＝run lock）/ `too-large`（サイズ・件数の上限超過）/ `busy`（一時的な過負荷。後で再試行できる＝arXiv の待ち行列超過など）/ `upstream`（外部サービス側の障害＝arXiv 到達不能・リトライ枯渇）/ `provider`（LLM プロバイダ利用不能。**注入クライアントが投げた例外もここに写す**＝テナントの 401 が 500 にならないように）/ `formal`（形式検査不通過）/ `quality`（品質未達）/ `typeset`（全文組版失敗）/ `canceled`（呼び出し側の中断＝切断）/ `timeout`（run 全体の期限超過。web が 504 と 499 を出し分けられるように分ける）/ `infra`（実行環境の障害＝権限・容量・パス衝突。コードのバグと区別してアラートするため）/ `internal`（想定外）。`code` は §6 の終了コードで、`kind` はそれを細分する軸（`code=2` が `input`/`conflict`/`too-large`/`busy`/`upstream`/`provider` に分かれる）。`detail` には `internal` のスタックのほか、`upstream`・`infra`・`JpaperError` の伏せる前の原文も入る。**`detail` はサーバ側のログ用であり、web - **出力先の排他（run lock）**: checkpoint は `<outDir>/.run` 単位で共有されるため、同一 `outDir` の並行実行は互いの訳文・用語文脈を混ぜたまま**両方が成功を返す**。`translatePaper` は開始時に `<outDir>/.run/run.lock` を原子的に取得し（方法は後述の「一時ファイルへ書き切ってから `link`」）、取得できなければ**終了コード 2**（入力エラー）で明示的に失敗する。ロックは `pid` / `startedAt` / `beatAt` を持ち、**保持者が生きている間 `beatAt` を更新し続ける**（`HEARTBEAT_MS` 30 秒）。更新が `LOCK_STALE_MS`（120 秒）途切れ、かつ保持プロセスが存在しないときだけ失効として奪う。pid の生存判定は `ESRCH` のときだけ「死亡」とする（`EPERM` は「存在するが権限が無い」＝生存の証拠。コンテナの pid 1 や別ユーザ実行で生きたロックを奪わないため）。ロックの作成は「一時ファイルへ書き切ってから `link`」で行う（原子的な排他と、常に完全な内容が読めることを同時に満たす。`open("wx")` は作成と書き込みの間に空ファイルを読まれ失効と誤判定される）。失効ロックの削除は補助ロック `run.lock.steal` で直列化する（直列化しないと複数プロセスが互いの新しいロックを消し合い、全員が保持者を自認する）。取得に失敗した側は必ず `kind="conflict"` で返し、生の fs エラーを外へ出さない（**削除・release も含めて**。実測: `run.lock` の位置がディレクトリだと `rmSync` の `ERR_FS_EISDIR` が exit 1 / `internal` で素通りした。node:fs は errno ではなく独自コードでも投げるので、infra 判定はそれも拾う）。**ロックの中身は型を検査する**: `beatAt` が数値でないと `now - beatAt` が `NaN` になり `NaN > staleMs` は常に false ＝**決して失効しない**（生きた pid と組み合わせれば恒久ロック。実測: pid 1 と壊れた `beatAt` で 100 年後も `conflict`）。未来の `beatAt` も同じ理由で失効扱いにする（NTP の巻き戻し・共有 FS のクロックずれ）。実装の正本は `src/durable/run-lock.ts`。web ハンドラから呼ぶ場合、同時リクエストは outDir を分けるか、この失敗を 409 相当として扱う。**ロックは「入口」だけでなく「書き手の寿命」も覆う**: `translatePaper` が返るまでに、その run が起動した書き手（セグメント翻訳の worker）は全て決着していなければならない。セグメント翻訳は `Promise.all` ではなく**全 worker を join してから最初の失敗を投げる**（1 本の失敗で即座に投げると、残りの worker が返却後も `checkpoint()` を書き続ける「亡霊」になる。実測: `seg-0000` を provider エラーで落とした run が返り、`finally` でロックを解放した 700ms 後に、既にロックを取得していた別 run の `.run/steps` へ `seg-0001`/`seg-0002` を上書きし、**成功（exit 0）を返した側の成果物に失敗した run の訳文が 1 節ぶん混入した**。以後の再実行は checkpoint 命中でその訳文を復元する）。中断（`signal`）では下位が即座に落ちるので join は待たない。
- **単一終了コード決定規則**（1 run で複数原因が混在時）: `6`（中断・期限超過）> `2`（入力/プロバイダ）> `3`（形式失敗）> `4`（品質失敗）> `5`（全文ゲート=(B)）> `1`（想定外）の優先順位で 1 つに決める。`6` を先頭に置くのは、中断された run の部分的な失敗を「翻訳の失敗」として報告しないため。`1` を最後尾に置くのは、内部バグを組版失敗の陰に隠さないため。実装の正本は `resolveExitCode`（`src/types/errors.ts`）。

## 9. 用語集の編集・論文の検索と翻訳（Web アプリ）

[用語集 Web アプリ ADR](../adr/20261007-glossary-web-app-replace-and-retypeset-without-llm.md)・[検索と翻訳ジョブ ADR](../adr/20261008-web-app-arxiv-search-and-translate-job-queue.md)。実装の正本は `src/terminology/replace.ts`（置換）・`src/terminology/replace-preview.ts`（確認画面の断片）・`src/workflows/glossary-edit.ts`（計画・適用・元に戻す）・`src/workflows/step-keys.ts`（無効化キー）・`apps/web/`（API と画面）。

- **編集の単位**: 1 回の適用で 1 語の**訳語だけ**を直す（表記方針・分類は変えない）。`keep-original` の語は訳語を持たないので編集できない。入力は空・`|`・改行・`\ { } $ % & # ^ _ ~` を拒む。`bilingual` の新しい form は `訳(src)`（原語は `src` の綴り。入力に併記があれば落として付け直す。§1 の併記形の正規化と同じ）、`translate` は訳だけ。
- **置換の対象と規則**: 訳文に現れる訳語（`bilingual` は form の日本語部分、`translate` は form）を、文字列の一致でそのまま新しい訳語へ置き換える。併記形の初出「訳(原語)」は日本語部分の置換で「新しい訳(原語)」になる。**ほかの語の訳語が直す訳語を含む**場合（「ラショモン集合」に対する「経験的ラショモン集合」）、その語の訳語の出現範囲に収まる出現は置換せず、確認画面で印を付ける（その語は別の行として残す）。同じ訳語を持つ別の語は確認画面で知らせ、出現は置き換える。書き換える場所: 節・タイトルの checkpoint の訳文と評価の訳注（`warnIssues`）、`glossary.md`（対象の行の form と、全行の訳注の列）、`brief.md`・`style.md` の本文（見出し行と style.md の「- キー:」のキーは書き換えない。`parseBriefMd`・`parseStyleMd` が節や項目を探す目印のため）、用語集の checkpoint（対象の語の form・全語の訳注・brief・style）。他の行の form は書き換えない。
- **checkpoint の書き直し**: 節・タイトルの checkpoint は、置換後の訳文を**置換後の glossary.md・brief.md・style.md から translatePaper と同じ関数（`step-keys.ts`）で作った無効化キー**で署名し直して書く（`writeStep`。旧世代は消す）。用語集の checkpoint は無効化キー（本文のハッシュ）を変えずに値だけ署名し直す。取り込みの checkpoint は触らない。署名は既存の鍵（`JPAPER_HOME/cache.key`）で行い、読むときは各 checkpoint のファイル名の無効化キーで署名を検証する（`readStep`。合わないものは無いものとして扱う）。
- **分割の特定**: 節の checkpoint の訳文は原文を持たないので、取り込みの checkpoint の本文を分割し直して節の原文を得る。文脈長の候補（claude・openrouter・ollama の既定と 4096〜1,000,000 の代表値）を順に試し、節の ID の集合が checkpoint と一致する分割を使う（全節の無効化キーが今の版の計算と一致するものを優先）。一致しなければ編集を拒む。
- **別の版が作った checkpoint の引き継ぎ**: 無効化キーが今の版の計算と一致しない checkpoint（作った版の鍵の作り方が違う）は、次の両方を満たすときだけ引き継ぎ、今の版の鍵で署名し直す: (1) `glossary.md`・`brief.md`・`style.md` が用語集の checkpoint の内容（render→parse）と一致する（最後の翻訳のあとに手で編集されていない。手で直して再実行していない語の訳し直しを失わせない）、(2) 節の原文と訳文の形式検査のうち対応を示す種別（数式・図・`\label`・引用参照・文書構造・危険コマンド）が通る。確認画面に引き継ぐことを示す。
- **LLM を使わない再組版**: 書き換えのあと、**呼ばれたら失敗するクライアント**を注入して `translatePaper` を回す（入力は取り込みの checkpoint の鍵と一致する arXiv ID、プロバイダは特定した文脈長の openrouter 設定、対訳あり、トレースは捨てる）。全節が checkpoint から返り、訳文の書き出し・訳注・和訳 PDF・対訳 PDF（§8「成果物 PDF の名前」）まで進む。LLM が 1 回でも呼ばれたら、または run が失敗したら、変更をバックアップから戻して失敗にする。arXiv ID 以外の入力から訳した論文は元の入力が分からないので編集を拒む。タイトルの checkpoint が無い論文も拒む。
- **バックアップ（1 世代）**: 適用ごとに、書き換える前の `glossary.md`・`brief.md`・`style.md`・`notes.json`・`.paper-id`・`.run/steps/`・`translation/chapters|build|bilingual/`・成果物 PDF を `.run/glossary-edit/backup.next/` へ複製し、**組み直し（和訳 PDF と、適用前にあった対訳 PDF）まで成功したときだけ** `backup/` と入れ替える（前回のバックアップは置き換える）。失敗した適用は `backup.next/` から戻し、前回のバックアップは残す。入れ替えるときに、適用した直後の状態の指紋（md・notes・`.paper-id` と訳文の中身、checkpoint のファイル名）を manifest に記録する。元に戻すときに今の状態の指紋が一致しなければ（その後の CLI 実行や手での編集がある）、conflict で拒んで今の状態を残す。一致すれば、これらを今あるものごと消してから複製を戻し、バックアップを消す。**全体の用語 DB への登録は戻さない**。適用前に対訳 PDF があったのに組めなくなった適用は、失敗として戻す。
- **全体の用語 DB**: 組み直しの `translatePaper` は用語集の結果を全体 DB へ書き戻さない（`writeBackGlossary: false`）。「全体の用語 DB にも登録する」を選んだ適用だけが、組み直しに成功したあと `writeBackProposed`（`ja` は新しい form、`source` は paperId）→`promote` で承認済みにする（§2。`isAcceptableTerm` を満たさない語は登録しない）。既に訳したほかの論文で同じ `src`（大文字小文字を区別しない）の訳語が違うものを「影響あり」として返す。用語集の一覧（`GET /api/glossary`）は承認済みの語ごとに「影響あり」を付け、その論文のタイトルは 1 回の一覧の中で論文ごとに 1 回だけ checkpoint から作って使い回す（issue #375。一覧を跨いでは使い回さない）。反映は論文ごとに編集画面から 1 本ずつ行う（一括しない）。
- **排他**: 適用・元に戻すは `.run/glossary-edit/run.lock`（`acquireRunLock`。同じプロセスの 2 本目も conflict）を最後まで持ち、ファイルを書き換える間は `.run/run.lock` も持つ（CLI の run と排他）。組み直しの `translatePaper` は自分で `.run/run.lock` を取る。
- **API と画面**: `pnpm dev:web` が API（Hono、`127.0.0.1:5174`、`JPAPER_WEB_API_PORT`）と画面（Vite、`127.0.0.1:5173`、`JPAPER_WEB_PORT`、`/api` を API へ中継）を一緒に立ち上げる。認証は持たず、`Host` が `127.0.0.1`・`localhost` 以外、`Origin` が画面・API のポートの `http://127.0.0.1:<port>`・`http://localhost:<port>` と完全一致しない要求は 403。POST は `content-type: application/json`（`POST /api/uploads` だけは `application/pdf`）以外を 415 で拒む（別オリジンの単純リクエストを通さない。どちらもプリフライトが要る型）。データの場所は CLI と同じ既定（CWD の `article/` と `JPAPER_HOME/glossary.db`）で、`JPAPER_ARTICLE_DIR`・`JPAPER_GLOSSARY_DB` で変えられる（checkpoint の署名鍵は常に `JPAPER_HOME`）。入力の誤りは 400、排他の衝突は 409。
- **論文の一覧**（`GET /api/papers`、論文の画面）: 論文ごとに作成日（`createdAt`。論文フォルダの作成日時。作成日時を持たない環境では下のファイルとフォルダの最も古い更新日時）と更新日（`updatedAt`。`glossary.md`・`brief.md`・`style.md`・`notes.json`・成果物 PDF（§8「成果物 PDF の名前」）の最も新しい更新日時。作成日より古ければ作成日）を ISO 8601 で返す。画面は既定で更新日の新しい順に並べ、更新日・作成日の新しい順と古い順、タイトル順（日本語のタイトル、無ければ原題、無ければ ID）に切り替えられる（同じ日時・タイトルは ID の順。選択は保存しない）。各行に、作成日の順なら作成日、それ以外は更新日を出す（issue #433）。
- **論文の検索**（`apps/web/server/arxiv.ts`）: 画面の 1 つの検索欄で、手元の論文（`GET /api/papers` をタイトル・ID で絞り込む）と arXiv（`GET /api/arxiv?q=`）を出す。arXiv ID（`arxiv:` 接頭辞・版つきを含む）は `id_list`、それ以外は語ごとの `all:<語>` の AND（英数字・`.`・`-` 以外の文字を除き、`AND`・`OR`・`ANDNOT` と英語の停止語（Lucene 既定。arXiv の `all:` は停止語を含むと 0 件を返す）は捨てる。8 語まで）で `https://export.arxiv.org/api/query` に問い合わせる（20 件、関連度順）。要求は API のプロセス内で 1 本ずつ、前の要求の開始から 3 秒空けて送る。同じ問い合わせは実行中の要求を共有し、10 分キャッシュする（50 件まで）。20 秒で打ち切る。Atom の entry から id（`/abs/` 以降を ID と版に分ける）・title・summary（空白を詰める）・author の name・published を取り出す。arXiv の誤り（id が `/api/errors`）・HTTP の誤り・タイムアウト・接続失敗は 502、検索語が無ければ 400。各 entry に `paperId`（`derivePaperId`）、`local`（`<paperId>-ja/` が論文フォルダとして並ぶなら `{ pdf: 和訳 PDF の有無 }`、無ければ null）、`job`（待機中・実行中のジョブの状態、無ければ null）を付ける。画面は和訳 PDF があれば「訳済み」（論文の画面へ）、ジョブがあればその状態、それ以外は「翻訳する」（翻訳の画面へ ID とタイトルを渡す）を出す。
- **翻訳ジョブ**（`apps/web/server/jobs.ts`）: `POST /api/jobs { arxivId, provider, model?, effort?, title? }`。arXiv ID は `detectInput`（パスとしては解釈しない）＋`isArxivId`、provider は `Provider` の列挙で必須、model・effort は空なら未指定、先頭 `-`・制御文字・200 字超は拒み、`modelConfigFrom`（CLI と同じ検査）に通す。誤りは 400。同じ `paperId` のジョブが待機中・実行中なら 409。ジョブは repo のルートを CWD に、`process.execPath <tsx/cli> <repo>/src/cli.ts <arXiv ID> --provider P [--model M] [--effort E] --out <articleDir>/<paperId>-ja` をシェルを通さず独立したプロセスグループで起動する（環境変数は API のものを引き継ぎ、`JPAPER_HOME` は絶対パスにする）。並行数（設定、1〜4、既定 1）に空きがあれば待機中のジョブを作成順に起動する。状態は `queued`→`running`→`done`（終了コード 0）・`failed`（それ以外）・`canceled`。
- **PDF のアップロードと翻訳**（issue #387。実装の正本は `apps/web/server/uploads.ts`・`apps/web/server/app.ts`）: `POST /api/uploads`（本文は PDF そのもの、`content-type: application/pdf`、元のファイル名は `x-jpaper-filename` に URL エンコードして載せる）。本文は `MAX_UPLOAD_BYTES`（= `DEFAULT_LIMITS.maxArchiveBytes`、100MiB）まで読み、`content-length` が上限を超える・読んだ量が上限を超えたら読むのをやめて 400（保存しない）。先頭 5 バイトが `%PDF-` でなければ 400（保存しない）。保存先は Web アプリの作業フォルダ（`WebConfig.uploadDir`、既定は `JPAPER_HOME/web-uploads/`）の `<ID>.pdf`。ID は内容の sha256 の先頭 16 桁（同じ内容は同じ ID で、書き直さない。別の内容が同じ ID に当たれば 409）で、一時ファイルから rename する。元のファイル名は制御文字を除き 200 字で切って、表示にだけ使う（論文 ID は `derivePaperId` を `<ID>.pdf` に当てたもの＝ ID そのもので、元のファイル名に依らない）。応答は 201 `{ upload: { id, name, pages, bytes } }`（`pages` は `pdfinfo` の全ページ数。読めなければ 400 で、この要求で新しく書いたファイルは消す）。`POST /api/jobs { upload: <ID>, name?, pages?, confirmLarge?, provider, model?, effort? }` で翻訳ジョブを加える（`upload` があれば `arxivId` は見ない）。ID の形（16 桁の 16 進）が違う・作業フォルダに無い・provider が `IMAGE_PROVIDERS`（claude・codex）でない・`pages`（§8 の `--pages` と同じ形。`optionalText` の検査も通す）が不正なら 400。読むページ（`pages` を当てた後）が `LARGE_PDF_PAGES`（100）を超え、`confirmLarge: true` が無ければ、ジョブを加えずに 409 `{ kind: "confirm-large", total, pages, estimate: { usd, minutes }, perPage: { usd, seconds, concurrency } }`（目安は CLI と同じ `estimatePdfRead`、並行数は provider の既定）を返す。ジョブは起動のときに作業フォルダの PDF を出力先の `source/<ID>.pdf` へコピーし（翻訳の記録と一緒に残し、訳し直しに使う。コピーできなければ起動せずに failed）、`<CLI> <出力先>/source/<ID>.pdf --provider P … [--pages R] [--yes] --out <articleDir>/<ID>-ja` で起動する。`--yes` は読むページが 100 を超え、同意を得たときだけ付ける。ジョブは `label`（arXiv ID か元のファイル名）と、PDF なら `pdf: { name, pages? }` を持つ（arXiv のジョブだけが `arxivId` を持つ）。キュー・並行数・取り消しは arXiv のジョブと同じ。画面: 翻訳のフォームの「arXiv ID ｜ PDF」の切り替えで PDF を選ぶと、ファイルの選択欄（選んだらすぐ送り、「名前（N ページ）」を出す。100MiB を超えるファイルは送らずに知らせる。選び直したら、前に選んだファイルの応答は捨てる）とページの範囲の欄を出し、provider は claude・GPT だけを選べる。始めようとして 409 `confirm-large` が返ったら、確認ダイアログ（ページ数と読むページ数・読み取りの目安・「翻訳の費用と時間は、これとは別にかかります」・範囲の欄・［やめる］［続ける］）を出す。範囲を書き換えると、読むページ数と目安を `perPage` から計算し直す（形が違えば「続ける」を押せない）。［続ける］（範囲の欄での Enter も同じ）で範囲と `confirmLarge: true` を付けて送り直す。同じ内容の PDF のジョブが待機中・実行中なら、そのジョブの名前で 409 を返す。

- **進捗と失敗の理由**: stderr の行（ANSI エスケープと制御文字を除き 1,000 字で切る）から作る。段階は起動時に `ingest`、`[取り込み] 完了`で `context`、`[文脈] 完了`で `translate`、`[翻訳 n/m]` で節 n/m（n=m で `typeset`）、`[組版] 完了`で `typeset`。理由は `失敗[kind]: msg` の行（`msg（kind）`）、無ければシグナルで止まったこと、最後の `エラー:`・`想定外エラー:` の行（`単一ユーザ既定を使用` の通知は除く）、終了コードの順。費用は `<outDir>/.run/llm-trace.jsonl.1` と `llm-trace.jsonl` の記録のうち、起動の直前に無かった runId の `costUsd` の合計（記録が無ければ null）。ログは stdout・stderr の末尾 200 行を持ち、`GET /api/jobs` は各ジョブの末尾 30 行を返す。
- **取り消しと終了**: `POST /api/jobs/:id/cancel`。待機中は起動せずに `canceled`、実行中はプロセスグループに SIGTERM（5 秒で終わらなければ SIGKILL）を送り、終わったら `canceled`。終わったジョブは 409、無いジョブは 404。API の終了（SIGINT・SIGTERM・SIGHUP）では待機中を取り消し、実行中を止める。ジョブはメモリだけに持ち、再起動で消える（終わったジョブは 50 件まで残す）。止まった翻訳は同じ ID で始め直せば CLI の checkpoint から再開する（`.run/run.lock` は持ち主の pid が無ければ奪える）。
- **設定**（`apps/web/server/settings.ts`）: `GET /api/settings` は `{ settings, providers: [{ name, effort }], maxConcurrency: 4, maxHistory: 10 }`（`settings` は `{ provider?, providers, concurrency, verifyTerms, pageNotes, endNotes, history }`）（`effort` は `modelConfigFrom` が effort を受け付ける provider で true）。`POST /api/settings { provider?, providers: { <provider>: { model?, effort? } }, concurrency, verifyTerms?, pageNotes?, endNotes? }` を `JPAPER_HOME/web-settings.json` に保存する（一時ファイルから rename。失敗したら一時ファイルを消す）。保存で置き換えるのはこれら（送らなかった真偽値の設定は保存済みの値を残す）で、ファイルの他のキー（`history`・知らないキー）は残す。ただしファイルが読めない（JSON の誤り・権限など）ときは、利用者が明示した保存なので送ったものだけで書き直す（`history` と知らないキーは残らない。壊れたファイルを画面から直す手段を兼ねる）。検査はジョブと同じで、誤りは 400（保存しない）。空の model・effort は捨てる。読むときはファイルが無い・壊れていれば空（`{ providers: {}, concurrency: 1, verifyTerms: true, pageNotes: false, endNotes: true, history: {} }`）、検査に通らない項目だけ捨てる。フォームの初期値（provider・model・effort）はコードに持たない。空の model・effort はジョブの引数に載らず、translatePaper の既定（§5。claude は最新の Sonnet、codex は最新の Sol、effort は medium）で埋まる。翻訳の画面のフォームは既定の provider とその provider の model・effort を初期値にし、provider を変えるとその provider の値に入れ替える。provider が空なら始められない。並行数を保存すると、空いた分の待機中のジョブがすぐ始まる。`verifyTerms`（設定画面のチェックボックス「用語を Web 検索で確かめる（claude・GPT）」。既定 true、真偽値以外は 400）が false なら、`POST /api/jobs` はジョブの引数に `--no-verify-terms` を足す（ジョブを加えた時点の設定で決まる。§4「用語の検証」）。設定画面の「PDF の訳注」の 2 つのチェックボックス `pageNotes`（各ページの脚注に載せる。既定 false）・`endNotes`（最後に訳注一覧として載せる。既定 true）（真偽値以外は 400）について、`pageNotes` が true なら `POST /api/jobs` はジョブの引数に `--page-notes` を、`endNotes` が false なら `--no-end-notes` を足し、用語集の編集の組み直し（`POST /api/papers/:id/apply`）も適用した時点の設定に従う（§8「訳注の生成契約」）。
- **model・effort の候補**（issue #339）: `POST /api/jobs` がジョブを加えたら、その provider の model・effort を `web-settings.json` の `history: { <provider>: { models, efforts } }` の先頭に置く（同じ値は前から除き、provider ごとに新しい順で `MAX_HISTORY`＝10 件まで）。model も effort も空なら残さない。始められなかったジョブ（400・409）は残さない。書き換えるのは `history` だけで、他のキーはファイルのまま残す。候補が変わらなければ書かない。**設定ファイルが読めない（JSON の誤り・権限など。無いのは除く）ときは書かない**（空の設定で上書きすると、手で直したファイルの既定・並行数が消える）。保存できなくてもジョブは始め、API のログに出す。`GET /api/settings` の `settings.history` で返し、翻訳の画面は選んだ provider の候補を model・effort の入力欄の `<datalist>` に出す（自由入力はそのまま。ジョブを加えたら設定を読み直して候補を更新する。読み直しに失敗しても直前の設定のままフォームを出す）。`POST /api/settings` は送られた `history` を無視して保存済みの履歴を残す。`POST /api/settings/history/clear {}` で履歴だけを消す（設定画面の「候補を消す」）。設定ファイルが読めなければ書かずに 409。読むときは検査（ジョブと同じ）に通らない値・重複を捨てて件数で切る。
